# 07 · 工具错误处理规范

> 阶段：3 Agent 工程化 · 难度：⭐⭐ · 预计：半天
> 前置：[06 MCP Server 开发](06-MCPServer开发.md)
> 产出：掌握 Agent 工程核心原则——失败要被 LLM 看到

---

## 核心原则

> **工具执行出错时，不要抛异常中断 Agent——把错误信息返回给 LLM，让它自己修复。**

| 做法 | 结果 |
|------|------|
| ❌ 抛异常 | Agent 崩溃，用户看到 500 错误 |
| ✅ 返回错误文本 | LLM 看到错误 → 向用户解释 / 换一种方式重试 |

---

## 错误返回的三段式

来自 Claude Code 源码的工程实践：

```java
@Tool(description = "执行命令")
public String execute(String command) {
    try {
        ProcessResult result = processExecutor.run(command);
        // 三段式返回：preview + filePath + truncated
        return """
            执行成功。
            输出预览（前 500 字）：%s
            完整输出文件：%s
            是否截断：%s
            """.formatted(
                result.preview(500),
                result.outputFile(),
                result.isTruncated()
            );
    } catch (TimeoutException e) {
        return "⚠️ 命令超时（120 秒限制）。命令可能卡住了。" +
               "建议：检查命令是否需要交互输入，或增加超时时间。";
    } catch (Exception e) {
        return "⚠️ 执行失败：" + e.getMessage() +
               "\n命令：" + command +
               "\n建议：检查命令格式或权限。";
    }
}
```

---

## 验收检查

- [ ] 所有 @Tool 异常都 catch 并返回错误文本
- [ ] 错误文本包含"建议"信息（引导 LLM 自我修复）
- [ ] Agent 不会因为工具错误而崩溃
