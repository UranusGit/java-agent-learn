# 上手路径与避坑——从哪开始、怎么少踩坑

> **这份文档是什么**：给"决定学 Agent 了"的读者一条**具体的上手路线**（七步，每步该做什么、做到什么程度），外加**六大坑**和一份**全仓库 AI 学习资源地图**。
>
> 前置：你已理解提示词五要素 + 结构化输出，并清楚 Agent 的核心循环（即 01、02 的能力）。

---

## 0. 三条原则（先读）

1. **不要一上来就学框架，先玩心智模型**：先在聊天界面把"五要素提示词"和"结构化输出"玩明白，再碰 Spring AI / LangChain4j。
2. **一次只加一个变量**：能单次调用解决的就别上循环，能一个工具就别上三个。每加一层，先想清楚"不加行不行"。
3. **从第一行代码就带评测和护栏**：这两样"补不了"，越晚越痛。

## 1. 七步上手路线

| 步骤 | 做什么 | 怎么做 |
|:---:|--------|------------|
| **①** | 写好一个 prompt：五要素 + 结构化输出 | 在任何聊天界面练熟五要素 + 结构化输出，先别碰框架 |
| **②** | 用框架做一个"单次调用 + JSON 输出"的功能 | 选 Spring AI 或 LangChain4j 任一套框架，跑通第一个调用 |
| **③** | 加记忆：让多轮对话记住上下文 | 用框架的 ChatMemory 让多轮对话记住上下文 |
| **④** | 加第一个工具：把"查订单 / 查天气"暴露成 Tool | 先掌握工具描述五件事（作用 / 何时用 / 参数 / 返回 / 失败行为），再动手写 |
| **⑤** | 戴护栏：迭代上限、超时、工具白名单 | 给 Agent 加迭代上限、超时、工具白名单 |
| **⑥** | 做评估：10 条测试用例 + 通过率 | 建 10 条用例算通过率，再按框架的评估能力自动化 |
| **⑦** | 做一个完整的实战项目 | 按练手项目把概念串一遍，再用框架实现 |

> 七步走完，你就完成了整套入门阶段的 Agent 工程化——从"会聊天"到"能写进简历的 Agent 项目"。

**七步上手路线**：

```mermaid

    S2 --> S3["③ 加记忆<br/>多轮对话记住上下文"]

    S7 --> EX{"按场景选进阶方向？"}
```

### 1.1 进阶两步（按需）：RAG 和 MCP

七步是最小闭环。现实中 90% 的 Agent 还会碰到两件事：**要回答自己知识库里的问题**（RAG），**要接外部的系统 / 工具生态**（MCP）。做完基础七步后，按你的场景选：

| 方向 | 解决什么 | 从这读 |
|------|---------|--------|
| **⑧ RAG（知识库）** | 让 Agent 查企业私有文档、产品手册再回答，而不是靠模型记的"旧知识"瞎编 | 本专题 04（RAG 入门）：学五步管道——切分 → 转向量 → 存库 → 检索 → 增强生成 |
| **⑨ MCP（外部工具）** | 让 Agent 直接调用"别的团队 / 别的语言 / 独立部署"的工具服务 | 本专题 05（MCP 入门）：学 Client/Server 心智模型与选型 |

## 2. 六大坑（新手最容易踩）

### 坑 1：把 Agent 当普通函数用 / 把简单任务硬套 Agent
- **表现**：一个固定规则的分类任务，套上 Agent 循环，又慢又贵还不稳。
- **解法**：先用决策树判断——流程固定用 Workflow，能单次调用就不上循环。

### 坑 2：工具写得不合格
- **表现**：Agent "经常不调工具 / 调错参数 / 查不到就编造"。
- **解法**：90% 是工具描述问题，不是模型问题。每个工具写清：作用、参数含义、返回、失败行为。

### 坑 3：提示词写死在代码里
- **表现**：改个语气要改代码、没法 A/B、没法回滚。
- **解法**：提示词外部化（PromptRepo / resources/prompts）+ 版本管理，让每次改动可回滚、可对比。

### 坑 4：没有评测，靠"这次碰巧成功"调参
- **表现**：换个输入就翻车，说不清为什么。
- **解法**：固定 10+ 条代表性输入，定义"什么算对"，改完跑一遍通过率。这是 LLM 应用的 TDD。

### 坑 5：护栏后补
- **表现**：一次死循环烧掉几百块 token，或者 Agent 调了不该调的工具。
- **解法**：初学就加迭代上限、超时、工具白名单。**护栏不是进阶内容，是必修内容。**

### 坑 6：没有日志，Agent 像个黑盒
- **表现**：出错时不知道 Agent 当时"想了什么、调了哪个工具、哪一步崩的"，只能反复重试碰运气。
- **解法**：加可观测性——记录每次调用的完整轨迹（用户输入、模型输出、工具调用、工具结果、耗时、token）。

## 4. 一条建议的节奏

> 之后按需深入：要做知识库客服加 RAG（让 Agent 查自己的知识库）、要接外部工具生态加 MCP、要上生产看可观测性与成本治理、要做多 Agent 看多 Agent 编排实战。

**建议节奏**：

```mermaid
timeline
    title 两条线并行推进：边读边做
    section 第 1-2 天
        读完 01+02，玩透五要素 + 结构化输出
    section 第 3-4 天
        框架起步（spring-ai 或 langchain4j），做单次调用 + JSON
    section 第 5-7 天
        加记忆 → 加第一个工具 → 戴护栏
    section 第 8-10 天
        做评估集，跑通过率
    section 第 11-14 天
        完整做一个实战项目（个人助理 或 智能运维）
```
