## AI 原生 vs 传统架构

| 维度 | 传统架构 | AI 原生架构 |
|------|---------|-----------|
| 状态 | CRUD（直接修改数据库） | Event Sourcing（事件流重建状态） |
| 查询 | 同步查数据库 | CQRS（读模型投影） |
| 通信 | 同步 RPC | 异步事件（Kafka） |
| 可恢复性 | 依赖数据库备份 | 事件流可重放 |

**为什么 AI 应用适合 Event Sourcing**：因为对话本身就是一系列事件（用户消息 → AI 回复 → 工具调用 → ...），这些事件是不可变的、有序的、可重放的。

## Event Sourcing 会话设计

```java
// 会话事件（不可变）
public sealed interface SessionEvent permits UserMessageAdded, AiReplyAdded, ToolCalled, SessionCreated {}

// 事件存储（append-only）
public interface SessionEventStore {
    void append(String sessionId, SessionEvent event);
    List<SessionEvent> replay(String sessionId);  // 重放所有事件重建状态
}

// 从事件重建会话状态
public SessionState reconstruct(String sessionId) {
    List<SessionEvent> events = store.replay(sessionId);
    SessionState state = SessionState.initial();
    for (var event : events) {
        state = state.apply(event);  // 逐个应用事件
    }
    return state;
}
```

> **崩溃恢复**：如果 Agent 在执行中崩溃，可以从事件流重放到崩溃前的状态，然后继续执行。
