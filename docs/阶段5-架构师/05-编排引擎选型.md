---

## 选型决策树

```
你的 Agent 复杂度如何？
├── 简单（< 5 个工具，单步或少步） → Spring AI 原生就够了，不需要编排引擎
├── 中等（多 Agent + Workflow + 状态管理） → Spring AI Advisor 链 + Workflow 模式
├── 复杂（多 Agent 协作 + Checkpoint + 断点续跑） → 需要编排引擎
│   ├── 国内生态 → Spring AI Alibaba Graph
│   ├── 研究性/实验性 → LangGraph4j
│   └── 企业级持久化 → Temporal（不是 AI 编排引擎，但可靠性最强）
└── 超复杂（跨组织 Agent 协作） → MCP + A2A（2-3 年内跟进不押注）
```

---

## ADR（架构决策记录）

选型决策必须写成文档，留痕可追溯：

```markdown
# ADR-001：多 Agent 编排引擎选型

## 状态
已接受

## 背景
客服平台需要多 Agent 协作（路由/技术/工单/运维），需要 Checkpoint 和断点续跑。

## 决策
选择 Spring AI Alibaba Graph。

## 理由
- 国内生态，中文文档完善
- 与 Spring AI 2.0 原生集成
- 支持 DAG + 状态机 + Checkpoint

## 后果
- 正面：团队学习成本低、社区活跃
- 负面：不如 LangGraph4j 灵活、绑定阿里生态
```
