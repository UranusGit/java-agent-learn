# 12-推理时计算与长程推理

> **定位**：前沿调研——2026 年推理侧最重要的趋势之一：**推理时计算（Inference-time compute）与长程推理（Long Horizon RL）**。与全体系教程的关系：这些技术解释了"为什么 Agent 要考虑加大模型/加推理预算"（呼应 [44-多模型协作](../教程/44-多模型协作与供应策略.md)、[24-预算控制](../项目/24-企业级长任务工作流引擎/04-三层预算与死循环防护.md)）。
>
> **性质声明**：本文为调研性质，部分为公开研究/Demo 与传统论文的交叉推论，非可引用的工程规范。

---

## 1. 推理时计算：用算力换智能

**核心思想**：不再只靠预训练/微调提升性能，而是**在推理时给模型更多"思考"预算**——多 token（long CoT）、多轮采样（best-of-N / self-consistency）、树搜索（Tree-of-Thought）、验证器打分（process reward model）。

```
传统: 输入 → 一次前向 → 输出
推理时计算: 输入 → 多次探索/搜索/验证 → 择优输出（花更多算力）
```

## 2. 三档推理时计算

| 档位 | 技术 | 算力放大 | Agent 意义 |
|------|------|---------|-----------|
| 轻 | long-CoT（长思考 token） | 5-10× | 复杂推理提升，延迟成本同步升 |
| 中 | best-of-N/self-consistency | N× | 降随机性错误，适合高风险决策 |
| 重 | 树搜索+PRM 验证 | 数十× | 逼近规划，工程复杂度高 |

## 3. 长程推理（Long Horizon RL）

**趋势**：把"长任务一致性/工具使用/自我反思"作为强化学习目标（而非只学一句对答）。这让模型**原生**更会做"多步、用工具、会纠错"的 Agent 工作——但代价是推理时更长、成本更高。

## 4. 对 Java/Spring 工程的意义

1. **成本治理更关键**：推理时计算的"扩展"是无上限的 Token 消耗——[27-成本](../教程/27-成本治理与Token计量.md)、[24-预算闸门](../项目/24-企业级长任务工作流引擎/04-三层预算与死循环防护.md) 从"可选"变"必需"。
2. **按任务分档**：简单 query 用普通档，复杂推理/高风险决策用推理时计算档——这正是 [32-模型路由](../教程/32-模型路由与降级.md)、[50-意图路由](../教程/50-意图路由与路由编排.md) 的天然输入（路由到不同"推理预算档"）。
3. **预算上限就是可控性**：推理时计算越强、越需要"最大轮次/Token/时长"硬闸（[24]）。

> **结语**：推理时计算让"堆算力换能力"成为新解，但**对平台工程是把"预算控制"和"按需分档路由"变得更重要**——不是模型变强就能不管成本，而是能力越强越要有精确的档位控制和成本闸门。
