# 14-Chain-of-Agents 与协作协议实证

> **定位**：前沿调研——深挖**多 Agent 协作的协议层技术（Chain-of-Agents 等）**：串行传递摘要、树状并行聚合、角色分工，与单次对话对比的实证增益。与全体系关系：呼应 [02-多Agent协作](../项目/02-多Agent协作平台/00-需求分析与架构设计.md)、[27-协作平台](../项目/27-企业级Agent协作平台/00-需求分析与架构设计.md)、[09-教程](../教程/09-多Agent协作.md)。
>
> **性质声明**：调研性质，Chain-of-Agents 为公开论文方向的转述；增益数字为论文量级参考，非本机实测。

## 1. Chain-of-Agents 核心思想

长上下文（如整本小说/长文档）单次塞给一个模型会注意力衰减（Lost in the Middle）。**Chain-of-Agents** 的思路：**串行让多个 Agent 各读一段→传递压缩摘要→末位 Agent 综合**，或**树状并行读完再聚合**。

## 2. 协作模式实证对比

| 模式 | 思想 | 优点 | 代价 |
|------|------|------|------|
| 单模型长上下文 | 一次全读 | 简单 | 注意力衰减（中间信息弱） |
| 串行摘要链（CoA） | 分段→逐段摘要传递 | 长文效果好、各段聚焦 | 串行慢、摘要有损 |
| 树状并行聚合 | 分片并行→聚合 | 快（并行） | 聚合成本、协调复杂 |
| 角色分工（solo/painter 等） | 各 Agent 专责后裁决 | 复杂任务准 | 多一轮对话开销 |

**经验结论**（调研量级）：对**超长、需要跨段综合**的任务，协作模式普遍优于单次硬塞；对**短而独立**的任务，协作是纯开销。

## 3. 与工程落地的关系

1. **摘要传递 = 上下文压缩的成本模型**（[31-压缩三路径](../项目/31-企业级Agent上下文管理平台/03-压缩三路径与历史管理.md) 有对应：摘要是有损但缩小上下文）。CoA 的"摘要有损"要在 [25-记忆衰减](../项目/25-企业级Agent记忆中枢/06-演化衰减与冲突消解.md) 框架里管理。
2. **树状并行聚合提升吞吐**（[24-DAG 多Worker](../项目/24-企业级长任务工作流引擎/05-DAG步骤化与多Worker抢任务.md) 的算法协作版）：把长文分片给多个 Worker 并行是同一思想。
3. **角色分工的"裁决 Agent"** → 提升复杂任务结构化输出一致性（[37-自我反思](../教程/80-自我反思与Agent评估.md)）。

## 4. 协作协议 vs 帧协议（工程视角）

- **帧内协作**（CoA 模式）解决"一个任务怎么拆给多个 Agent 干"。
- **跨信任域协议**（[27-协作平台](../项目/27-企业级Agent协作平台/00-需求分析与架构设计.md) 的 A2A）解决"不同组织的 Agent 怎么安全对接"。

两者正交：**先有协作帧（拆活），再有互操作协议（跨域）**。

> **结语**：协作模式实证表明"分而治之+摘要综合"能解决单模型长上下文衰减，但**换来摘要有损与协调成本**——工程上要与上下文压缩（31）、DAG 并行（24）、记忆衰减（25）打通，才能真正受益。
