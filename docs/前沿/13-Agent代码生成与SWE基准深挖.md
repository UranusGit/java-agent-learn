# 13-Agent 代码生成与 SWE 基准深挖

> **定位**：前沿调研——深挖 **SWE-bench 等代码 Agent 基准**：用什么测、测什么、局限在哪。与全体系关系：呼应 [37-评估](../教程/37-自我反思与Agent评估.md)、[12-附录评估生态](../附录/12-评估与可观测生态/00-Langfuse与Ragas集成.md)、[19-评测平台](../项目/19-企业级Agent信任与评测平台/00-需求分析与架构设计.md)。

> **性质声明**：本文为调研性质，SWE-bench 等为真实公开基准（论文/仓库），但数据与个别论断为调研转述。

---

## 1. 为什么代码 Agent 是 Agent 评测的标杆任务

代码任务**结果可自动判定**（单测/编译），不像开放问答需要人评——所以代码类基准是 Agent 能力量化最成熟的场。典型：**SWE-bench**（真实 GitHub issue → 让 Agent 修代码 → 跑隐藏单测），**SWE-bench Verified**（人工确认的 500 例子集，业界事实标准）。

## 2. 主流代码 Agent 基准对比

| 基准 | 测什么 | 判定 | 局限 |
|------|--------|------|------|
| SWE-bench | 修真实 issue（多文件） | 隐藏单测 | 只覆盖 Python 仓库子集；对"多仓库/大型工程"弱 |
| SWE-bench Verified | 人工确认子集 | 隐藏单测 | 同上，更可信但规模小 |
| HumanEval / MBPP | 单函数生成 | 单测 | 不做多步工具协作，偏"单函数" |
| Aider / CodeX 等博弈榜 | 工程修改 | lint+测试+人评 | 榜单易饱和/刷榜 |

## 3. 对自建评测平台的启示（关键）

1. **自动判定的价值**：代码基准证明"结果可机器校验"比"人评主观分"更适合做发布闸门（[19-发布闸门](../项目/19-企业级Agent信任与评测平台/06-信任评分与发布闸门.md)）。
2. **分层金标**：SWE-bench 式"真实任务+隐藏判据"是最强金标；但成本高，需与 [19-金标分层](../项目/19-企业级Agent信任与评测平台/02-金标资产化.md) 结合（先单例集、再真实集）。
3. **警惕饱和**：代码基准**饱和快**（模型刷分），不能只挂一个榜——要 [涨分与业务真实回归](../项目/26-企业级Agent数据飞轮平台/04-评估汇流与回归门禁.md) 双看。

## 4. 工程落地

- 自建评测可参考 SWE-bench 架构：真实任务集 + 隐藏判据 + 环境沙箱隔离（[附录19-沙箱](../附录/19-Agent沙箱与执行环境/00-沙箱技术对比与选型.md)）。
- Agent 改代码要可回滚可审计（[12-研发效能](../项目/12-研发效能DevOps平台/02-代码审查Agent.md) 的血缘）。

> **结语**：代码基准是"可机器校验评测"的黄金标准，但**饱和快、偏静态语言**——自建评测要仿其"隐藏判据+隔离环境"架构，而非迷信单一榜单。
