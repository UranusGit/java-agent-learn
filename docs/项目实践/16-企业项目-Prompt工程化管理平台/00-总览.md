# ⑯ PromptFactory — Prompt 工程化管理平台

> **代号**：PromptFactory
> **核心问题**：团队 10 个人改 Prompt 全靠 Git + 微信沟通，没有版本管理、没有评估门禁、没有灰度发布——怎么系统化管理 Prompt 全生命周期？

---

## 项目定位

```mermaid
flowchart TD
    Problem["痛点"] --> P1["Prompt 散落在代码里<br/>没有统一管理"]
    Problem --> P2["改了 Prompt 不知道效果<br/>没有评估"]
    Problem --> P3["改坏了线上崩溃<br/>没有灰度"]
    Problem --> P4["谁改了什么不知道<br/>没有审计"]

    Solution["PromptFactory"] --> S1["Prompt 注册中心<br/>统一存储+版本管理"]
    Solution --> S2["评估门禁<br/>变更前自动评估"]
    Solution --> S3["灰度发布<br/>5%→25%→50%→100%"]
    Solution --> S4["审计追溯<br/>谁改了什么一目了然"]

    style Solution fill:#4caf50,color:#fff
```

## 四个 Sprint

```mermaid
flowchart LR
    S1["Sprint 1<br/>Prompt 注册中心<br/>存储+版本+Diff"] --> S2["Sprint 2<br/>评估门禁<br/>变更前跑 Eval Set"]
    S2 --> S3["Sprint 3<br/>灰度发布<br/>渐进式放量+自动回滚"]
    S3 --> S4["Sprint 4<br/>Prompt IDE<br/>可视化编辑+A/B测试"]

    style S1 fill:#4caf50,color:#fff
    style S4 fill:#2196f3,color:#fff
```

| Sprint | 目标 | V1→V2→V3 | 时间 |
|--------|------|---------|------|
| Sprint 1 | Prompt 注册中心 | V1 内存存储 → V2 持久化 → V3 版本树 | 1 周 |
| Sprint 2 | 评估门禁 | V1 全量评估 → V2 增量评估 → V3 差异分析 | 1 周 |
| Sprint 3 | 灰度发布 | V1 按比例 → V2 按用户群 → V3 自动决策 | 1 周 |
| Sprint 4 | Prompt IDE | V1 在线编辑 → V2 预览测试 → V3 A/B 实验 | 1 周 |

## 架构设计

```mermaid
flowchart TD
    UI["Prompt IDE<br/>（Web 界面）"] --> API["Prompt API<br/>CRUD + 版本管理"]
    API --> Registry["注册中心<br/>版本树 + Diff"]
    API --> Gate["评估门禁<br/>变更前跑 Eval"]
    Gate --> Eval["评估引擎<br/>旧版 vs 新版"]
    Eval --> Decision{"门禁通过？"}
    Decision -->|"通过"| Canary["灰度控制器"]
    Decision -->|"不通过"| Block["拒绝注册"]
    Canary --> Router["流量路由器"]
    Router --> V1["生产版"]
    Router --> V2["候选版"]
    Canary --> Monitor["质量监控<br/>自动放量/回滚"]

    style Registry fill:#4caf50,color:#fff
    style Gate fill:#ff9800,color:#fff
```
