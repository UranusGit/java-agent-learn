## ADR-01：三层记忆统一读写

**决策**：工作（ChatMemory 全窗口）/ 长期（自研语义召回）/ RAG（知识库相似度）三层，读写语义各有不同但由一个 MemoryHub 统一编排。

**背景**：两三层记忆各写各的会重复、语义混淆。

**取舍**：统一入口 + 分层存储；三层读写由 MemoryHub 编排、Audit 打点、Scope 隔离（11 的编排）。

## ADR-02：长期记忆自研 ChatMemoryRepository

**决策**：持久化 `implements ChatMemoryRepository`（javap 实证），非官方无 Jdbc/Redis（CLAUDE.md 铁律）。

**背景**：官方仅 `InMemoryChatMemoryRepository`，跨会话持久化需自研。

**取舍**：自研换取按 scope/score/时间查询 + 语义索引；官方接口保持兼容（findByConversationId/saveAll/delete）。

## ADR-03：混合检索（语义+关键词+时间 RRF）

**决策**：04 用嵌入（语义）+ BM25（关键词）+ 时间加权，RRF 融合。

**背景**：纯向量对"精确标识/新近性"弱；用户 ID、近期偏好召回不准。

**取舍**：混合召回鲁棒（RRF 对权重不敏感）但多一路信号要维护；换来召回准确率 ≥85%。

## ADR-04：作用域强制隔离（Fail-closed）

**决策**：所有记忆读写强制带 scope（tenant:agent:conv），缺 scope 默认拒绝。

**背景**：多租户/多 Agent 无隔离则记忆泄漏。

**取舍**：安全(不漏读) > 便捷；漏配 scope 宁可拒绝不可漏读；用 Reactor Context 传递租户（WebFlux 铁律）。

## ADR-05：score 强化衰减 + 冲突消解

**决策**：记忆 score 被召回强化、久不召回指数衰减；新旧矛盾按时间/score 消解、双版本留时间线索。

**背景**：过期/矛盾记忆误导 Agent。

**取舍**：动态演化 + "宁显双版本不暴删"，避免"只看最新丢背景"。

## ADR-06：遗忘权级联全链路删除

**决策**：用户删记忆时，短期 `ChatMemory.clear` + 长期 `deleteByConversationId` + 向量 + 元数据同事务删除，并审计。

**背景**：GDPR 被遗忘权要求删干净，向量残留是合规漏洞。

**取舍**：三级删除一致（事务）+ 审计；换取合规性（呼应 25/43）。

## ADR-07：Token 预算分层召回

**决策**：短/长/RAG 递归切分 token 预算，topK 由预算推，绝不让召回撑爆上下文。

**背景**：记忆层是上下文五层之一，无限召回会挤爆（呼应 34/27）。

**取舍**：每层 fit 预算（省钱不爆） > 召回完整；用 topK 折衷。

## ADR-08：记忆可见域三级（私有/团队/全局）

**决策**：写默认私有、读按需开放（PRIVATE/TEAM/GLOBAL），跨 Agent 借读只读引用。

**背景**：多 Agent 要协作记忆但不共享一切（呼应 09）。

**取舍**：借读(实时引用) + 授权拷贝区分；避免同步问题又能协作。

- ADR-03 混合 = 多一路信号维护（换取召回准）。
