## 二、score 强化衰减 + 衰减作业

```java
// 概念代码：记忆 score 演化
public double onRecall(MemoryRecord r) { return Math.min(r.score()+DELTA, 1.0); }    // 被召回加强
public double onDecay(MemoryRecord r, long ageDays)                                  // 定时作业
    { return r.score() * Math.exp(-LAMBDA * ageDays); }                              // 指数衰减

@Scheduled(cron="0 3 * * *")                       // 每日衰减作业
public void decayJob() {
    for (var r : jdbc.queryAllMemories()) {        // 全记忆扫描衰减
        double s = onDecay(r, ageDays(r));
        if (s < ARCHIVE_THRESHOLD) archive(r);     // 衰减到阈值 → 归档(不参与召回)
        else jdbc.updateScore(r.id(), s);
    }
}
```

**收益**：①抑制"僵尸记忆"（长期没用还占召回位）②新近 + 反复 = 高 score 常驻（呼应用户真实偏好）。

### 二.1 本节测试与验证（score 强化衰减 + 衰减作业）

**前置条件**：`onRecall`/`onDecay`/`decayJob`（`@Scheduled`）已实现；记忆库有可写 score 与可设 `ageDays` 的记录；能方便地"撤回一次召回"与"伪造老化时间"。

**材料——核对命令/观察**（直接查库观察 score 变化，无固定端点）：

```sql
SELECT id, content, score, ts FROM memory_store ORDER BY ts;
```

**步骤与断言**：

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | 对同一记忆连续多次 `onRecall` | score 持续上升并趋近 1.0（≤ MAX）；反复命中的记录在召回排序中常驻靠前 |
| 2 | `onDecay(r, ageDays)` 大 ageDays | score 指数下降；低于 `ARCHIVE_THRESHOLD` 的记忆被 `archive(r)` 移出召回范围 |
| 3 | 触发 `decayJob` 全量扫描 | 长期不用记忆被衰减/归档，活跃记忆 score 更新，召回命中率不因僵尸记忆下降 |
| 4 | 观察归档后召回 | 归档记忆不再进召回结果（占位清除） |

**失败排查**：①score 到 1.0 不再涨→`onRecall` 的 `Math.min` 截断生效（属正常）；②衰减不触发归档→`ARCHIVE_THRESHOLD` 比对或 `archive` 分支未执行；③调度不跑→`@Scheduled`（`@EnableScheduling`）未启用。

## 三、冲突消解（新旧矛盾）

同一 scope 同主题新旧记忆矛盾（旧"偏好A"新"偏好B"）：

| 依据 | 处理 |
|------|------|
| 时间新 | 新版为主，旧版标 depreciated |
| score 高 | 反复强化的一方优先 |
| 两者都有依据 | 标"双版本+时间"，交 LLM 结合上下文判断（不武断删） |

**原则**：**宁显双版本 + 时间线索**，不暴力删旧——比"只看最新"更能处理"偏好会变但旧背景仍有用"的复杂情况。

## 四、记忆质量评估（为 08 飞轮铺路）

- 每次召回被 Agent 实际采用 → 记正信号；召回但没用 → 记负信号。
- 高负信号记忆 → 降级/建议清理；高正信号 → 保留强化。
- 这是 08 迭代"反馈回流"的雏形（呼应 [41-数据飞轮](../../教程/41-数据飞轮与持续改进.md)）。
