## 二、混合检索（语义 + 关键词 + 时间）

```java
// 概念代码：混合召回 → RRF 融合排序
public List<MemoryRecord> hybridRecall(String scope, String query, int topK) {
    float[] v = embeddingModel.embed(query);                 // 语义向量(实证)
    var semantic = vectorStore.similaritySearch(SearchRequest.query(query).topK(topK*2));

    var keywordCandidates = bm25Search(scope, query, topK*2);   // 关键词/BM25(如 PostgreSQL FTS)
    var timeCandidates = recentSearch(scope, topK*2);           // 时间新近(呼应06衰减)

    // RRF 融合：三种排序按倒数排名融合，稳定且对权重不敏感
    return rrfFuse(semantic, keywordCandidates, timeCandidates, topK);
}
private List<MemoryRecord> rrfFuse(List<List<MemoryRecord>> ranked, int topK) {
    Map<String,Double> scores = new HashMap<>();
    for (int k=0;k<ranked.size();k++) for (int i=0;i<ranked.get(k).size();i++)
        scores.merge(ranked.get(k).get(i).id(), 1.0/(k+1+i), Double::sum); // RRF: Σ1/(rank)
    return scores.entrySet().stream().sorted(...).limit(topK)...;
}
```

**要点**：RRF（倒数排名融合）对"不同信号来源的权重"不敏感且稳定——比直接加权相加更鲁棒（呼应 [35-高级RAG](../../教程/08-架构师进阶/01-高级RAG与AgenticRAG.md) 的混合检索融合）。

## 三、为什么混合检索优于纯向量

| 场景 | 纯 embedding | 混合(BM25+时间+语义) |
|------|-------------|--------------------|
| 同义表达("偏好深色"↔"喜欢黑色") | 好 | 好(语义) |
| 精确事实("账户号 88xx") | 弱(向量噪音) | 强(BM25 精确词) |
| 时间新近(前几天刚说的) | 弱 | 强(时间加权) |
| 冷启动/低频词 | 弱 | 中(混合兜底) |

**取舍**：纯向量对"精确标识/时间"都弱，工程级记忆召回要靠**多信号混合**。

### 三.1 本节核对（为什么混合检索优于纯向量）

- [ ] 四类场景（同义 / 精确事实 / 时间新近 / 冷启动）中纯向量的短板能复述，且与 §二 的语义/BM25/时间三信号一一对应
- [ ] 能解释 RRF 为何比"直接加权相加"鲁棒（对信号权重不敏感、稳定）
