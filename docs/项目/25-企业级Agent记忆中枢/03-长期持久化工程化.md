## 二、记忆表 + 去重幂等

```java
// 概念代码：记忆存储(事务 + 去重 + 元数据)
@Repository
public class JdbcSemanticMemoryRepository implements ChatMemoryRepository {
    // 去重键：内容感知哈希 + scope，同事实只存一条(若变化则更新而非新增)
    private String dedupKey(String scope, String content) {
        return scope + ":" + sha256(normalize(content));
    }

    @Override @Transactional
    public void saveAll(String conversationId, List<Message> messages) {
        for (Message m : messages) {
            String scope = MemoryScope.forConversation(conversationId).key();
            String dk = dedupKey(scope, m.getText());
            if (!exists(dk)) {                        // 不存在才插入
                long id = jdbc.updateInsertWithKey(scope, m.getText(), now(), dk);
                vectorStore.add(Document.builder().id(String.valueOf(id))    // 同事务写向量
                        .metadata("scope", scope).content(m.getText()).build());
            } // 已存在：跳过(或按06演化更新score)
        }
    }
}
```

**一致性**：`@Transactional` 保证写库 + 向量 **同事务**——任一步失败整体回滚，避免"库里有一条但向量没有"的脏记忆。

### 二.1 本节测试与验证（去重幂等与事务一致性）

**前置条件**：`JdbcSemanticMemoryRepository`（实现 `ChatMemoryRepository`）已实现，接可回滚事务（如 H2/PostgreSQL + `@Transactional`）；`dedupKey`/`exists`/`saveAll`/向量 add 在同一事务入口可触发。

**材料——去重/一致性核对语句**：

```sql
SELECT scope, COUNT(*), COUNT(DISTINCT content) FROM memory_store GROUP BY scope;
SELECT COUNT(*) FROM vector_store;
```

**步骤与断言**：

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | 同 scope 同内容写两次（`saveAll` 两次同一 `Message`） | 只存一份：`COUNT(*) = COUNT(DISTINCT content)`（去重键命中，跳过更新） |
| 2 | 同 scope 不同内容写两次 | 存两行（内容不同，dedupKey 不同不误判为重复） |
| 3 | 制造写库成功而向量写失败的异常（如向量无对应列/超时） | 整体回滚：`memory_store` 该条也不在，库与向量一致（无脏记忆） |
| 4 | 核对元数据 | 每条记录 `scope/ts/content/dedupKey` 完整可查 |

**失败排查**：①同内容存了多份→`dedupKey` 归一化不一致（大小写/空白差异）或 `exists(dk)` 未命中；②回滚后库留数据→`@Transactional` 未覆盖向量 add（REQUIRED 传播失效）或向量写未参与同事务；③误判重复→scope+content 拼的 key 把不同事实折叠了。

## 三、组合查询能力

```java
@Override
public List<Message> findByConversationId(String conversationId) {
    String scope = MemoryScope.forConversation(conversationId).key();
    // 按 scope 查 + 时间正序 → 可回放该会话的长期记忆
    return jdbc.query("SELECT * FROM memory_store WHERE scope=? ORDER BY ts ASC", scope, ...);
}
// 附加：按维度聚合(某tenant全部记忆/某Agent偏好)为后续隔离/评估铺路
```

**要点**：`findByConversationId` 用 **scope 组合键** 而非裸 conversationId，天然支持多租户/多 Agent 隔离（[05 迭代] 深化）。

### 三.1 本节测试与验证（组合查询能力）

**前置条件**：`findByConversationId` 与按维度聚合查询已实现（同 §二 落库数据）。

**材料——查询核对 SQL**：

```sql
SELECT * FROM memory_store WHERE scope='tenantA:agentA:conv1' ORDER BY ts ASC;
-- 按维度聚合：某 tenant 全部记忆 / 某 Agent 偏好
SELECT scope, COUNT(*) FROM memory_store GROUP BY scope;
```

**步骤与断言**：

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | `findByConversationId(conv1)` | 仅返回该 scope 记录，按 `ts` 时间正序可回放 |
| 2 | 查询不同 scope（conv2 / 另一 tenant） | 不混入其它 scope 数据（scope 组合键准确过滤） |
| 3 | 按维度聚合查询 | 某 tenant 全部记忆 / 某 Agent 偏好统计正确，供后续 05 隔离 / 08 评估使用 |

**失败排查**：①查到别的 scope→`WHERE scope=?` 未带权限过滤或 conversationId 不含 tenant/agent 前缀；②顺序乱→`ORDER BY ts` 缺失或 time 字段未落。
