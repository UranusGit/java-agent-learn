## 二、边缘 A/B

```java
// 概念代码：节点组对照实验
Experiment exp = experiment.of("model-v2-vs-v1", bucketByNodeLabel("region"));
exp.assign(bucketA, ModelRef.v1());      // 对照组
exp.assign(bucketB, ModelRef.v2());      // 实验组
// 观测窗口后: 效果指标(差例率/延迟/成本) 显著性判定 → 全量 v2 或停
// 边缘差例(脱敏) → 飞轮采集(26思想)
```

### 二.1 本节测试与验证（节点组灰度管道与边缘 A/B）

**前置条件**：03 分发已管道化（可 5%→50%→全量）；遥测能产出对照指标（差例率/延迟/成本）；`experiment.of(...)` 分桶逻辑按节点标签生效；边缘差例脱敏回流已接。

**材料——代码内含的旋钮**：`bucketByNodeLabel("region")`；`bucketA=V1` / `bucketB=V2`；指标 `差例率/延迟/成本` 显著性判定；`差例(脱敏)→飞轮采集`。

**核对命令**（实验状态与分桶指标可查）：

```bash
curl -s http://localhost:8081/edge-hub/experiments/model-v2-vs-v1    # A/B 实验状态
# 预期输出（节选）：
#   {"expId":"model-v2-vs-v1","buckets":{"A(v1)":{"nodes":48},"B(v2)":{"nodes":48}},
#    "metrics":{"errorRateDelta":"-1.2%","latencyP95Delta":"+3ms"},
#    "gate":"HOLD","verdict":"NOT_SIGNIFICANT"}
```

**步骤与断言**：

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | 对节点组启动 5% 灰度 | 仅 5% 节点进入新版本，指标守门开启 |
| 2 | 人为造坏 case（指标恶化超阈） | 灰度自动停止放量（不继续扩 50%） |
| 3 | A/B 同标签节点分桶对照 | 同负载两组指标可对比，观察窗口后做显著判定 |
| 4 | 采集边缘差例 | 脱敏后回流进飞轮（26 思想），不把原始 PII 或低质语料回流 |

**失败排查**：①灰度量停不了→守门判据未接或阈值未生效；②A/B 不显著→分桶混杂（要按同标签同负载）或样本不足；③差例泄漏 PII→回流前脱敏未落地；④守门把正常迭代误停→阈值过严或指标口径偏差。
