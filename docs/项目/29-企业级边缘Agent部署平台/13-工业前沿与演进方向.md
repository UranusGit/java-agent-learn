# 13-工业前沿与演进方向

> **定位**：收官篇。把项目 29（边缘 Agent 部署平台）放到边缘 AI 前沿（端侧小模型/NPU/边缘 K8s）校准，给出演进方向。读者画像：要判断"边缘 Agent 的投入节奏与技术跟随点"的架构师。前置阅读：本项目全部正向迭代。

---

## 一、平台成熟度回看

| 能力 | 迭代 | 成熟度 |
|------|------|--------|
| 纳管/分发/断网自治 | 01-04 | ✅ 生产可用 |
| 分工/安全/远程运维 | 05-07 | ✅ 生产可用 |
| 联邦/灰度/TCO | 08-10 | ✅ 生产可用（联邦依赖组规模） |

**收敛判断**：全链达**可投产**；与 11（工业边缘）/17（实时边缘）项目的边缘迭代构成不同视角（29 是**部署平台视角**——管节点/分发/运维，非具体业务场景）。

## 二、业界对照（校准）

| 方向 | 性质 | 与本方向 |
|------|------|---------|
| **端侧小模型（1-7B 蒸馏）** | 模型演进 | 03 分发的"货"；模型越小边缘越可行（量化+蒸馏双轨） |
| **NPU/专用芯片** | 硬件 | 02 硬件档案/10 TCO 的变量；NPU 普及改变端云经济账 |
| **KubeEdge/OpenYurt** | 边缘 K8s | 本平台 edge-hub 的容器化演进路径（边缘节点编排标准化） |
| **iOS/Android 端侧 LLM（系统级）** | 端侧 | 05 端云分工的"端"极延伸（系统级本地模型接入） |

## 三、演进方向（按价值排序）

1. **边缘 K8s 化**：edge-hub 演进到 KubeEdge 类标准（节点编排生态复用，减少自研维护）。
2. **端云智能路由**：按任务复杂度+网络态+TCO **实时**决定云边执行（从静态分工到动态路由，融合 [23-路由](../../项目/23-企业级Agent意图路由网关/00-需求分析与架构设计.md) 思想）。
3. **NPU 适配层**：硬件异构（GPU/NPU/CPU）的统一推理抽象（10 TCO 模型纳入芯片维度）。
4. **边缘联邦学习**：节点本地数据训练→只回传梯度（数据不出域的持续改进，呼应 [26-飞轮](../../项目/26-企业级Agent数据飞轮平台/08-多业务联邦飞轮.md) 的隐私版）。
5. **端侧系统模型集成**：接入手机/车机系统级 LLM（iOS 端侧模型等）作为"零成本端侧推理"选项（05 分工新增一极）。

## 四、工程纪律复盘

- **不要**全量齐发模型（带宽预算+灰度）。
- **不要**断网装正常（显式告知）。
- **不要**用 LLM 做运维自愈（确定性剧本）。
- **务必**设备身份与数据加密（边缘=物理暴露面）。
- **务必**算 TCO（边缘不是政治正确是经济决策）。
