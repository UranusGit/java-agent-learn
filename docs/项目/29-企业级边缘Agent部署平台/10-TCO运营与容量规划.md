### 二.1 本节测试与验证（云边对照与容量决策）

**前置条件**：`EdgeFinJob` 能把遥测+资产台账归集成节点级 TCO；云 API 单价数据可配；容量画像（qps/复杂度/时长）随遥测可得。

**材料——对照流程内含的输入**：`节点负载画像(qps/复杂度/时长)` + `边缘TCO(摊销+运维+带宽)` vs `云API成本(同负载tokens×单价)` → `高频低复杂度留边缘 / 低频高复杂度回云或混合`。

**步骤与断言**：

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | 查看某节点 TCO 台账 | 四项成本（硬件摊销/运维/带宽/电力）齐全可查 |
| 2 | 同负载跑边缘与云双列对照 | 看板实时显示「边缘TCO vs 云API成本」两列 |
| 3 | 构造一个高频低复杂度负载 | 决策建议「留边缘（划算）」 |
| 4 | 构造一个低频高复杂度负载 | 决策建议「回云/混合」 |
| 5 | 看容量建议 | 过载节点有扩/迁移建议，闲置节点有缩建议 |

**失败排查**：①TCO 四项缺项→归集链路未接遥测/资产台账；②对照不出→云单价未配或同负载换算口径不统一；③建议长期一边倒→对照阈值写死或负载画像数据残缺。
