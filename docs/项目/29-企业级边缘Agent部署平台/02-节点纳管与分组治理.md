# 02-节点纳管与分组治理

> **定位**：把"看得见"升级为**管得住**——**① 节点注册模型（硬件/算力/模型集/标签）② 分组与标签（按门店/产线/区域）③ 心跳健康与失联处置**。呼应 [02-27 AgentCard注册](../../项目/27-企业级Agent协作平台/02-AgentCard注册与能力发现.md) 的注册思想。前置阅读：[01-最小Demo](01-最小Demo.md)。
>
> **铁律 0**：纳管模型/分组自研「概念代码」。

---

## 一、四问

| 问 | 答 |
|----|----|
| **新增了什么需求** | ①节点档案（硬件/算力/已装模型/版本）②标签分组（区域/业务/风险级）③失联分级处置（告警/隔离/工单） |
| **影响了哪些模块** | edge-hub → 节点目录；心跳 → 健康档案 |
| **架构如何演进** | 节点从"列表"演进为"档案化资产" |
| **上一版痛点** | 上百节点无分组无法批量操作；失联节点静默消失 |

**本迭代验收**：①节点档案完整可查 ②按标签批量操作（下发/巡检）③失联超阈自动告警+隔离。

## 二、节点档案与分组

```java
// 概念代码：节点档案
public record NodeProfile(String nodeId, HardwareSpec hw,        // CPU/GPU/内存
                          Set<String> models,                     // 已装模型+版本
                          Map<String,String> labels,              // region=cn-east/biz=store
                          NodeHealth health) {}
// 分组操作: 下发模型到 labels{biz=store} 全组; 失联>10min 告警, >1h 隔离(不再接分发任务)
```

## 三、验收

| 测试 | 期望 |
|------|------|
| 新节点上线 | 档案自动建档 |
| 按组下发 | 只影响标签匹配节点 |
| 节点失联 | 告警→隔离 |
