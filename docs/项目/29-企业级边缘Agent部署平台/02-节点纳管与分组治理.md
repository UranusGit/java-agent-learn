## 二、节点档案与分组

```java
// 概念代码：节点档案
public record NodeProfile(String nodeId, HardwareSpec hw,        // CPU/GPU/内存
                          Set<String> models,                     // 已装模型+版本
                          Map<String,String> labels,              // region=cn-east/biz=store
                          NodeHealth health) {}
// 分组操作: 下发模型到 labels{biz=store} 全组; 失联>10min 告警, >1h 隔离(不再接分发任务)
```

### 二.1 本节测试与验证（节点档案与分组）

**前置条件**：edge-hub 已实现 `NodeProfile` 档案与标签分组；至少 2 个可用节点并打上不同标签；心跳与失联判定已接通。

**材料——代码内含的旋钮**：档案字段 `NodeProfile(nodeId, hw, models, labels, health)`；分组操作 `下发模型到 labels{biz=store} 全组`；失联阈值 `.10min 告警, >1h 隔离`。

**核对命令**（档案完整可查）：

```bash
curl -s http://localhost:8081/edge-hub/nodes/edge-001    # 单节点档案详情
# 预期输出（节选）：
#   {"nodeId":"edge-001","hw":{"cpu":8,"gpu":"none","memGB":16},
#    "models":["qwen3:4b"],"labels":{"region":"cn-east","biz":"store"},"health":"ONLINE"}
```


**步骤与断言**：

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | 新节点上线注册 | 云端自动建档，`NodeProfile` 的硬件/模型集/标签字段完整可查 |
| 2 | 对 `labels{biz=store}` 组下发模型 | 仅标签匹配节点收到，未匹配节点零影响 |
| 3 | 独立核对未匹配节点 | 其档案/队列无本次下发痕迹（隔离性验证） |
| 4 | 停一台节点心跳≥10min | 该节点进入告警态；≥1h 自动标记隔离（不再接分发任务） |

**失败排查**：①新节点不上档案→注册链路未写入目录；②按组下发误伤他组→标签键值不精确或匹配用 `contains` 而非精确（应只匹配 `biz=store`）；③失联不告警→心跳超时判据与阈值未生效；④隔离后仍被分发→隔离态未拦截分发任务的 choose。
