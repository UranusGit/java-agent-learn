# 04-断网自治与分层降级

> **定位**：断网是**设计前提**——**① 分层降级（路由/推理/检索/上下文各层的离线模式）② 显式告知（离线模式不装正常）③ 恢复补办（排队云操作回放）**。呼应 [教程 55 §4](../../教程/55-边缘Agent与端云协同部署.md)、[30-容错](../../教程/30-容错与弹性设计.md)。前置阅读：[03-模型分发与灰度回滚](03-模型分发与灰度回滚.md)。
>
> **铁律 0**：降级编排自研「概念代码」；本地推理实证模式。

## 一、四问

| 问 | 答 |
|----|----|
| **新增了什么需求** | ①断网检测与降级编排（层各有离线模式）②用户显式告知（"离线模式，能力受限"）③离线期间云依赖操作排队，恢复补办 |
| **影响了哪些模块** | 新增 DegradeOrchestrator；各能力层 → 离线实现 |
| **架构如何演进** | 节点从"断网即瘫"演进为"分层自治" |
| **上一版痛点** | 断网静默失败/装正常；恢复后离线请求全丢 |

**本迭代验收**：①断网核心功能可用率 ≥90%（00 验收①）②离线状态显式暴露 ③恢复后排队操作自动补办。

## 二、分层降级表

```java
// 概念代码：断网降级编排
public OfflineCapability degrade(NetworkState net) {
    return switch (net) {
        case ONLINE  -> fullStack();                                  // 全能力
        case DEGRADED-> localStack().withCloudQueue();                // 本地+排队云操作
        case OFFLINE -> localStack()                                  // 纯本地
            .withNotice("离线模式：本地知识/小模型服务，部分功能恢复联网后可用");
    };
}
// localStack = 本地规则+语义路由(23思想) + 本地小模型 + 本地知识缓存 + 本地窗口上下文(31思想)
```
