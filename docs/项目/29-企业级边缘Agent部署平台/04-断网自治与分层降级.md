## 二、分层降级表

```java
// 概念代码：断网降级编排
public OfflineCapability degrade(NetworkState net) {
    return switch (net) {
        case ONLINE  -> fullStack();                                  // 全能力
        case DEGRADED-> localStack().withCloudQueue();                // 本地+排队云操作
        case OFFLINE -> localStack()                                  // 纯本地
            .withNotice("离线模式：本地知识/小模型服务，部分功能恢复联网后可用");
    };
}
// localStack = 本地规则+语义路由(23思想) + 本地小模型 + 本地知识缓存 + 本地窗口上下文(31思想)
```

### 二.1 本节测试与验证（断网降级编排：分层降级 / 显式告知 / 排队补办）

**前置条件**：`DegradeOrchestrator` 已实现 `degrade(net)` 三分支；本地栈（本地规则/小模型/知识缓存/窗口上下文）可就地推理；网络态检测与云操作队列已接通。

**材料——代码内含的旋钮**：三个网络态 `ONLINE → fullStack()` / `DEGRADED → localStack+withCloudQueue()` / `OFFLINE → localStack+withNotice()`；离线提示文案「离线模式：本地知识/小模型服务…」。

**核对命令**（节点网络态与降级能力自查）：

```bash
curl -s http://localhost:8081/edge-hub/nodes/edge-001/health    # 节点网络态与当前能力栈
# 预期输出（节选）：
#   {"nodeId":"edge-001","network":"OFFLINE","mode":"localStack",
#    "notice":"离线模式：本地知识/小模型服务，部分功能恢复联网后可用",
#    "queuedCloudOps":3}
```


**步骤与断言**：

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | 保持在线调用核心能力 | 全栈能力返回，无需排队 |
| 2 | 断网（切断专线）后发起本地可解问题 | 本地栈正常回答；页面/提示显式展示「离线模式，能力受限」文案（不装正常） |
| 3 | 断网期间发起云依赖操作（如跨设备记忆同步） | 操作进入队列，不在前台伪装成功 |
| 4 | 恢复网络 | 队列自动补办完成；节点升级回全栈；期间已排队操作不回丢 |
| 5 | 统计断网核心功能可用率 | ≥90%（00 验收①） |

**失败排查**：①断网后报错吞本地栈→`OFFLINE` 分支未返回 `localStack()`；②离线不显示提示→`withNotice()` 未透出到前端；③云操作断网直接报"失败"而非排队→未走 `withCloudQueue()`；④恢复后队列丢→补办任务未持久化/无重放。
