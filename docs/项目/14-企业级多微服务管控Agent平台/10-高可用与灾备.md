## 三、长任务断点续跑（检查点）

```mermaid
stateDiagram-v2
    [*] --> 开始执行 : 收到长任务
    开始执行 --> 步骤1
    步骤1 --> 检查点 : 记录步骤1结果
    检查点 --> 步骤2
    步骤2 --> 检查点 : 记录步骤2结果
    检查点 --> 步骤N
    步骤N --> 完成
    完成 --> [*]
    检查点 --> 中断 : 崩溃/重启
    中断 --> 恢复 : 从最后检查点续跑
    恢复 --> 步骤2 : 跳过已完成步骤
```

```java
// agent-executor：检查点持久化（事件溯源式：记录每一步输入/输出/预算）
// 重启后从 checkpoint 恢复，不重跑已完成步骤
// 本迭代验收：任务执行到步骤 3 中断 → 重启 → 从步骤 3 续跑
```

### 3.1 本节测试与验证（长任务断点续跑）

**前置条件**：检查点存储（对象存储/DB）就绪；agent-executor 支持从 checkpoint 恢复。

**材料**：§三 状态机 + checkpoint 持久化。

**步骤与断言**：

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | 发起长任务，执行到步骤 3 | 步骤 1-2 结果已写入检查点 |
| 2 | 模拟崩溃/重启（kill 后重启） | 从检查点恢复，从步骤 3 继续（日志确认不重跑 1-2） |
| 3 | 断点恢复后再执行完 | 任务最终完成，重复执行对步骤 1-2 幂等 |

**失败排查**：①重启从步骤 1 重跑→检查点未落库/恢复逻辑未读取；②恢复后状态错乱→检查点快照未包含执行到哪个步骤的游标。

## 四、容量规划（压测 → 实例数）

### 4.1 压测基线（示例）

| 服务 | 单实例吞吐 | 目标 QPS | 实例数 |
|------|-----------|---------|--------|
| agent-executor | 20 req/s | 200 | ≥10 |
| model-gateway | 50 req/s | 300 | ≥6 |
| tool-executor | 30 req/s | 240 | ≥8 |
| retrieval-service | 80 req/s | 400 | ≥5 |

```mermaid
flowchart LR
    LOAD["压测工具<br/>(k6/Locust)"] --> P["压测基线<br/>单实例吞吐/延迟"]
    P --> F["公式<br/>实例数 = ceil(目标QPS / 单实例吞吐) × 冗余系数1.5"]
    F --> H["HPA 配置<br/>min/max + 触发阈值"]

    style F fill:#fff9c4
```

### 4.2 HPA 配置（K8s）

```yaml
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: agent-executor-hpa
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: agent-executor
  minReplicas: 2
  maxReplicas: 20
  metrics:
    - type: Resource
      resource:
        name: cpu
        target:
          type: Utilization
          averageUtilization: 70
```

### 4.3 本节测试与验证（容量规划与 HPA）

**前置条件**：k6/Locust 压测工具就绪；K8s HPA 已部署。

**材料**：§4.1 压测基线表 + §4.2 HPA YAML + 容量公式 `ceil(目标QPS/单实例吞吐)×1.5`。

**步骤与断言**：

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | 按 §4.1 基线核算各服务实例数 | 公式结果与表一致（agent-executor 目标 200 QPS / 20 ≈10×1.5≈15） |
| 2 | HPA YAML 校验（`kubectl apply`） | `autoscaling/v2` 合法，`minReplicas:2/maxReplicas:20`、CPU 70% 生效 |
| 3 | k6 压测到目标 QPS | HPA 自动扩缩实例数，延迟保持 P99 达标 |

**失败排查**：①实例数计算错→确认单实例吞吐为压测真实值（非理论值）；②HPA 不扩→metrics-server 指标采集正常、`averageUtilization` 阈值已达；③延迟超标→单实例吞吐基线偏乐观，调整冗余系数。

## 六、优雅停机与滚动发布

```mermaid
sequenceDiagram
    participant K as K8s
    participant P as Pod(旧)
    participant P2 as Pod(新)

    K->>P: SIGTERM（滚动发布开始）
    P->>P: 停止接收新请求(就绪探针变 false)
    P->>P: 处理完在途请求(优雅停机窗口)
    K->>P2: 启动新 Pod(就绪后接流量)
    P2-->>K: 就绪
    Note over P,P2: 零停机发布
```

```yaml
# spring boot 优雅停机
server:
  shutdown: graceful
spring:
  lifecycle:
    timeout-per-shutdown-phase: 30s
```

## 七、全篇回归验证

**前置条件**：§1.1-§6.1 各节核对/测试均通过；K8s 集群、检查点存储、压测工具、多区域就绪。

**材料**：故障注入 + 长任务 + 压测 + 容灾演练四类探针（§3.1/§4.3 已覆盖基础）。

**步骤与断言**：

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | 杀掉一个 agent-executor Pod | 探针摘除 → HPA 补新 → 请求无感知（≤60s 自愈） |
| 2 | 长任务执行到步骤 3 → kill → 重启 | 从步骤 3 续跑（日志确认不重跑 1-2） |
| 3 | k6 压测目标 QPS | HPA 自动扩缩，延迟 P99 达标 |
| 4 | 主区域故障 → DNS 切备 → 恢复 | RTO 达标；恢复后数据一致（RPO 内） |

**失败排查**：①自愈慢→探针周期/HPA 补新延迟不在 60s 预算内；②断点续跑不对→检查点游标未持久化；③容灾 RPO 超标→异步同步延迟超窗口或数据不一致。
