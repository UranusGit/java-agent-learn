```mermaid
flowchart LR
```

### 1.2 调优清单（按收益排序）

| 调优点 | 手段 | 收益 |
|--------|------|------|
| 模型网关 | 语义缓存（09 迭代）| 高频查询省 LLM |
| 上下文 | 压缩（15 迭代）| 长对话省 Token |
| 响应式 | 全链异步（12 迭代）| 吞吐量级 |
| 检索 | 混合+重排（15 迭代）| 质量↑ 重查↓ |
| 并发 | flatMap 限流（14 迭代）| 防打爆配额 |
| 连接池 | WebClient/DB 池调优 | 减少等待 |
| GPU | vLLM 批处理/连续批（16 迭代）| 吞吐↑ 成本↓ |

## 二、模型微调决策（何时微调 vs Prompt/RAG）

```mermaid
flowchart TB
    Q{"效果不达标?"} --> P["先试 Prompt(低成本)"]
    P -->|"还差"| R["再试 RAG(加知识)"]
    R -->|"还差"| G{"问题是?"}
    G -->|"领域风格/格式/语气"| F["微调(风格契合)"]
    G -->|"事实/知识"| R2["RAG 更合适"]
    G -->|"复杂推理"| M["换更强模型"]

    style F fill:#fff9c4
```

| 场景 | 推荐 | 理由 |
|------|------|------|
| 指令不清/格式 | Prompt 优化 | 低成本、可灰度 |
| 缺领域知识 | RAG | 可更新、可溯源 |
| 领域风格/输出格式固定 | 微调 | 风格契合、省 token |
| 复杂推理 | 换强模型 | 微调救不了推理 |

> **调研共识（2026）**：先 Prompt/RAG，无效才微调；**金标评估驱动**（13 迭代）判断"是否真进步"。

```mermaid
flowchart LR
    U["用量计量<br/>Token/调用/存储"] --> B["计费引擎<br/>按租户×费率"]
    B --> C["账单生成<br/>周期/明细"]
```

| 检索 | 向量查询数 | 按量 |
| 存储 | 会话/记忆体积 | 按 GB |

## 四、迁移路线图（从现有系统到平台）

### 4.1 迁移路径

```mermaid
flowchart LR
    M["单体/现有系统"] --> S1["① 接入网关<br/>会话/认证统一"]
    S1 --> S2["② 模型调用代理<br/>接入 model-gateway"]
    S2 --> S3["③ 工具迁移<br/>登记到 tool-registry"]
    S3 --> S4["④ 双跑期<br/>新旧并行+流量灰度"]
    S4 --> S5["⑤ 切流<br/>按租户/业务灰度"]
    S5 --> S6["⑥ 下线旧系统"]

    style S4 fill:#fff9c4
```

### 4.2 迁移策略

| 阶段 | 动作 | 风险控制 |
|------|------|---------|
| ① 接入网关 | 统一认证/会话/审计 | 透明代理，行为不变 |
| ② 模型代理 | 调用走网关（路由/配额） | 单模型→多模型渐进 |
| ③ 工具登记 | 现有工具注册+准入 | 未登记不执行 |
| ④ 双跑 | 新旧并行 + 评估对比（13） | 评估驱动切流 |
| ⑤ 切流 | 按租户/业务灰度（09） | 秒级回滚 |
| ⑥ 下线 | 旧系统降流量→下线 | 全量验证后 |
