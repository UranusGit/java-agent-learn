## 1. 六个关键设计复盘

### 1.1 为什么是"语义层确定性编译"而非纯 Text2SQL

直生 Text2SQL 的 LLM 在**开放空间**生成 SQL（表选错/列猜错/join 幻觉），企业私有基准准确率甚至只有 ~11%。语义层把问题从"生成 SQL"（开放）压缩为"选指标+选维度"（封闭选择题）——封闭空间 LLM 难错，SQL 由规则引擎确定性编译。**代价**：分析师要维护指标字典/join 图；换来的是"覆盖的问题准确率 ~100%"。这是本项目与"套壳 Text2SQL"的本质区别。

代码锚点：`MetricCompiler.compile()` 是规则引擎，`SemanticLayerService.resolveIntent()` 让 LLM 只做选择题（[03 §4.5/§4.6](03-语义层与指标中台.md)）。

### 1.2 为什么安全在 DB 层不在 prompt 层

prompt 说"只写 SELECT"是**约束不是强制**——LLM 可以被注入、可以犯错。真正的边界在存储层：只读角色（非 superuser 不可绕过）、RLS（prompt 注入也绕不过）、只读物理副本（写入结构性不可能）。应用层校验（JSqlParser 语法级）只是**第二道**。

代码锚点：`SqlGuardrail.validate()`（应用层第二道）+ `db/schema-v2.sql` 只读角色（DB 层第一道，[02 §4.4/§4.8](02-SQL安全护栏.md)）。

### 1.3 为什么 join 用预定义图而不让 LLM 现场 join

跨表关联是 SQL 幻觉重灾区：fan-out 膨胀（一对多 join 行数爆炸）、笛卡尔积、错选 join 策略。语义层的 join 图是**分析师维护一次**的确定性关联路径——"JOIN 逻辑从 LLM 任务中彻底剥离"，跨表 100% 可审计。**代价**：新表关联要分析师补 join 图；换来正确性。

代码锚点：`JoinGraph`（预定义路径）+ `MetricCompiler` 沿图取列（[03 §4.3/§4.5](03-语义层与指标中台.md)）。

### 1.4 为什么多源要"先查 Data Catalog 再查数据"

Agent 跳过 catalog 直接猜表名，跨库必然猜错（Salesforce account_id vs ERP client_no vs 数仓 dim_customer_key）。**路由决策必须 grounded in governed metadata**——Catalog 是元数据中枢，路由是"选择题"不是"生成题"（与语义层同构：把开放问题转封闭问题）。

代码锚点：`CatalogTools.findSources()` 先查元数据，`MultiSourceRouter` 用 `entity(RoutingPlan.class)` 输出决策（[05 §4.4/§4.8](05-多数据源AgenticRAG.md)）。

### 1.5 为什么缓存命中必须校验权限

语义缓存放的是"问题-SQL-结果"，若 A 租户能命中 B 租户的缓存，等于数据泄漏。所以语义缓存命中**必须校验 tenant 边界**——权限内才可命中。**成本优化不能以安全为代价**。

代码锚点：`SemanticCacheService.semanticHit()` 校验 `doc.getMetadata().get("tenant_id")`（[07 §4.4](07-成本治理与缓存.md)）。

### 1.6 为什么数据质量要"对账+冻结"而非"事后发现"

"clean-looking wrong answers"（看起来对但实际错）比"明显的错"更危险——业务会信错数据做决策。指标 CI 对账（vs 分析师手写 control query）+ 漂移冻结（降级为"待复核"标注）保证**不静默给错答案**。数值型答案用"执行准确率"评估（数字对才是对），非语义相似度。

代码锚点：`ReconciliationService` + `MetricFreezeService` + `EvaluationService.matchesExpected()`（[08 §4.4/§4.8](08-数据质量与治理.md)）。

## 2. 最容易写错的五处

| # | 位置 | 错误 | 后果 | 正确（代码锚点） |
|---|------|------|------|-----------------|
| 1 | 安全 | 只靠 prompt 约束只读 | LLM 被注入/犯错 | DB 层只读角色+RLS+只读副本（[02 §4.8](02-SQL安全护栏.md)） |
| 2 | 校验 | 正则黑名单挡注入 | 编码绕过 | JSqlParser `parseStatements` 语法级解析（[02 §4.4](02-SQL安全护栏.md)） |
| 3 | 跨表 | LLM 现场 join | fan-out/笛卡尔积 | 语义层预定义 join 图（[03 §4.3](03-语义层与指标中台.md)） |
| 4 | 多源 | Agent 直接猜表名 | 跨库猜错 | 先查 Data Catalog 再查数据（[05 §4.4](05-多数据源AgenticRAG.md)） |
| 5 | 缓存 | 命中不校验权限 | 跨租户数据泄漏 | 语义缓存命中校验 tenant 边界（[07 §4.4](07-成本治理与缓存.md)） |
