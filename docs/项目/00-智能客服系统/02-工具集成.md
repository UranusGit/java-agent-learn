## 1. 为什么加工具

客服场景大量信息是**实时、私有、需查询**的——查订单、查物流、查 FAQ。工具让 Agent 从「凭训练知识瞎说」变成「查真实数据再回答」。

| 工具 | 功能 | 数据源 |
|------|------|--------|
| `queryFaq` | 按关键词查 FAQ | 预置 FAQ 列表 |
| `queryOrder` | 按订单号查订单状态 | 模拟订单服务 |

### 2.2 `FaqQueryTool.java`

```java
package com.shop.customer.tool;

import org.springframework.ai.tool.annotation.Tool;
import org.springframework.ai.tool.annotation.ToolParam;
import org.springframework.stereotype.Component;

import java.util.List;

@Component
public class FaqQueryTool {

    private static final List<FaqItem> FAQS = List.of(
            new FaqItem("退换货政策是什么", "7天无理由退换，15天内质量问题包换，需保留吊牌与购买凭证。"),
            new FaqItem("支持以旧换新吗", "支持，需旧机可开机、屏幕完好，抵价以门店检测为准。"),
            new FaqItem("发货时效", "现货商品 48 小时内发货，预售商品以页面标注为准。")
    );

    @Tool(name = "queryFaq", description = "根据关键词查询常见问题解答。")
    public List<FaqItem> queryFaq(@ToolParam(description = "查询关键词") String keywords) {
        return FAQS.stream()
                .filter(f -> f.question().contains(keywords)
                        || f.answer().contains(keywords))
                .toList();
    }
}
```

```java
package com.shop.customer.tool;

import org.springframework.ai.tool.annotation.Tool;
import org.springframework.ai.tool.annotation.ToolParam;
import org.springframework.stereotype.Component;

import java.util.Map;

@Component
public class OrderQueryTool {

    private static final Map<String, OrderInfo> ORDERS = Map.of(
            "DD20240810", new OrderInfo("DD20240810", "已发货", "SF123456789"),
            "DD20240811", new OrderInfo("DD20240811", "待支付", null)
    );

    @Tool(name = "queryOrder", description = "根据订单号查询订单状态与物流单号。")
    public OrderInfo queryOrder(@ToolParam(description = "订单号") String orderId) {
        return ORDERS.get(orderId);
    }
}
```

### 2.4 工具注册：`ChatClientConfig.java`

```java
package com.shop.customer.config;

import com.shop.customer.tool.FaqQueryTool;
import com.shop.customer.tool.OrderQueryTool;
import org.springframework.ai.chat.client.ChatClient;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class ChatClientConfig {

    @Bean
    public ChatClient chatClient(ChatClient.Builder builder,
                                 FaqQueryTool faqTool,
                                 OrderQueryTool orderTool) {
        return builder
                .defaultSystem("你是电商客服小智，只能依据工具查询结果回答，不要编造订单/物流信息。")
                .defaultTools(faqTool, orderTool)
                .build();
    }
}
```

> **注意**：Spring AI 2.0 里 `defaultTools` 注册 `@Tool` Bean（`Object...` 变长参数）；若挂载 `ToolCallbackProvider`，用的是 `defaultToolCallbacks(toolCallbackProvider)`（javap 实证 `ChatClient.Builder` 提供 `defaultToolCallbacks(ToolCallbackProvider...)`，[附录 05-02 §1]）。

### 2.5 `ChatService.java` 更新（使用带工具的 ChatClient）

```java
package com.shop.customer.service;

import org.springframework.ai.chat.client.ChatClient;
import org.springframework.stereotype.Service;
import reactor.core.publisher.Flux;

@Service
public class ChatService {

    private final ChatClient chatClient;

    public ChatService(ChatClient chatClient) {
        this.chatClient = chatClient;
    }

    public String chat(String sessionId, String message) {
        return chatClient.prompt()
                .user(message)
                .call()
                .content();
    }

    public Flux<String> chatStream(String sessionId, String message) {
        return chatClient.prompt()
                .user(message)
                .stream()
                .content();
    }
}
```

> `ChatService` 本身无改动——工具能力通过 `ChatClientConfig` 注入。这就是「能力通过配置组装，业务代码不感知」的体现。

## 3. 工具调用可见性（让用户看到"查了什么"）

> 过程可见性是工业级标配。客服场景，最该让用户看到的"过程"是——**这次回答背后查了哪个工具、返回了什么**。用户说"订单 DD20240810 什么状态"，如果只回一句"已发货"，用户无法确认是系统查出来的还是 AI 编的；看到"已调用订单查询工具→返回 1 条"才有据。

工具执行经 [教程 28] 的事件协议发射可见性事件（客服侧订阅后转前台展示）：

| 事件 | 内容 | 前端展示（客服工作台） |
|------|------|----------------------|
| ToolStart | 工具名 + 参数预览 | "正在查询订单 DD20240810…" |
| ToolProgress | 长查询进度 | 查询进行中动画 |
| ToolEnd | 成功/失败 + 结果预览 | "查到：已发货（2024-08-10 出库）" |
| ThoughtDelta | 推理片段 | 可选展示"AI 判断应查物流" |

**四条纪律**：
1. **结果 preview 截断**：客服工作台只显示结果摘要（≤200 字），完整详情按需展开（防大结果撑坏会话）。
2. **无匹配也可见**：工具未命中时也发 ToolEnd(命中=0)——用户看到"系统确实查了但没有该单"，而非看着 AI 编答案。
3. **成对**：ToolStart↔ToolEnd 一一对应，工具抛异常也发 ToolEnd(failed)——客服能看出"查询失败了"而非"AI 卡住"。
4. **与可观测衔接**：可见性事件与 [教程 31] 的 tool Span 同源（同一工具调用），审计/排障可查完整参数（工作台只给预览，后台留全量）。
