## 1. 为什么需要记忆

当前 Agent 每次请求是「无状态」的——上一轮的订单号、用户偏好都记不住。ChatMemory 让 Agent 能记住用户说的每一句话，追问不重复。

> **关键 API 澄清（[附录 05-00 §2]）**：`RedisChatMemory` / `MongoChatMemoryRepository` **不存在**。本地 javap 实证的内存实现是 `InMemoryChatMemoryRepository`（`org.springframework.ai.chat.memory`）；`ChatMemoryRepository` 是**同步 SPI**（`findConversationIds()` / `findByConversationId(String)` / `saveAll(String, List<Message>)` / `deleteByConversationId(String)`，javap 实证）。Redis 持久化必须**自研实现 `ChatMemoryRepository` 接口**。

### 2.3 `RedisChatMemoryRepository.java`（自研 ChatMemoryRepository，按 javap 实证签名 + 正确序列化范式修复）

```java
package com.shop.customer.memory;

import org.springframework.ai.chat.memory.ChatMemoryRepository;
import org.springframework.ai.chat.messages.AssistantMessage;
import org.springframework.ai.chat.messages.Message;
import org.springframework.ai.chat.messages.MessageType;
import org.springframework.ai.chat.messages.SystemMessage;
import org.springframework.ai.chat.messages.UserMessage;
import org.springframework.data.redis.core.StringRedisTemplate;
import org.springframework.stereotype.Component;

import java.io.IOException;
import java.util.ArrayList;
import java.util.List;
import java.util.Map;

/**
 * Redis 持久化的 ChatMemoryRepository（自研——本地未实证官方 Redis 实现，[附录 05-00 §2]）。
 *
 * ⚠️ 序列化铁律（2026-08-22 round-trip 实测）：Spring AI 的 Message 及其子类无
 * property-based Creator，【绝不能】用 GenericJacksonJsonRedisSerializer 直接把 Message
 * 当 value 存——写入不报错，但读取必炸（LinkedHashMap / no property-based Creator）。
 * 正确范式：存可序列化的 Map（type/content/metadata），读回时按 MessageType 用 .builder() 重建
 * （官方 RedisChatMemoryRepository 同款思路，见 [附录 05-00 §2.3]）。
 * 这里用自动装配的 StringRedisTemplate 存 JSON 字符串；2.0.0 官方仅 InMemory，持久化必须自研。
 */
@Component
public class RedisChatMemoryRepository implements ChatMemoryRepository {

    private static final String KEY_PREFIX = "chatmemory:";
    // 用 StringRedisTemplate（Boot 自动装配）存 JSON 字符串，避免自定义对象序列化器
    private final StringRedisTemplate redis;
    private final ObjectMapper mapper = new ObjectMapper();

    public RedisChatMemoryRepository(StringRedisTemplate redis) {
        this.redis = redis;
    }

    @Override
    public List<String> findConversationIds() {
        return redis.keys(KEY_PREFIX + "*").stream().toList();
    }

    @Override
    public List<Message> findByConversationId(String conversationId) {
        List<String> entries = redis.opsForList().range(KEY_PREFIX + conversationId, 0, -1);
        if (entries == null) {
            return List.of();
        }
        List<Message> messages = new ArrayList<>();
        for (String json : entries) {
            messages.add(fromJson(json));   // JSON 字符串 → Map → 按 type 重建 Message
        }
        return messages;
    }

    /**
     * ⚠️ 覆盖语义（2026-08-22 补充）：
     * MessageWindowChatMemory.add() 每轮传进来的是"已含全部历史 + 窗口裁剪后"的【完整窗口】，
     * repository 必须【整体覆盖】而不是 append。若用 rightPushAll 追加，每轮会把含旧消息的
     * 整个窗口再 append 一遍 → Redis list 无限膨胀、每条消息重复累积（对应 demo01 发现的 bug）。
     * 官方 InMemoryChatMemoryRepository.saveAll 即 Map.put(整体替换) 语义；Redis 用"先删后写"对齐。
     */
    @Override
    public void saveAll(String conversationId, List<Message> messages) {
        String key = KEY_PREFIX + conversationId;
        redis.delete(key);                            // 覆盖：先删旧窗口
        if (!messages.isEmpty()) {
            List<String> jsons = messages.stream().map(this::toJson).toList();
            redis.opsForList().rightPushAll(key, jsons);
        }
    }

    @Override
    public void deleteByConversationId(String conversationId) {
        redis.delete(KEY_PREFIX + conversationId);
    }

    // —— 存：Message → Map（可被 Jackson 序列化）→ JSON 字符串 ——
    private String toJson(Message m) {
        try {
            Map<String, Object> doc = new java.util.HashMap<>();
            doc.put("type", m.getMessageType().toString());   // 类型必须存，重建时靠它
            doc.put("content", m.getText());
            doc.put("metadata", Map.of());
            return mapper.writeValueAsString(doc);
        } catch (Exception e) {
            throw new IllegalStateException("序列化 Message 失败", e);
        }
    }

    // —— 读：JSON 字符串 → Map → 按 MessageType 用 builder 重建（官方同款） ——
    private Message fromJson(String json) {
        try {
            // 目标 Map.class（具体类型，无需泛型 TypeReference —— 这台机器 Jackson3 无对应类路径，
            // 也避免 tools.jackson / com.fasterxml 双里混淆）；读回 Map 再按 type 手建 Message
            Map<String, Object> doc = mapper.readValue(json, Map.class);
            String type = (String) doc.get("type");
            String content = (String) doc.get("content");
            @SuppressWarnings("unchecked")
            Map<String, Object> metadata = (Map<String, Object>) doc.getOrDefault("metadata", Map.of());
            switch (MessageType.valueOf(type)) {
                case USER:      return UserMessage.builder().text(content).metadata(metadata).build();
                case ASSISTANT: return AssistantMessage.builder().content(content).properties(metadata).build();
                case SYSTEM:    return SystemMessage.builder().text(content).metadata(metadata).build();
                default:        throw new IllegalStateException("未知消息类型: " + type);
            }
        } catch (IOException e) {
            throw new IllegalStateException("反序列化 Message 失败", e);
        }
    }
}
```

> ⚠️ `ChatMemoryRepository` 的真实方法签名（javap 实证）：`findConversationIds()` / `findByConversationId(String)` / `saveAll(String, List<Message>)` / `deleteByConversationId(String)`，全部同步（[附录 05-00 §2]）。**持久化走自研 repository，不用虚构类**。
>
> **⚠️ 序列化铁律（2026-08-22 round-trip 实测，见 [附录 05-00 §2.3]）**：Spring AI 的 `Message` 及子类字段 `private final`、无 `@JsonCreator`/`@JsonProperty`——Jackson 无 property-based Creator，**直接用 `GenericJacksonJsonRedisSerializer` 把 `Message` 当 value 存，读取必失败**（读回 `LinkedHashMap` 或 `cannot deserialize ... no property-based Creator`），且常表现为「**第一次请求成功、第二次请求 500**」（首次无历史读空不炸，二次读旧数据才炸）。必须改成上面这种「存 `Map` + 按 `MessageType` 用 `.builder()` 重建」。

### 2.3.1 为什么用 `MessageWindowChatMemory` 会「每次全量存一遍历史」？（存储语义，2026-08-22 补）

这是使用 `MessageWindowChatMemory` **必然**出现的现象，不是 bug，而是它作为「窗口策略」的固有设计。看官方 `MessageWindowChatMemory.add()` 源码（`spring-ai-model-2.0.0`）：

```java
public void add(String conversationId, List<Message> messages) {
    List<Message> memoryMessages = chatMemoryRepository.findByConversationId(conversationId); // ① 先读全量历史
    List<Message> processed = process(memoryMessages, messages);                              // ② 拼上新消息 + 按 maxMessages 裁剪
    chatMemoryRepository.saveAll(conversationId, processed);                                  // ③ 把【整个窗口】覆盖写回
}
```

**结论**：`MessageWindowChatMemory` 每轮都是「读全量 → 拼新 → 裁剪 → 整体覆盖写」，天然要全量读改写。它维护的是「**一个对话的最近 N 条快照**」，每次把整份快照交付给 repository。**这是策略选择，不是缺陷**——窗口小（如 20 条）时每轮覆盖写也就几毫秒，demo 够用。

但这里藏着一个**必须注意的语义坑**，否则会真的把历史存重复：

| 存储语义 | 官方内存实现做法 | 说明 |
|----------|----------------|------|
| **覆盖（Map 语义、正确）** | `InMemoryChatMemoryRepository.saveAll` 用 `chatHistoryMap.put(id, new ArrayList<>(messages))` **整体替换** | 框架每轮给的 `messages` 已是完整窗口 = **最终状态**，接收端应直接整体替换 |
| **追加（List append、错误）** | Redis list 用 `rightPushAll` 直接追加 | 每轮把"含旧消息的整个窗口"**再 append 一次** → 历史无限累积、每条重复 |

**所以自研 Redis `saveAll` 必须是"先删后写"覆盖语义**（如上代码），**禁止 `rightPushAll` 无脑追加**。若真需要「增量追加、不重算窗口、省 I/O」，就不该用 `MessageWindowChatMemory`，而要自研一个「只追加新消息」的 `ChatMemory` 实现（`add()` 直接 saveAll 增量，不读全量）——那是另一个策略，本 demo 不展开（见 [附录 05-00 §2.3] 与记忆中枢项目）。

### 2.4 `ChatMemoryConfig.java`（门面 + 仓库两层组合）

```java
package com.shop.customer.memory;

import org.springframework.ai.chat.memory.ChatMemory;
import org.springframework.ai.chat.memory.MessageWindowChatMemory;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class ChatMemoryConfig {

    // 注意：不再自定义 RedisTemplate<String,Message> + GenericJacksonJsonRedisSerializer——
    // Message 对象不能 JSON 直接序列化（见 §2.3）。仓库用自动装配的 StringRedisTemplate 存 JSON 字符串即可。
    @Bean
    public ChatMemory chatMemory(RedisChatMemoryRepository repository) {
        return MessageWindowChatMemory.builder()
                .chatMemoryRepository(repository)   // 自研 Redis 仓库（本地实证仅 InMemory）
                .maxMessages(20)                     // 窗口内保留最近 20 条消息（2.0.0 Builder 方法为 maxMessages）
                .build();
    }
}
```

### 2.5 `ChatClientConfig` 更新（加记忆 Advisor，接会话 ID）

```java
package com.shop.customer.config;

import com.shop.customer.tool.FaqQueryTool;
import com.shop.customer.tool.OrderQueryTool;
import org.springframework.ai.chat.client.ChatClient;
import org.springframework.ai.chat.client.advisor.MessageChatMemoryAdvisor;
import org.springframework.ai.chat.client.advisor.vectorstore.QuestionAnswerAdvisor;
import org.springframework.ai.chat.memory.ChatMemory;
import org.springframework.ai.vectorstore.SearchRequest;
import org.springframework.ai.vectorstore.VectorStore;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class ChatClientConfig {

    @Bean
    public ChatClient chatClient(ChatClient.Builder builder,
                                 FaqQueryTool faqTool,
                                 OrderQueryTool orderTool,
                                 VectorStore vectorStore,
                                 ChatMemory chatMemory) {
        QuestionAnswerAdvisor ragAdvisor = QuestionAnswerAdvisor.builder(vectorStore)
                .searchRequest(SearchRequest.builder().topK(3).similarityThreshold(0.7).build())
                .build();
        MessageChatMemoryAdvisor memoryAdvisor = MessageChatMemoryAdvisor.builder(chatMemory).build();

        return builder
                .defaultSystem("你是电商客服小智，只能依据工具查询结果回答，不要编造订单/物流信息。")
                .defaultTools(faqTool, orderTool)
                .defaultAdvisors(ragAdvisor, memoryAdvisor)
                .build();
    }
}
```

> ```xml

### 2.6 `ChatService.java` 更新（传入会话 ID，走记忆）

```java
package com.shop.customer.service;

import org.springframework.ai.chat.client.ChatClient;
import org.springframework.ai.chat.memory.ChatMemory;
import org.springframework.stereotype.Service;
import reactor.core.publisher.Flux;
import reactor.core.publisher.Mono;
import reactor.core.scheduler.Schedulers;

@Service
public class ChatService {

    private final ChatClient chatClient;

    public ChatService(ChatClient chatClient) {
        this.chatClient = chatClient;
    }

    // 同步一次性对话：call() 是阻塞调用，收敛到 boundedElastic（WebFlux 铁律，与 01-最小Demo 一致）
    public Mono<String> chat(String sessionId, String message) {
        return Mono.fromCallable(() -> chatClient.prompt()
                .user(message)
                .advisors(a -> a.param(ChatMemory.CONVERSATION_ID, sessionId))   // 常量，非字面量
                .call()
                .content())
                .subscribeOn(Schedulers.boundedElastic());
    }

    public Flux<String> chatStream(String sessionId, String message) {
        return chatClient.prompt()
                .user(message)
                .advisors(a -> a.param(ChatMemory.CONVERSATION_ID, sessionId))
                .stream()
                .content();
    }
}
```

> 用 `ChatMemory.CONVERSATION_ID` 常量（[附录 05-00 §2]），**禁止抄字面量字符串**。

## 3. 验证包（手工测试与验证）
**前置条件**：03 已通过；Redis 可用（需在 pom.xml 中添加依赖）；会话带 sessionId。

**材料 A——多轮剧本**：①"查订单 DD20240810"→②"刚才那个订单到哪了"。

**材料 B——重启剧本**：同一 sessionId 问两轮 → 重启应用 → 第三轮追问。

**步骤与断言**：

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | 材料A ①② | 第②轮能记住 DD20240810（不需要重说订单号） |
| 2 | 换新 sessionId 问② | 记不住（隔离正确，不串会话） |
| 3 | 材料B 重启后第③轮 | 历史仍在（Redis 持久化生效，非内存） |
| 4 | 连续对话 >20 轮 | Redis 中该会话只保留最近 20 条（窗口裁剪生效） |

**失败排查**：①记不住→Memory Advisor 未挂或 conversationId 未传；②串会话→sessionId 固定写死（应每会话唯一）；③重启丢→仍用 InMemoryChatMemoryRepository（换 Redis 实现）；④不裁剪→窗口参数未生效（检查 MessageWindowChatMemory 配置）。
