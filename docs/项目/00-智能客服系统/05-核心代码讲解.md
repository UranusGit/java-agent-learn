## 3. 四段核心代码精讲

### 3.1 ChatClient 构建链（[02 §2.4]、[03 §2.5]、[04 §2.5]）

**为什么这样写**：
- `defaultSystem` 定人格（系统消息每次自动注入）
- `defaultTools` 注册能力（`@Tool` Bean 或 `ToolCallbackProvider`）
- `defaultAdvisors` 编排横切（RAG Advisor 先检索、Memory Advisor 后注入历史）
- **Advisor 顺序**：RAG → Memory → … 由 `@Order`/`getOrder()` 控制（[教程 13 §执行顺序]）

### 3.2 工具调用（[02 §2.2-2.3]）

**为什么这样写**：
- LLM 不执行代码，它只决定「调什么工具、传什么参数」；真正执行由 Spring AI 反射调用你的 Java 方法
- `@ToolParam(description)` 是 LLM 的唯一依据——**必须写清楚**
- 返回用 `record`（结构化输出），LLM 能稳定消费

### 3.3 RAG 检索注入（[03 §2.3-2.5]）

**为什么这样写**：
- ETL 三件套 `DocumentReader → TokenTextSplitter → VectorStore.add` 完成「文档 → 向量库」
- `QuestionAnswerAdvisor` 在每次请求时检索相关块注入上下文——**RAG 是横切关注点，用 Advisor 而非硬编码**
- `similarityThreshold=0.7` 防无关召回

### 3.4 记忆注入与保存（[04 §2.3-2.5]）

**为什么这样写**：
- `ChatMemory` 门面 + `ChatMemoryRepository` 存储两层组合
- **Redis 持久化必须自研 `ChatMemoryRepository`**（官方无 Redis 实现；用 `ReactiveRedisTemplate`，WebFlux 铁律）
- `MessageChatMemoryAdvisor` 流式也会自动写入（[附录 12-00 §2]）
