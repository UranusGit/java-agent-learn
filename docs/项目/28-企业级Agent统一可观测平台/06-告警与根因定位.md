## 二、根因树（依赖拓扑定位）

```java
// 概念代码：拓扑根因
public RcaResult analyze(List<Alert> storm) {
    var graph = topo.of(storm);                  // 按调用依赖建图(网关→模型→工具→检索)
    var origin = graph.findOrigins(storm);       // 入度为0的故障节点=首发(非被连带)
    return RcaResult.of(origin,
        suggestion(origin),                       // 规则建议(如"模型网关5xx→查上游限流")
        evidence(storm));                         // 聚合证据(受影响链路样本)
}
```

### 二.1 本节测试与验证（告警聚合与拓扑根因）

**前置条件**：AlertHub 已接入 05 信号与依赖拓扑；能构造"网关→模型→工具→检索"的连锁故障事件。

**材料——核对手段**：在测试环境制造一次网关抖动，连锁触发若干条下游告警；对 `analyze(storm)` 的结果断言。

**材料——核对命令**：

```bash
# 查询聚合后的根因告警（rca=true 返回首发节点/抑制计数/建议/证据）
curl "http://localhost:8081/obs/alerts?window=1h&rca=true"
```

预期输出示例（约 30 条连锁告警被聚合为 1 条，origin 指向首发故障节点）：

```json
{
  "window": "1h",
  "alerts": [
    {
      "rootCause": "llm-gateway",
      "suppressedCount": 28,
      "suggestion": "模型网关5xx → 查上游限流",
      "evidence": ["trace-abc123", "trace-def456"]
    }
  ]
}
```

**步骤与断言**：

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | 制造网关抖动连锁约 30 条告警 | 聚合为 ≤3 条根因告警（同源抑制/时间窗合并生效） |
| 2 | 查看根因 | origin 指向入度为 0 的首发故障节点（网关），非被连带的链式节点 |
| 3 | 查看建议与证据 | suggestion 来自规则/历史模式，evidence 含受影响链路样本 |
| 4 | 建议覆盖抽样 | 任一批故障中根因建议命中率 ≥80%（00 验收④） |

**失败排查**：①聚合超 3 条 → 同源/时间窗合并未生效；②首发指偏 → 依赖拓扑建错边（方向/缺失），回查 topo 构造；③建议率低 → 规则库/历史案例覆盖不足，补规则样本。
