## 二、usage 挂链路与聚合

```java
// 概念代码：usage 归因（Span 属性 → 多维聚合）
// 每次 LLM 调用的 gen_ai.usage.* 属性带 traceId/sessionId/tenantId(02管道增补)
public CostView cost(RangeWindow w, DimSlice dim) {
    return metrics.query("gen_ai_token_total", w, dim)     // 按租户/业务线/模型切片
        .map(m -> CostView.of(m.dims(), m.value().multiply(priceTable.of(m.modelDim()))));
}
public List<SessionCost> topExpensive(RangeWindow w, int n) {  // 烧钱会话 TopN
    return store.topSessionsByUsage(w, n);   // → 3 跳下钻到该会话链路(03)
}
```

### 二.1 本节测试与验证（usage 归因聚合）

**前置条件**：usage 走指标不采样（ADR-05 / `## 一` 影响模块）；每次 LLM 调用带 `gen_ai.usage.*` + traceId/sessionId/tenantId 属性。

**材料——核对手段**：对已知会话触发大 Token 任务，用多维聚合查询；制造一次成本突增对照 `topExpensive`。

```bash
# 对时间窗内按租户/业务线/模型切片查 token 总量
curl "http://localhost:8080/obs/cost?window=<w>&slice=<tenant|bizline|model>"
```

**步骤与断言**：

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | 某会话跑大任务，查该会话 usage | 该会话 Token/费用可单独切出（会话级 100% 下钻） |
| 2 | 任意窗口查询 | `gen_ai_token_total` 按租户/业务线/模型维度切片返回，单价换算正确（`priceTable.of(model)`） |
| 3 | 制造月成本突增 | 归因能定位到具体租户/模型/会话类型（异动维度） |
| 4 | 调 `topExpensive(w,n)` | 返回烧钱会话 TopN，且能下钻到该会话链路（03） |

**失败排查**：①会话级查不出 → usage 属性未带 sessionId（02 管道标签缺失或采集未启），核对属性链条；②单价换算错 → `priceTable` 模型维度 mapping 缺失；③TopN 下钻断 → 会话→traceId 关联键缺失，回查 01/03。
