## 二、双层 SLO 与错误预算

```java
// 概念代码：Agent SLO 体系
enum AgentSlo {
    TECH_AVAIL(0.995),      // 技术可用性(非5xx)
    TECH_P95_MS(2500),      // 首 Token P95
    BIZ_SUCCESS(0.92),      // 业务成功率(会话完成且达标)
    BIZ_SATISFY(0.85);      // 满意度(正反馈占比)
}
// 错误预算 = (1-SLO)×窗口流量; 预算耗尽 → 冻结非紧急变更(联动23/26发布管道)
// 燃烧率 = 实际错误率/预算错误率: >14.4(1h)快烧P0 / >6(6h)慢烧P1
```

**要点**：**业务 SLO 比技术 SLO 更重要**——服务全绿但答非所问（业务 SLO 塌）仍是故障；业务 SLO 数据来自 05 的会话评分。

### 二.1 本节测试与验证（双层 SLO 与错误预算）

**前置条件**：管道指标（错误率/首 Token P95）+ 05 会话评分可采；SloService 监控四类 `AgentSlo` 指标。

**材料——核对手段**：在玻璃板健康视图查看四类 SLO 的达成率与预算余量；构造燃烧率越界场景验证冻结与分级告警。

**步骤与断言**：

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | 打开 SLO 看板 | 技术双层（可用性/P95）+ 业务双层（成功/满意）的达成率与预算余量可见 |
| 2 | 业务评分侧喂入低分会话（05） | 业务 SLO（BIZ_SUCCESS/BIZ_SATISFY）达成率下降，能被纳入故障判定 |
| 3 | 制造预算耗尽（错误率越界） | SloService 触发变更冻结（联动 26/23 发布管道），非紧急变更被拦 |
| 4 | 制造快烧/慢烧 | 快烧（1h>14.4）→ P0 分页告警；慢烧（6h>6）→ P1 告警 |

**失败排查**：①看板空 → 四类指标未采到（技术取管道原始指标、业务取 05 评分）；②不冻结 → 燃烧率未达阈值或联动发布管道接口未接；③分级不准 → 燃烧率阈值/窗口配置错位，核对 1h/6h 口径。
