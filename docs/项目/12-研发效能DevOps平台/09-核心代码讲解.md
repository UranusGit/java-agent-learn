## 1. 六个关键设计复盘

### 1.1 为什么代码库 RAG 是"AST 分块"而非文本切块

代码不是自然语言——文本切块会把方法切开、丢失作用域链。JavaParser 按方法/类边界分块 + 作用域链元数据，Recall@5 +4.3（cAST 论文）。**代码 RAG 本质是"解析问题，不是检索问题"**——索引质量决定检索质量，检索质量决定所有下游（审查/测试/诊断）的质量。[01 §3.6-3.7] 的 `JavaChunk`/`JavaChunkIndexer` 是完整可手写实现。

### 1.2 为什么审查是"静态层先行 + LLM 收尾"

SAST+LLM 混合 F1 0.91-0.95 vs 纯 SAST 0.10-0.55 vs 纯 LLM 0.61-0.68（[调研 §SAST+LLM]）。静态层（SpotBugs/Semgrep）确定性抓硬问题，LLM 只做语义层收尾。**关键红线：禁止 LLM 自动 suppression 真阳性**——LLM 过滤 SAST 误报时会系统性误杀真漏洞（CWE-327 漏判率 77%）。[02 §3.6] 的 `SemgrepRunner` 直接解析 `--json` 输出，L1 处置由 SAST 规则判定。

### 1.3 为什么测试用"变异测试闸门"而非行覆盖率

行覆盖率可被 AI 刷分（92% 可编译但只杀 58-62% 变异 vs 人类 78%）——LLM 生成的测试能"跑过"但抓不住 bug。变异测试（PIT）注入变异体、测试必须杀死才有效，**不可刷分**。[03 §3.7] 的 `MutationGate` 解析 PIT 的 `mutations.xml` 算 kill rate，这是质量闸门的本质。

### 1.4 为什么多 Agent 评审要"强聚合层"

并行专业 Sub-Agent（安全/性能/架构/合规）各查一个维度，但评论会重复/矛盾。聚合层做四件事：语义去重、共识打分（严重度×命中 Agent 数）、幻觉过滤（无代码依据丢弃）、争议上抛 HITL。**聚合 Agent 禁止重新审查**——对撕式重审实证性降低 precision。[05 §3.6] 的 `ReviewAggregator` 完整实现这四步，`CodeIndexService.validLocation` 做幻觉过滤。

### 1.5 为什么评估要"盲评 + 误报率门槛"

LLM-judge 有过度纠正偏置（48.2% 假阴性来自泛化断言）与确认偏置（对抗性元数据可改变检出率 59.6pp）——必须脱敏盲评。**误报率是生死线（<5% 上线门槛）**：误报淹没开发者的后果比漏报更重。[07 §3.6] 的 `BlindJudge` 用脱敏 prompt（不含来源标注），`OnlineMetrics` 用 `Counter` 算 dismissed/total。

### 1.6 为什么私有代码安全要"检索前 Fail Closed"

事后过滤（先检索再删敏感代码）是结构性失败——敏感代码已经进了上下文/LLM。**权限过滤必须在 ANN pre-filter 层（元数据过滤），严禁 post-filter**；Fail Closed（无权限即拒绝，不静默跳过）。[08 §3.7] 的 `SecureCodeSearchService` 用 `filterExpression("department == ...")` 先过滤再检索。

## 4. 最容易写错的五处

| # | 位置 | 错误 | 后果 | 正确 |
|---|------|------|------|------|
| 1 | 代码分块 | 文本切块 | 方法被切开/丢失作用域 | JavaParser AST 分块 |
| 2 | 审查 | 纯 LLM / 让 LLM 过滤 SAST | 误报超标 / 误杀真漏洞 | 静态层先行 + 禁止 suppression 真阳性 |
| 3 | 测试 | 行覆盖率闸门 | 可被 AI 刷分 | 变异测试闸门 |
| 4 | 评估 | Judge 不盲评 | 确认偏置扭曲结论 | 脱敏盲评 + 独立模型 |
| 5 | 安全 | post-filter 权限 | 敏感代码已进上下文 | 检索前 Fail Closed |
