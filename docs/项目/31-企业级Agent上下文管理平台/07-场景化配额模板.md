## 二、场景模板

```yaml
# 概念配置：场景配额模板
support-bot:            # 客服: 记忆重(用户历史偏好关键)
  fixedSystem: 300
  weights: { memory: 0.5, rag: 0.3, tools: 0.2 }
  compression: HYBRID
data-analyst:           # 分析: RAG重(证据为主)
  weights: { memory: 0.2, rag: 0.6, tools: 0.2 }
risk-agent:             # 风控: 工具/规则重
  weights: { memory: 0.15, rag: 0.25, tools: 0.6 }
```

### 二.1 本节测试与验证（场景模板继承覆盖）

**前置条件**：`TemplateStore` 支持三内置模板、业务继承+局部覆盖、配置热更新生效机制。

**步骤与断言**：

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | 新客服业务直接套 `support-bot` 模板装配 | 开箱即用，配额/权重/压缩（HYBRID）全部生效，无需手调 |
| 2 | 某分析业务仅覆盖 `weights.rag`（如 0.6→0.7） | 只改 RAG 权重，其余字段继承模板默认值，未覆盖项不变 |
| 3 | 校验各场景权重 | `support-bot`(0.5/0.3/0.2)、`data-analyst`(0.2/0.6/0.2)、`risk-agent`(0.15/0.25/0.6) 各自之和 =1 |
| 4 | 修改模板 YAML 后触发热更新 | 分钟级生效（灰度），新装配用新配额，无需重启 |
| 5 | 覆盖冲突 | 继承+覆盖无二义性（覆盖只在叶子字段，不整层覆盖） |

**失败排查**：①新业务没配额→`TemplateStore` 未加载该模板/未配置默认场景；②覆盖影响了别字段→覆盖粒度过粗（应叶子级）；③热更不生效→配置刷新未监听/灰度未放行新版本。
