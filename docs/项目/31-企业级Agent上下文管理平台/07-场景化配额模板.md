# 07-场景化配额模板

> **定位**：让配额**按业务场景**开箱即用——**① 场景模板（客服/数据分析/风控各自的配额与压缩策略）② 模板继承与覆盖 ③ 配置热更新**。呼应 [23-路由配置数据化](../../项目/23-企业级Agent意图路由网关/06-路由灰度与秒级回滚.md)。前置阅读：[06-裁剪可观测与装配审计](06-裁剪可观测与装配审计.md)。
>
> **铁律 0**：模板模型/热更自研「概念代码」。

---

## 一、四问

| 问 | 答 |
|----|----|
| **新增了什么需求** | ①三场景模板（客服重记忆、分析重 RAG、风控重规则/工具）②业务继承模板+局部覆盖 ③配额配置热更新（灰度生效） |
| **影响了哪些模块** | BudgetAllocator → 模板化配置源 |
| **架构如何演进** | 配额从"每业务手调"演进为"模板继承+按需覆盖" |
| **上一版痛点** | 新业务从零调配额；一套默认不合所有场景 |

**本迭代验收**：①三模板开箱即用 ②业务覆盖单项（如只改 RAG 配额）③热更新分钟级生效。

## 二、场景模板

```yaml
# 概念配置：场景配额模板
support-bot:            # 客服: 记忆重(用户历史偏好关键)
  fixedSystem: 300
  weights: { memory: 0.5, rag: 0.3, tools: 0.2 }
  compression: HYBRID
data-analyst:           # 分析: RAG重(证据为主)
  weights: { memory: 0.2, rag: 0.6, tools: 0.2 }
risk-agent:             # 风控: 工具/规则重
  weights: { memory: 0.15, rag: 0.25, tools: 0.6 }
```

## 三、验收

| 测试 | 期望 |
|------|------|
| 新客服业务 | 套 support-bot 模板即用 |
| 局部覆盖 | 只改 rag 权重其余继承 |
| 热更新 | 改配置分钟级生效 |
