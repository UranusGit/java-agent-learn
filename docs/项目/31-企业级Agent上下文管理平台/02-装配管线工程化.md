# 02-装配管线工程化

> **定位**：把整层丢弃升级为**部分裁剪**——**① 层注册（业务可扩展层）② 每层声明自己的"瘦身"策略（RAG 减 topK/工具减挂载/记忆减条数，而非全丢）③ 层间依赖（工具层依赖路由结果）**。前置阅读：[01-最小Demo](01-最小Demo.md)。
>
> **铁律 0**：管线/瘦身策略自研「概念代码」。

---

## 一、四问

| 问 | 答 |
|----|----|
| **新增了什么需求** | ①层注册 SPI（业务自定义层如"合规声明层"）②瘦身策略接口（shrink(targetTokens)）③层依赖解析（工具层按意图路由结果选择） |
| **影响了哪些模块** | Assembler → 管线化；层 → 策略化 |
| **架构如何演进** | 从"固定五层整丢"演进为"可扩展层+渐进瘦身" |
| **上一版痛点** | RAG 超预算只能全丢（丢掉全部证据）；业务无法插入自有层 |

**本迭代验收**：①业务注册自定义层生效 ②RAG 超载减 topK 保 top1（不全丢）③工具层按路由只挂相关工具。

## 二、瘦身策略（渐进而非丢弃）

```java
// 概念代码：层的渐进瘦身
public interface ContextLayer {
    int shrink(int targetTokens);   // 各层自己知道怎么缩
}
// RAG层: topK→topK/2→top1 (证据保底)
// 工具层: 全量Schema→只挂路由命中的3个→精简描述
// 记忆层: topK召回→只留最高相关→摘要化
// 系统提示/用户输入: shrink() 直接抛异常(不可裁,底线)
```

**要点**：**每层最懂自己怎么缩**——RAG 知道哪条证据最重要、工具知道哪些被路由命中。管线只负责"要你缩到多少"，缩法由层自治。

## 三、验收

| 测试 | 期望 |
|------|------|
| RAG 层超载 | topK 渐减，不全丢 |
| 自定义"合规层" | 注册后参与装配 |
| 路由命中 2 工具 | 工具层只挂 2 个 |
