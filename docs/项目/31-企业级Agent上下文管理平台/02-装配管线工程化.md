## 二、瘦身策略（渐进而非丢弃）

```java
// 概念代码：层的渐进瘦身
public interface ContextLayer {
    int shrink(int targetTokens);   // 各层自己知道怎么缩
}
// RAG层: topK→topK/2→top1 (证据保底)
// 工具层: 全量Schema→只挂路由命中的3个→精简描述
// 记忆层: topK召回→只留最高相关→摘要化
// 系统提示/用户输入: shrink() 直接抛异常(不可裁,底线)
```

**要点**：**每层最懂自己怎么缩**——RAG 知道哪条证据最重要、工具知道哪些被路由命中。管线只负责"要你缩到多少"，缩法由层自治。

### 二.1 本节测试与验证（渐进瘦身）

**前置条件**：各层 `ContextLayer.shrink(int targetTokens)` 已实现（RAG 减 topK、工具按路由挂、记忆精简）；可注入真实超载层。

**核对命令**（按 §二 代码手写用例后执行）：

```bash
mvn test -Dtest=LayerShrinkTest        # RAG 渐减/工具按路由/不可裁抛异常用例
# 预期输出（节选）：
#   Tests run: 5, Failures: 0, Errors: 0, Skipped: 0
#   topK 8→4→top1 保底；系统/用户层 shrink 抛异常
#   BUILD SUCCESS
```


**步骤与断言**：

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | RAG 层 `topK=8` 超载，调 `shrink(target)` | topK 渐减（8→4→2/1），最终保 top1，证据非全丢 |
| 2 | 工具层全量 Schema，路由命中 2 个，调 `shrink` | 挂载从全量减到命中 2 个，Schema 精简描述，未命中者被裁 |
| 3 | 业务注册自定义"合规声明层"，load 进管线 | 该层参与装配（内容出现在渲染输出中），自定义生效 |
| 4 | 对系统提示层调 `shrink` | 抛异常/拒绝（不可裁底线），系统提示保留 |
| 5 | 对用户输入层调 `shrink` | 同上，用户输入保留 |

**失败排查**：①RAG 全丢→瘦身未保底 `top1`（`shrink` 少了一次 stop 判断）；②工具层没瘦身→未读取路由结果（依赖解析未接通）；③系统/用户被缩→`shrink` 未对不可裁层抛异常。
