## 一、四问

| 问 | 答 |
|----|----|
| **新增了什么需求** | ①配额模型（系统提示固定额、用户输入保底额、记忆+RAG 竞争池）②动态调剂（竞争池内按相关度分配）③配额执行与观测（每次装配的分配留痕） |
| **影响了哪些模块** | Assembler → 配额前置；新增 BudgetAllocator |
| **架构如何演进** | 预算从"总量控制"演进为"结构化分配" |
| **上一版痛点** | 总包干下记忆挤爆 RAG（或反之）；系统提示被挤变形 |

**本迭代验收**：①固定层/保底层永不被挤 ②竞争池按需动态分配 ③每次装配配额分配可查。

## 二、配额模型

```java
// 概念代码：三层配额
public record LayerBudget(int fixedSystem,      // 固定:系统提示(契约,不参与竞争)
                          int reserveUser,       // 保税:用户输入(底线,不参与竞争)
                          int competitivePool) {} // 竞争池:记忆+RAG+工具按需争
// 竞争池分配:按"相关度得分×层权重"加权分配(记忆3条高相关>RAG 8条低相关时记忆多分)
public Map<String,Integer> allocate(int pool, List<Demand> demands) {
    return weightedByRelevance(demands, pool);   // 相关度高者多得,不足者触发02瘦身
}
```

## 三、验收

| 测试 | 期望 |
|------|------|
| 记忆高相关 | 竞争池多分给记忆 |
| 用户超长输入 | 保底层扩、竞争池让 |
| 分配记录 | 每次装配留痕（供 05 观测） |
