## 二、配额模型

```java
// 概念代码：三层配额
public record LayerBudget(int fixedSystem,      // 固定:系统提示(契约,不参与竞争)
                          int reserveUser,       // 保税:用户输入(底线,不参与竞争)
                          int competitivePool) {} // 竞争池:记忆+RAG+工具按需争
// 竞争池分配:按"相关度得分×层权重"加权分配(记忆3条高相关>RAG 8条低相关时记忆多分)
public Map<String,Integer> allocate(int pool, List<Demand> demands) {
    return weightedByRelevance(demands, pool);   // 相关度高者多得,不足者触发02瘦身
}
```

### 二.1 本节测试与验证（分层配额分配）

**前置条件**：`BudgetAllocator` 三层配额已实现；可构造 `fixedSystem/reserveUser/competitivePool` 及各层 `Demand`。

**步骤与断言**：

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | 记忆 3 条高相关 vs RAG 8 条低相关，竞争池有限 | 竞争池按相关度加权多分给记忆（相关度高者多得） |
| 2 | 用户输入超长 | 保底层（`reserveUser`）自动扩，竞争池让出（保底不被挤） |
| 3 | 系统提示配额固定 | `fixedSystem` 不参与竞争、值不变（契约） |
| 4 | 竞争池耗尽、需求仍不足 | 不足者触发 02 渐进瘦身（而非直接丢） |
| 5 | 每次装配 | 分配结果留痕（配额分配记录供 05/06 观测） |

**失败排查**：①固定层被挤→`allocate` 把 `fixedSystem/reserveUser` 误并入竞争池；②竞争池全给 RAG→权重未按相关度归一化；③分配未留痕→未写 `LayerStat`，回看 06 装配报告结构。
