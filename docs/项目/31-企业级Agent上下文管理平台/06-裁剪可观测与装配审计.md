## 二、装配报告

```java
// 概念代码：装配报告（每次输出）
public record AssemblyReport(String runId,
        Map<String, LayerStat> layers,     // 每层: 请求/分配/实际token, 裁剪动作
        String compression,                // 压缩路径与摘要比例
        int cacheStatus) {}                // KV/语义/检索 命中情况
// 与 28 平台信号关联: 裁剪率高的会话 vs 评分低的会话 相关性分析
// → "裁剪过度导致效果差"从猜测变数据
```

### 二.1 本节测试与验证（装配报告与审计）

**前置条件**：`AssemblyReport` 已在每次装配末尾记录（`report.record(runId, layers, ...)`）；可查询历史报告。

**步骤与断言**：

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | 触发一次完整装配（受剪场景） | 产出报告：含各层 `LayerStat`（请求/分配/实际 token、裁剪动作）、`compression` 压缩路径、`cacheStatus` 命中情况 |
| 2 | 抽查多轮 | 每轮都有报告（可查 100%，00 验收⑤） |
| 3 | 裁剪-效果分析 | 能把"批量裁剪率"与"该会话评分"关联计算，输出相关性（裁剪过度→效果差有数据支撑） |
| 4 | 观测联动 | 装配事件已进入观测管道（玻璃板可见，28） |

**失败排查**：①无 `runId`→报告未在装配末尾记录；②缺裁剪动作→`LayerStat` 未记录 `trim`；③关联算不出→裁剪率与评分未打同一次装配的信号令牌。
