## 一、四问

| 问 | 答 |
|----|----|
| **新增了什么需求** | ①装配报告（层/配额/裁剪/压缩/token 明细）②裁剪-效果关联（裁剪多的会话效果差？）③装配事件可查（排障/解释素材） |
| **影响了哪些模块** | Assembler → 全程打点；新增 AssemblyReport |
| **架构如何演进** | 装配从"黑盒输出"演进为"透明可审计" |
| **上一版痛点** | 效果差不知是否因裁剪过度；排障看不见装配细节 |

**本迭代验收**：①每次装配报告可查 100%（00 验收⑤）②裁剪与效果可关联分析 ③装配事件入观测管道。

## 二、装配报告

```java
// 概念代码：装配报告（每次输出）
public record AssemblyReport(String runId,
        Map<String, LayerStat> layers,     // 每层: 请求/分配/实际token, 裁剪动作
        String compression,                // 压缩路径与摘要比例
        int cacheStatus) {}                // KV/语义/检索 命中情况
// 与 28 平台信号关联: 裁剪率高的会话 vs 评分低的会话 相关性分析
// → "裁剪过度导致效果差"从猜测变数据
```
