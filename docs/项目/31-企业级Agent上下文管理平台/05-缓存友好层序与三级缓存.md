## 二、层序与三级缓存

```java
// 概念代码：稳定层序渲染 + 三级缓存
public String renderCacheFriendly(List<ContextLayer> layers) {
    return layers.stream()
        .sorted(comparing(ContextLayer::volatility))   // 波动性升序:最稳在前
        .map(ContextLayer::content).collect(joining()); // 系统→工具→记忆→RAG→用户
}   // 同会话轮次间前缀不变 → KV/Prompt Cache 复用(推理侧)

public Mono<String> ask(String input) {
    return semanticCache.hit(input)                     // ①语义缓存:相似问复用答案
        .switchIfEmpty(retrievalCache.andAssemble(input) // ②检索缓存:query复用
            .map(ctx -> llm.call(ctx)));                 // ③KV缓存:前缀复用(推理服务)
}
```

### 二.1 本节测试与验证（稳定层序与三级缓存）

> KV 命中率提升为推理侧能力，本节点验证"前缀稳定性"（层序）与语义/检索缓存命中行为；`≥30%` 指标联动侧压测。

**前置条件**：`renderCacheFriendly` 与三级缓存已实现；同一会话可多次 `ask`。

**步骤与断言**：

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | 同一会话内两轮装配（用户输入变，其余稳定） | 两轮渲染结果是稳定层序，可变部分只在末尾（用户层）→ 前缀不变 |
| 2 | 相似问题两次 `ask`（语义缓存开启） | 第二次命中语义缓存，复用答案（省钱） |
| 3 | 相同 query 两次（检索缓存开启） | 第二次直接命中检索结果，不重复检索 |
| 4 | 高风险场景发起相似问题 | 语义缓存被禁用，如实重新推理（不命中） |
| 5 | 侧压测同会话多轮 | KV/前缀命中率较旧层序提升 ≥30%（00 验收③） |

**失败排查**：①前缀仍变→`volatility` 排序未生效（系统/工具层被排到末位）；②相似问题不命中→语义阈值过低/未开启缓存键归一化；③高风险仍命中→禁用开关未在 `hit` 前判断。

## 三、失效纪律

| 缓存 | 失效触发 |
|------|---------|
| 语义 | 高风险场景禁用 + TTL + 人工反馈负相关时清 |
| 检索 | 知识库版本变更（血缘联动） |
| KV 前缀 | 层内容变化（系统提示改版/工具集变） |
