## 二、失败分类 → 降级链

```java
// 概念代码：失败降级链（按类型确定性路由）
public Mono<DelegationResult> resilientDelegate(DelegationRequest req) {
    return doDelegate(req)
        .retryWhen(Retry.backoff(2, Duration.ofSeconds(2))     // 瞬时故障:指数退避重试
            .filter(this::isTransient))                          // 只重试瞬时(网络抖动)
        .onErrorResume(e -> switch (failureType(e)) {
            case NEGOTIATION_REJECTED, CAPABILITY_MISS ->
                tryAlternativeAgent(req);                        // 协商拒/能力不匹配→换Agent
            case TIMEOUT -> queryThenFallback(req);              // 超时→先查状态再降级(04)
            case RESULT_REJECTED -> reDelegateWithHint(req);     // 结果拒收→带拒收原因重委托
            case DEGRADED -> localFallback(req);                 // 对方降级→本地兜底模式
            default -> escalateToHuman(req, e);                  // 兜底:转人工(HITL)
        });
}
```

**链序**：瞬时重试 → 换 Agent → 带因重委托 → 本地兜底 → 人工。**前面的便宜，后面的贵**——和 [23-兜底降级链](../../项目/23-企业级Agent意图路由网关/07-兜底降级链与HITL闸门.md)、[32-模型降级](../../教程/04-企业级架构主干/12-模型路由与降级.md) 一脉的方法论。

### 二.1 本节测试与验证（失败分类与降级链）

**前置条件**：`resilientDelegate(req)` 可执行；可构造 瞬时网络抖动 / 协商拒绝 / 结果拒收 / 降级 / 全链失败 五类故障注入。

**材料——降级矩阵**：

| 测试 | 期望 |
|------|------|
| 网络抖动 | 退避重试成功 |
| 协商拒绝 | 自动换同能力 Agent |
| 结果拒收 | 带原因重委托 |
| 全链失败 | 转人工不中断报错 |

**步骤与断言**：

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | 注入瞬时故障 | `retryWhen(Retry.backoff(2,2s))` 仅对 transient 生效，重试后成功 |
| 2 | NEGOTIATION_REJECTED / CAPABILITY_MISS | 换同能力 Agent 重委托，不报错 |
| 3 | TIMEOUT | 先查状态再降级（不盲目重委托，承 04） |
| 4 | RESULT_REJECTED | 带拒收原因重委托 |
| 5 | DEGRADED | `localFallback` 本地兜底模式执行 |
| 6 | 全链失败 | `escalateToHuman` 转人工，不中断报错 |

**失败排查**：①瞬时故障被重试成重放副作用→`isTransient` 判定过宽，把非幂等也重试；②协商拒绝不换 Agent→`failureType` 分类落到 default；③超时被重试→未走 TIMEOUT 分支先查状态。

## 三、补偿动作（对已发生的副作用）

```java
// 概念代码：副作用补偿注册表
public interface Compensable { Mono<Void> compensate(DelegationTask t); }

// 例：委托"群发通知"后取消——已发的消息不能撤回，但可发更正；委托"创建报表"取消——删除半成品
compensator.register("notify.broadcast", t -> sendCorrection(t));   // 逆操作
compensator.register("report.create",   t -> cleanupDraft(t));      // 清理
compensator.register("payment.*",       t -> escalateToHuman(t));   // 不可逆→人工
```

**纪律**：**不可逆副作用（支付/外发）不允许自动补偿**——升人工裁决（呼应 [28-HITL](../../教程/04-企业级架构主干/08-Human-in-the-Loop与审批流.md)）；可逆的登记逆操作自动执行。

### 三.1 本节测试与验证（补偿动作）

**前置条件**：`Compensator` 注册表已装 `notify.broadcast`/`report.create`/`payment.*` 等条目；可触发取消含副作用的任务。

**材料——补偿矩阵**：

| 测试 | 期望 |
|------|------|
| 取消含副作用任务 | 补偿动作按注册执行 |
| 不可逆副作用（`payment.*`） | 升人工，禁止自动补偿 |

**步骤与断言**：

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | 取消 `notify.broadcast` 任务 | 触发 `sendCorrection`（已发消息的更正） |
| 2 | 取消 `report.create` 任务 | 触发 `cleanupDraft`（删除半成品） |
| 3 | 取消 `payment.*` 任务 | 不自动补偿，`escalateToHuman` 转人工裁决 |
| 4 | 核对补偿登记 | 可逆副作用均在注册表有逆操作条目 |

**失败排查**：①不可逆仍自动补→`payment.*` 未注册为不可逆/拦截缺失；②可逆没补偿→注册表缺条目或补偿器未在取消点触发；③补偿重复→补偿动作非幂等。

## 四、全篇回归验证

> §二.1（降级链）与 §三.1（补偿）均通过后的整体验收。

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | 五类失败各注入一次 | 各走对降级路径（重试/换Agent/带因重委托/本地兜底/人工），业务不中断（对照 00 验收④） |

**回归失败排查**：任一步 FAIL 按 §二.1/§三.1 排查项回溯（failureType 分类 / isTransient / 补偿注册 / 不可逆拦截）；对照 00 验收④「协作失败可降级（不中断业务）」。
