## 二、身份互信（谁在委托）

```java
// 概念代码：跨域身份验证（JWT 签名验证 / SVID 校验）
public Identity verify(AuthCredential cred) {
    return switch (cred) {
        case JwtCredential j -> jwtVerifier.verify(j.token());   // OIDC/JWT(需引入依赖后实证)
        case SvidCredential s -> spiffe.verify(s.x509());        // SPIFFE/SVID(呼应16网格)
        default -> throw new Unauthorized("credential required");
    };
}
// 所有协作 API 前置：无有效身份 = 拒绝（Fail-closed）
```

### 二.1 本节测试与验证（跨域身份互信）

**前置条件**：`verify(AuthCredential)` 可执行；可构造合法 `JwtCredential`/`SvidCredential` 与非法（过期/篡改/空）凭证。注意：JWT/OIDC/SPIFFE 校验需引入依赖后实证，先以明文/JDK 可验的测试密钥落地。

**材料——凭证矩阵**：

| 测试 | 期望 |
|------|------|
| 无凭证委托 | 401 拒绝 |
| 伪造/过期凭证 | 校验失败拒绝（Unauthorized） |
| 合法 JWT 凭证 | 返回 Identity（issuer/sub 可读） |

**步骤与断言**：

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | 无凭证调用协作 API | Unauthorized，Fail-closed（不进入委托） |
| 2 | 伪造/过期凭证 | 验证抛 `Unauthorized`，身份未建立 |
| 3 | 合法凭证 | `verify` 返回 Identity，协作 API 放行 |
| 4 | 缺省 default 分支 | 未知凭证类型命中 default → Unauthorized |

**失败排查**：①无凭证仍进入委托→协作 API 前置校验缺失；②伪造凭证通过→签名验证未做（`jwtVerifier.verify` 只验结构未验签名）；③default 兜不住→switch 缺 default 分支。

## 三、最小授权（委托不放大）

```java
// 概念代码：授权裁决（交集语义）
public Set<String> adjudicate(DelegationRequest req, Identity caller) {
    Set<String> granted = caller.permissions();          // 原始授权(来自用户/平台)
    Set<String> wanted  = Set.of(req.capability());
    if (!granted.containsAll(wanted))
        throw new Forbidden("委托超出原始授权: " + diff(granted, wanted));   // 不放大
    return wanted;                                        // 最小集放行
}
```

**规则**：`放行权限 = 原始授权 ∩ 目标能力`——委托方**不能把自己没有的能力转委托出去**，也**不能要求超出用户授权的 scope**（呼应 [16-网格"委托不放大"](../../项目/16-企业级Agent服务网格/10-A2A互操作与策略市场.md)、[08-零信任 PDP](../../项目/08-Agent供应链安全网关/06-零信任策略引擎.md)）。

### 三.1 本节测试与验证（委托不放大）

**前置条件**：`AuthorizationPDP.adjudicate(req, caller)` 可执行；可给 caller 配置不同的 `permissions()` 集合、给 `DelegationRequest` 配不同 `capability()`。

**材料——授权矩阵**：

| 测试 | 期望 |
|------|------|
| 委托方没有的能力 | 403 拒绝 + 审计 |
| 转委托放大（要求超出原始授权 scope） | 被交集裁决拦下 |
| 正常最小授权（capability ⊆ granted） | 放行且记录 |

**步骤与断言**：

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | caller 无 `report.generate` 却委托该能力 | `Forbidden`（"委托超出原始授权: diff"），不放大 |
| 2 | 需要用户授权之外的额外 scope | 被拦（交集语义），未放行超额权限 |
| 3 | caller 有该能力且范围内 | 返回 wanted 最小集，放行 |
| 4 | 核对放行集 | 返回值 ⊆ `granted ∩ wanted`，无越权 |

**失败排查**：①无权限仍放行→`containsAll` 校验未执行或未抛 Forbidden；②放大未拦→放行集不是交集而是并集/直接取 wanted；③拒绝未记录→Forbidden 未进审计。

## 四、拒绝审计

所有 Forbidden/Unauthorized 落审计（who/target/capability/ts）——既是安全回溯证据，也是异常行为（高频越权尝试）告警的数据源（呼应 [23-审计](../../教程/04-企业级架构主干/03-工具执行可观测与审计.md)）。

### 四.1 本节核对（拒绝审计）

| # | 核对项 | 判据 |
|---|--------|------|
| 1 | 审计字段齐全 | Forbidden/Unauthorized 记录含 who/target/capability/ts，可回溯 |
| 2 | 审计与告警闭环 | 高频越权可被盯（异常行为数据源），非只存不用 |

## 五、全篇回归验证

> §二.1（身份互信）与 §三.1（委托不放大）均通过后的整体验收。

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | 无凭证 / 伪造凭证 / 越权放大各触发一次 | 全线拒绝且落审计（对照 00 验收②/③：委托不放大 100%、注入拦截 100%） |
| 2 | 合法凭证 + 范围内最小授权 | 放行且记录，放行集 ⊆ 原始授权 ∩ 目标能力 |
| 3 | 核对审计 | 每次 Forbidden/Unauthorized 均可查 who/target/capability/ts |

**回归失败排查**：任一步 FAIL 按 §二.1/§三.1 排查项回溯（前置校验 / 签名验证 / 交集裁决）；对照 00 验收②「委托不放大 100%」。
