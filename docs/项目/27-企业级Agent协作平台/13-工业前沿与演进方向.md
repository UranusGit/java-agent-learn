| 方案 | 性质 | 与本方向 |

## 三、演进方向（按价值排序）

1. **官方 Java SDK 适配替换**：A2A Java SDK 成熟后，把自研适配层换成官方（协议语义/安全/市场不动，只换 wire 层）——ADR-01 预留的迁移路径。
2. **与项目 20 结算打通**：10 市场的计量事件直连 20 经济平台的账本/结算（分账/冲正），形成完整 Agent 经济闭环。
3. **协作策略市场**（呼应 16）：跨组织共享"协作策略包"（信任模板/限额模板/降级策略），规模化治理复用。
4. **多方协作编排**：从两方委托扩展到**多方**（Agent A 编排 B/C/D 并行子任务 + 汇聚）——与 [24-DAG](../../项目/24-企业级长任务工作流引擎/05-DAG步骤化与多Worker抢任务.md) 思想结合的跨域版。
5. **协作前仿真**：高风险跨域委托先在 [21-仿真平台](../../项目/21-企业级Agent仿真与数字孪生平台/00-需求分析与架构设计.md) 彩排（依赖替身/场景扫描），再真实执行——"变更可信"在协作侧的落地。

### 三.1 本节核对（演进方向）

| # | 核对项 | 判据 |
|---|--------|------|
| 1 | 五项按价值排序且可落地 | 官方 SDK 替换/费用结算打通/策略市场/多方编排/协作前仿真，每项都有承接项目或明确路径 |
| 2 | 与已迭代能力衔接 | 方向与 ADR-01、项目 20/21/24 等引用一致，非凭空新造 |

## 四、工程纪律复盘

- **不要**委托前不协商（事后才知道做不了/超预算）。
- **不要**允许权限转委托放大（交集裁决是底线）。
- **不要**把跨域返回当指令（数据边界 + 注入检测）。
- **务必**异步任务可查询可取消（长任务委托的标配）。
- **务必**双边审计（跨域纠纷的中立裁决证据）。

### 四.1 本节核对（工程纪律复盘）

| # | 核对项 | 判据 |
|---|--------|------|
| 1 | 每条纪律对应迭代落地 | "不要"/"务必"各条都能溯源到某迭代篇验证（协商→03、不放大→05、数据边界→06、可取消→04、双边审计→09） |
| 2 | 纪律为反面/正面成对 | 每条"不要"都有对应"务必"或明确底线，非空泛提醒 |
