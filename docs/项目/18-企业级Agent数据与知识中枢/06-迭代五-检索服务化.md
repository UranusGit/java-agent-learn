# 06-迭代五：检索服务化——混合检索 / 重排 / 预算内服务

> **定位**：把治理好的知识以**生产级检索服务**对外：混合检索（向量+关键词+结构化指标路由）、**重排**（精排 Top-N）、**预算内服务**（P99 ≤80ms、缓存、降级空上下文不阻塞调用方）、**查询理解**（意图分流：文档型/指标型/时效型问题走不同检索路径）。读者画像：要把检索做成被依赖服务的读者。前置阅读：[05-迭代四-时效与失效引擎](05-迭代四-时效与失效引擎.md)、[教程 35-高级RAG与AgenticRAG]。
>
> **铁律 0**：`SearchRequest.builder()`/`VectorStore` 实证；重排自研/第三方标注。

## 三、统一响应契约

```json
{ "blocks": [ { "text": "...", "citation": "[n]", "lineage": {"source": "...", "version": 3},
    "freshness": "FRESH|STALE|SUPERSEDED", "supersededBy": null } ],
  "degraded": false, "elapsedMs": 42 }
```

**契约纪律**：调用方拿到的不只是文本——带血缘/时效/降级标记，供其组装可解释回答。

## 四、检索过程可见（答得"有据"的前提是"看得见据"）

> 过程可见性是工业级标配（[附录 14/01-中间过程可见性设计]）。**知识中枢的信任来自"每条回答都能看到检索依据"**——命中哪些文档、各多少分、走了混合检索的哪条路径。

一~三节的检索链 emit 检索过程事件：`{q, 检索路径(向量/BM25/混合), 命中文档[{id, 来源, 分数, 剪裁片段}], 排序方式}`：

| 环节 | 事件 | 用户看到 |
|------|------|---------|
| 路由 | RetrieverChosen{path}` | "本次走混合检索" |
| 命中 | RetrievalHits{docs[{id,score}]}` | "命中 3 条：文档A(0.92) 文档B(0.85)…" |
| 过滤 | FilterApplied{tenant/版本, retained}` | "已按租户/版本过滤，剩 3 条" |
| 重排 | Reranked{order}` | "重排后 top：文档B" |

**四条纪律**：
1. **命中即可见**：所有命中文档 id+分数进事件，前端据此渲染"回答依据引用 [n]"（与回答内的 [n] 一一对应，可点开原文）。
2. **过滤透明**：多租户/版本过滤（04/07）后保留多少条发事件——用户知道"哪条被权限过滤了"（审计透明，防"看不到=没检索"）。
3. **剪裁片段**：命中片段只发裁剪版（≤200 字），全文走按需 REST——事件流不背整篇文档（呼应附录统领篇 preview 截断）。
4. **与血缘衔接**：命中事件带来源/版本，可直接进血缘追溯（04）——"这个答案依据来自哪个版本的哪份文档"。

**验证**（叠加本迭代验证包）：问一问题 → 事件流含 RetrieverChosen→RetrievalHits{≥1 命中带 id+score}→（重排走 Reranked）；租户B 问受权限问题 → FilterApplied{retained=N}；命中片段 ≤200 字。

## 五、验证包（手工测试与验证）
**前置条件**：三路分流+混合检索+重排+语义缓存+预算降级实现；金标 100 问。

**材料 A——分流集**：事实/语义/SQL 各 50 条；**材料 B——同题连问两次**。

**步骤与断言**：

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | 材料A 路由统计 | 正确率 ≥90% |
| 2 | 金标 100 问对比 | 混合+重排 Top1 比纯向量 +≥10% |
| 3 | 压测 200 并发 | P99 ≤80ms；材料B 第二次 ≈0ms（缓存） |
| 4 | 强制预算 20ms | 部分结果+degraded=true（不超时不空转） |

**失败排查**：②提升小→重排只接了向量路；③超 SLA→重排远程调用未并行；④空转→预算检查在循环外。
