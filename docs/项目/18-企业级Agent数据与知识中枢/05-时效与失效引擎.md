# 05-时效与失效引擎——TTL / 失效链 / 订阅通知

> **定位**：让知识"**会过期**"：每块知识带**时效契约**（TTL 窗口/事件驱动失效/永久），**失效链**（新事实入库→旧知识标记 supersededBy 而非删除——Agent 引用时知其被取代）、**订阅通知**（依赖某知识的下游 Agent 在失效时收到通知）。呼应 Google/PagerDuty 2026 共识"共享事实失效是 RAG 最大坑"。读者画像：被旧知识坑过的读者。前置阅读：[04-知识质量与血缘治理](04-知识质量与血缘治理.md)。

### 二.1 本节测试与验证（时效降权、失效链与订阅通知）

**前置条件**：TTL+事件失效+supersededBy+订阅推送实现。

**材料 A——TTL 块**（7 天）；**材料 B——事件**（产品下架）；**材料 C——新价文档**。

**步骤与断言**：

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | 材料A 到期 | 检索降权可测（排名下降或 stale 标记） |
| 2 | 材料B 发布 | 关联知识 ≤1min 标记失效 |
| 3 | 材料C 入库 | 旧价块 supersededBy 指新块；答案含取代声明 |
| 4 | 订阅验证 | 依赖该域的 Agent 全部收到失效事件 |

**失败排查**：①不降权→TTL 未进打分器；③无声明→答案组装未读 supersededBy；④漏推→订阅按块 id 非知识域。

## 三、全篇回归验证

回归断言（§二.1 本节验证通过后，最终整体验收）：

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | TTL 到期与事件失效同时发生 | 两种失效路径（定时+事件）均正确标记，无互扰 |
| 2 | 失效链多跳走查 | 旧→新→更新串成 supersededBy 链，Agent 引用时能追溯最新版 |

**失败排查**：双失效互扰→降权与标记并发时序；链条断裂→supersededBy 写入非原子，回看 §二.1。
