### 3.4 `SessionEvent.java`（事件类型：sealed 闭合联合）

```java
package com.group.agent.event;

import java.time.Instant;

/**
 * 会话事件的闭合联合（Java 21 sealed）。
 * 新增事件类型时，编译器强制你处理所有 switch 分支——对应 dsh 的 assertNever。
 */
public sealed interface SessionEvent permits
        UserMessage, AssistantChunk, AssistantMessage,
        ToolCall, ToolResult, TurnStart, TurnEnd {

    String sessionId();
    long seq();
    long time();

    // 三个 surface 事件（模型可见）需要记录来源事件 seq
    interface Surface {
        java.util.List<Long> sourceEventSeqs();
    }
}

record UserMessage(String sessionId, long seq, long time,
                   String content, Source source, List<Long> sourceEventSeqs)
        implements SessionEvent, SessionEvent.Surface {
    public enum Source { USER, INJECTED, GOAL }
}
record AssistantChunk(String sessionId, long seq, long time, String delta)
        implements SessionEvent {}
record AssistantMessage(String sessionId, long seq, long time,
                        String content, String model, List<Long> sourceEventSeqs)
        implements SessionEvent, SessionEvent.Surface {
    @Override public java.util.List<Long> sourceEventSeqs() { return sourceEventSeqs; }
}
record ToolCall(String sessionId, long seq, long time,
                String callId, String toolName, String arguments)
        implements SessionEvent {}
record ToolResult(String sessionId, long seq, long time,
                  String callId, String value, List<Long> sourceEventSeqs)
        implements SessionEvent, SessionEvent.Surface {}
record TurnStart(String sessionId, long seq, long time) implements SessionEvent {}
record TurnEnd(String sessionId, long seq, long time,
               String reason /* completed | interrupted | error */)
        implements SessionEvent {}
```

> 说明：`data JSONB` 存的是上面每个 record 的字段。实际落库时 `type` 列用 `type()` 名称，`data` 用完整 record 的 JSON。为手写简洁，落库时统一 `data = 全 record JSON`，读取时按 `type` 反序列化。

### 3.5 `SessionEventStore.java`（写侧唯一入口）

```java
package com.group.agent.event;

import com.fasterxml.jackson.databind.ObjectMapper;
import org.springframework.jdbc.core.simple.JdbcClient;
import org.springframework.stereotype.Repository;
import org.springframework.transaction.annotation.Transactional;

import java.util.List;

@Repository
public class SessionEventStore {

    private final JdbcClient jdbc;
    private final ObjectMapper mapper;

    public SessionEventStore(JdbcClient jdbc, ObjectMapper mapper) {
        this.jdbc = jdbc;
        this.mapper = mapper;
    }

    /** 全代码库唯一允许写事件的方法：seq 单调 + JSON 可序列化 + 事务。 */
    @Transactional
    public void append(SessionEvent e) {
        Long last = jdbc.sql("""
                SELECT seq FROM session_event
                WHERE session_id = :sid ORDER BY seq DESC LIMIT 1""")
                .param("sid", e.sessionId())
                .query(Long.class).optional().orElse(-1L);
        if (e.seq() != last + 1) {
            throw new IllegalStateException("seq 不连续: session=" + e.sessionId()
                    + " expected=" + (last + 1) + " got=" + e.seq());
        }
        try {
            jdbc.sql("""
                    INSERT INTO session_event(session_id, seq, type, time, data)
                    VALUES (:sid, :seq, :type, :time, CAST(:data AS jsonb))""")
                    .param("sid", e.sessionId())
                    .param("seq", e.seq())
                    .param("type", typeName(e))
                    .param("time", e.time())
                    .param("data", mapper.writeValueAsString(e))
                    .update();
        } catch (Exception ex) {
            throw new IllegalStateException("事件 JSON 序列化失败: " + typeName(e), ex);
        }
    }

    public List<SessionEvent> load(String sessionId) {
        return jdbc.sql("""
                SELECT type, data FROM session_event
                WHERE session_id = :sid ORDER BY seq ASC""")
                .param("sid", sessionId)
                .query((rs, i) -> deserialize(rs.getString("type"), rs.getString("data")))
                .list();
    }

    private String typeName(SessionEvent e) {
        return e.getClass().getSimpleName();
    }

    @SuppressWarnings("unchecked")
    private SessionEvent deserialize(String type, String json) {
        try {
            Class<?> clazz = Class.forName("com.group.agent.event." + type);
            return (SessionEvent) mapper.readValue(json, clazz);
        } catch (Exception e) {
            throw new IllegalStateException("事件反序列化失败: type=" + type, e);
        }
    }
}
```

### 3.6 `SessionProjector.java`（模型历史由日志折叠）

```java
package com.group.agent.event;

import org.springframework.ai.chat.messages.*;
import org.springframework.stereotype.Component;

import java.util.ArrayList;
import java.util.List;

@Component
public class SessionProjector {

    /** 从日志折叠出「模型看到的历史」——Model-visible means logged。 */
    public List<Message> deriveMessages(List<SessionEvent> events) {
        List<Message> history = new ArrayList<>();
        for (SessionEvent e : events) {
            switch (e) {
                case UserMessage um ->
                    history.add(new UserMessage(um.content()));
                case AssistantMessage am -> {
                    if (am.content() != null && !am.content().isBlank()) {
                        history.add(new AssistantMessage(am.content()));
                    }
                    // 空 content 跳过（仅承载 max-tokens usage）
                }
                case ToolResult tr -> {
                    // 2.0：工具结果以 ToolResponseMessage 顶层消息呈现（不再包在 UserMessage 里）
                    history.add(ToolResponseMessage.builder()
                            .responses(List.of(new ToolResponseMessage.ToolResponse(
                                    tr.callId(), "", tr.value())))
                            .build());
                }
                case AssistantChunk ac, ToolCall tc, TurnStart ts, TurnEnd te -> {
                    // 边界/分块事件不直接进模型历史
                }
            }
        }
        return history;
    }
}
```

### 3.7 `EventSourcingAdvisor.java`（请求前注入日志投影的历史）

```java
package com.group.agent.event;

import org.springframework.ai.chat.client.ChatClientRequest;
import org.springframework.ai.chat.client.ChatClientResponse;
import org.springframework.ai.chat.client.advisor.api.CallAdvisor;
import org.springframework.ai.chat.client.advisor.api.CallAdvisorChain;
import org.springframework.ai.chat.client.advisor.api.StreamAdvisor;
import org.springframework.ai.chat.client.advisor.api.StreamAdvisorChain;
import org.springframework.ai.chat.memory.ChatMemory;
import org.springframework.ai.chat.messages.Message;
import org.springframework.ai.chat.messages.MessageType;
import org.springframework.ai.chat.prompt.Prompt;
import org.springframework.core.annotation.Order;
import org.springframework.stereotype.Component;
import reactor.core.publisher.Flux;

import java.util.ArrayList;
import java.util.List;

/**
 * 会话 ID 从 ChatMemory.CONVERSATION_ID 取；用日志投影的历史替换框架记忆。
 * 同时实现 CallAdvisor + StreamAdvisor（真实 2.0 API，[附录 05-SpringAI2-API基准/00-Advisor与ChatMemory §1.1]）。
 */
@Component
@Order(1)
public class EventSourcingAdvisor implements CallAdvisor, StreamAdvisor {

    private final SessionEventStore eventStore;
    private final SessionProjector projector;

    public EventSourcingAdvisor(SessionEventStore eventStore, SessionProjector projector) {
        this.eventStore = eventStore;
        this.projector = projector;
    }

    @Override
    public String getName() {
        return "EventSourcingAdvisor";
    }

    @Override
    public ChatClientResponse adviseCall(ChatClientRequest request, CallAdvisorChain chain) {
        String sessionId = (String) request.context().get(ChatMemory.CONVERSATION_ID);
        List<Message> history = projector.deriveMessages(eventStore.load(sessionId));
        // ChatClientRequest.builder() 无参；复制改写用 request.mutate()（javap 实证）
        ChatClientRequest merged = request.mutate()
                .prompt(new Prompt(merge(history, request.prompt()),
                        request.prompt().getOptions()))
                .build();
        return chain.nextCall(merged);
    }

    @Override
    public Flux<ChatClientResponse> adviseStream(ChatClientRequest request, StreamAdvisorChain chain) {
        String sessionId = (String) request.context().get(ChatMemory.CONVERSATION_ID);
        List<Message> history = projector.deriveMessages(eventStore.load(sessionId));
        ChatClientRequest merged = request.mutate()
                .prompt(new Prompt(merge(history, request.prompt()),
                        request.prompt().getOptions()))
                .build();
        return chain.nextStream(merged);
    }

    /** 系统消息置顶 → 日志投影历史 → 当前请求消息（当前 user 消息已在历史中，不重复注入）。 */
    private List<Message> merge(List<Message> history, Prompt current) {
        List<Message> all = new ArrayList<>();
        for (Message m : current.getInstructions()) {
            if (m.getMessageType() == MessageType.SYSTEM) {
                all.add(m);
            }
        }
        all.addAll(history);
        for (Message m : current.getInstructions()) {
            if (m.getMessageType() != MessageType.SYSTEM) {
                all.add(m);
            }
        }
        return all;
    }
}
```

> ⚠️ 装配切换：本迭代把 v0 的框架记忆整体替换为事件溯源。`AgentConfig` 里要**删掉** `ChatMemory` Bean 与 `MessageChatMemoryAdvisor`（`defaultAdvisors(...)` 那行），历史由 `EventSourcingAdvisor`（`@Component` + `@Order(1)` 自动装配）从事件日志注入——否则框架记忆与日志投影同时启用，历史会双份进入模型。

### 3.8 `ChatService.java`（写事件 + 调模型）+ 改造 `ChatController`

```java
package com.group.agent.service;

import com.group.agent.event.*;
import org.springframework.ai.chat.client.ChatClient;
import org.springframework.ai.chat.memory.ChatMemory;
import org.springframework.stereotype.Service;

import java.util.concurrent.atomic.AtomicLong;

@Service
public class ChatService {

    private final ChatClient chatClient;
    private final SessionEventStore eventStore;
    private final AtomicLong seq = new AtomicLong(0);   // 演示用；生产按会话独立计数器

    public ChatService(ChatClient chatClient, SessionEventStore eventStore) {
        this.chatClient = chatClient;
        this.eventStore = eventStore;
    }

    public String chat(String sessionId, String message) {
        long t = System.currentTimeMillis();
        eventStore.append(new TurnStart(sessionId, seq.incrementAndGet(), t));
        eventStore.append(new UserMessage(sessionId, seq.incrementAndGet(), t,
                message, UserMessage.Source.USER, List.of()));
        // 当前 user 消息已作为事件落库，由 EventSourcingAdvisor 从日志注入历史——
        // 这里不再 .user(message)，否则历史里已含本条消息，会双份进入模型
        String answer = chatClient.prompt()
                .advisors(a -> a.param(ChatMemory.CONVERSATION_ID, sessionId))
                .call()
                .content();
        // 简版：把整段回答作为一个 assistant 消息落库（v6 再拆 chunk 级）
        eventStore.append(new AssistantMessage(sessionId, seq.incrementAndGet(),
                System.currentTimeMillis(), answer, "deepseek", List.of()));
        eventStore.append(new TurnEnd(sessionId, seq.incrementAndGet(),
                System.currentTimeMillis(), "completed"));
        return answer;
    }
}
```

## 4. ADR 演进决策

### ADR 013-04：会话模型用事件溯源，不用「消息表 + 平行存储」
- **Why**：v0 的 `ChatMemory` 只存最终消息；合规需要可审计可回放
- **取舍**：事件溯源以「写侧复杂 + 读侧 fold」换「可审计/可回放/可恢复/可派生全免费」
- **参考**：[附录 14-开源代码深度分析/00-deepseek-harness/12-Java工程师借鉴手册 §P1]

### ADR 013-05：事件类型用 sealed 闭合联合
- **Why**：契约面（事件类型）闭合，扩展面（事件 data）用 record——一收一放
- **参考**：[附录 14-开源代码深度分析/00-deepseek-harness/12-Java工程师借鉴手册 §K3]

### 4.1 本节核对（ADR 013-04 / 013-05）

- [ ] ADR 013-04 的取舍能复述：以写侧复杂 + 读侧 fold 换「可审计/可回放/可恢复/可派生」；对比"消息表 + 平行存储"的双份真相矛盾
- [ ] ADR 013-05 的 sealed 闭合联合能指明：新增事件类型时 switch 编译期被强制补分支（v8 演进期兑现回报）
