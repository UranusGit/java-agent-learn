### 3.1 租户上下文（从认证解析，不信任客户端头）

```java
package com.group.tenant;

import reactor.core.publisher.Mono;
import org.springframework.web.server.ServerWebExchange;
import org.springframework.web.server.WebFilter;
import org.springframework.web.server.WebFilterChain;

/**
 * 租户过滤器：租户从认证 Token 解析（网关注入 X-Tenant-Id），
 * 不信任客户端自带的租户头——防止越权（fail-closed）。
 */
public class TenantContextFilter implements WebFilter {

    public static final String TENANT_KEY = "tenantId";

    @Override
    public Mono<Void> filter(ServerWebExchange exchange, WebFilterChain chain) {
        // 从认证主体解析租户（真实实现从 JWT/认证服务取）
        String tenantId = resolveFromAuth(exchange);
        if (tenantId == null) {
            // 无租户上下文：拒绝（fail-closed）
            exchange.getResponse().setStatusCode(org.springframework.http.HttpStatus.FORBIDDEN);
            return exchange.getResponse().setComplete();
        }
        return chain.filter(exchange)
                .contextWrite(ctx -> ctx.put(TENANT_KEY, tenantId));
    }

    private String resolveFromAuth(ServerWebExchange exchange) {
        // 真实实现：从 Authorization header 的 JWT 声明里取 tenant
        return exchange.getRequest().getHeaders().getFirst("X-Tenant-Id");
    }
}
```

> ⚠️ 上面的 `resolveFromAuth` 直接读客户端头是**演示**——真实实现必须从**认证服务解析**（JWT claim / session），否则客户端可伪造租户。本文档的架构决策是「从认证解析」，代码里注明真实落点。

### 3.4 灰度发布：`PromptTemplateRegistry.java` + `GrayscaleRule.java`

```java
package com.group.control.gray;

import org.springframework.stereotype.Component;

import java.util.Map;
import java.util.concurrent.ConcurrentHashMap;

/**
 * Prompt 版本注册表：按「版本 + 灰度规则」解析。
 * 灰度规则存配置中心，改配置即时生效可回滚。
 */
@Component
public class PromptTemplateRegistry {

    private final Map<String, String> templates = new ConcurrentHashMap<>();  // version -> prompt
    private final GrayscaleRule rule = new GrayscaleRule();

    public String resolve(String tenantId, String userId) {
        return rule.inGray(userId) ? templates.getOrDefault("v2", templates.get("v1"))
                                   : templates.get("v1");
    }

    public void put(String version, String prompt) {
        templates.put(version, prompt);
    }

    /** 灰度规则：百分比/租户/用户（存配置中心）。 */
    public static class GrayscaleRule {
        private double percent = 0.10;   // 默认切 10%
        public boolean inGray(String userId) {
            return userId == null ? false
                    : (Math.abs(userId.hashCode()) % 100) < percent * 100;
        }
        public void setPercent(double p) { this.percent = p; }   // 改配置即时生效
    }
}
```

# A：租户隔离——用 acme 身份读 b07 会话（应被拒/404）
curl -H "X-Tenant-Id: acme" "http://localhost:8080/api/session/b07_xxx/events"
# B：工具权限分级——同 delete_order 按租户下发不同策略

# C：灰度——相同输入多次调用，统计 v1/v2 命中比例（GrayscaleRule percent=0.10）
for i in $(seq 1 100); do curl -H "X-Tenant-Id: acme" "http://localhost:8080/api/chat?sessionId=s$i" -H "Content-Type: text/plain" -d "订单 ORD-001 金额多少"; done

**步骤与断言**：

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | 材料 A（跨租户查询） | acme 读取 b07 会话 → 404/空集（租户数据隔离，验收 1）；反查同租户可读 |
| 2 | 租户配额隔离（§3.3） | 构造 acme 预算耗尽，不影响 b07 正常调用（验收 2，BudgetPolicy 按 tenantId 取） |
| 3 | 材料 B 工具权限分级 | 同 `delete_order` 按租户 `DENY`/`ALLOW`/`REQUIRES_APPROVAL` 生效（验收 3）——`HumanApprovalToolManager` 从 ControlPlane 拉策略而非硬编码 |
| 4 | 材料 C 灰度发布 | 100 次调用中约 10% 命中 Prompt v2（percent≈10%，验收 4）；改配置 percent=0 后全部走 v1（**即时回滚**） |
| 5 | 模型 A/B 路由 | 灰度组走模型 B、其余模型 A；`gen_ai.*` 指标带模型标签可对比 |
| 6 | 高可用（验收 5） | 停掉会话服务一个实例（K8s 缩容/杀进程），会话访问不中断；就绪探针把流量切走，3 分钟内恢复 |

**失败排查**：①租户隔离失效→`TenantContextFilter` 直接信任客户端头未从认证解析（越过场景只读 `X-Tenant-Id`）或未在 query/写路径带 tenantId 谓词；②权限分级不生效→`HumanApprovalToolManager` 还在硬编码 `dangerousTools` 未改成拉取 ControlPlane 策略；③灰度不切→`GrayscaleRule.percent` 配置未即时读取或 `inGray` 依据 userId 恒定（同一 userId 恒命中/恒不命中）；④HA 中断→就绪就绪探针配置错或服务无跨实例共享日志存储（事件库需共享 PostgreSQL）。
