## 3. 五段核心代码精讲

### 3.1 事件溯源会话日志（[02 §3] 完整代码）

**为什么这样写**：
- `sealed interface SessionEvent` —— 闭合联合：新增事件类型时编译器逼你处理所有 switch 分支（对应 dsh 的 `assertNever`）
- `SessionEventStore.append` 是**唯一写入口**，校验 `seq = last + 1` ——「日志可重建」的前提是 seq 连续
- `SessionProjector.deriveMessages` 从日志折叠模型历史 —— **「模型看到的」只来自日志**，这就是 `Model-visible means logged`
- `EventSourcingAdvisor` 同时实现 `CallAdvisor` + `StreamAdvisor` —— 真实 2.0 API（[附录 12-00]），流式也要注入历史

**手写要点**：先写事件 record，再写 Store（唯一入口），再写 Projector，再写 Advisor。写完验证：`GET /api/session/{id}/events` 能看到完整事件链。

### 3.2 能力缝（[03 §3.2] 完整代码）

**为什么这样写**：
- `OrderQueryPort` 接口 + `@ConditionalOnProperty` 两个 Provider —— 切后端 = 改配置 `tool.order-query.backend`
- `@Tool` 消费者只依赖端口 —— **模型面 schema 永远不变**（对应 dsh「Provider 注册能力而非工具」）

**手写要点**：先接口，再 local/http 两个实现，再改 `ToolOrderQuery`。验证：把 backend 从 local 改 http，工具 schema 零改动。

### 3.3 工具拦截（[03 §3.3] + [05 §3.3] 完整代码）

**为什么这样写**：
- **拦截点是 `ToolCallingManager` 装饰器，不是 Advisor** —— Advisor 环绕整个 ChatClient 调用，看不到「工具执行」这个时点；`ToolCallingManager` 正好插在「模型决定调工具」与「工具实际执行」之间（[教程 22 §正确落点]）
- 装饰器在 delegate 前后分别记录 `tool/call`、`tool/result` —— 审计可看到「模型想要什么 + 实际执行了什么」
- v4 把审批守卫放进同一装饰器 —— 命中危险工具必须 `AllowedOnce` 审批

**手写要点**：装饰器实现 `ToolCallingManager`，构造注入 delegate；`extractToolCalls` 从 prompt 的 `ToolCallMessage` 里取工具调用。验证：危险工具无审批被拒。

### 3.4 崩溃闭合（[04 §3.3] 完整代码）

**为什么这样写**：
- `closeOrphanTurns` 从后往前扫描「最后一个 TurnStart > TurnEnd」= 未闭合 turn；若「ToolCall > ToolResult」= 孤儿工具调用
- **合成闭合而非截断** —— 单 turn 可能巨大，截断会丢审计；补一个 `interrupted` 结束标记保住已发生事实
- 修复也要落库（`store.appendBatch`）—— 恢复本身是可重放的

**手写要点**：先写 `SessionWriteBuffer`（批量 + 显式 flush），再写 `RecoveryService`，再写冷读阶梯。验证：工具执行中 kill -9，恢复后无悬挂 turn。

### 3.5 审批（[05 §3.1-3.3] 完整代码）

**为什么这样写**：
- `ApprovalOutcome` sealed —— `AllowedOnce/Rejected/Cancelled/Unavailable`，无 answerer/超时 → `Unavailable`（fail-closed）
- 审计对 `approval/asked` + `approval/decided` 成对落日志 —— 崩溃 tail 时可检测「asked 无 decided」的不完整审批
- **`allowed-once`** —— 批准只放行本次，不建立持久授权

**手写要点**：先 `ApprovalOutcome`，再 `ApprovalService`（挂起 + 超时 + 审计对），再 `HumanApprovalToolManager`。验证：delete_order 无审批被拒，审批后只放行一次。
