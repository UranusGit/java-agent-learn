## 1. 七个关键设计复盘

### 1.1 为什么隔离是"schema 隔离 + 事务级 RLS"双层（本项目最痛的教训）

v2 第一版实现"新建连接 `SET app.current_tenant` 后归还"——连接级（session 级）设置在连接池下对后续借出的业务连接毫无作用，且污染池中连接导致**反向串号**，越权压测全泄露。修正为两条：

1. **schema-per-tenant**：每租户一个独立 schema（`t_<id>`），业务表物理隔离——删档=`DROP SCHEMA`、导出=只读该 schema、迁移=只迁该 schema。
2. **事务级 RLS**：事务开头 `set_config('search_path', 't_<id>', true)` + `set_config('app.current_tenant', '<id>', true)`（第三参 true = SET LOCAL 语义，随事务结束失效，连接归还池无残留），配合 `FORCE ROW LEVEL SECURITY`——即使 search_path 被注入或跨 schema 全限定查询，RLS 也兜底为 0 行。

**泛化教训**：任何"连接级状态"在连接池环境下都是错的——状态要么事务级（随事务生死），要么显式传参。识别这类错误的方法只有一个：**越权测试矩阵进 CI（ADR-207）**，因为 code review 看不出"SET 了但没用"。

### 1.2 为什么配额是"预扣+修正"而不是实时扣

实时逐 token 扣减的 Redis QPS 与对话流量同阶（每秒数千次），且流式中途断连时扣多少算不清。预扣（请求开始按估计量原子扣）+ 修正（完成回补差额）把 Redis 压力降为每请求 2 次，且天然覆盖断连场景（预扣已收，实际按已有 usage 修正）。**代价**：短暂超限窗口（预扣估计偏低时）——配额治理允许的误差换架构简洁，商业上完全可接受。

### 1.3 为什么账单不能从指标出（ADR-214）

Prometheus 指标的三宗罪：可重置（重启丢基数）、可降采样（聚合丢明细）、无审计语义（谁都不能对指标数发誓）。计费数据的要求恰好相反。所以**事件流水（append-only，DB 触发器拒绝 UPDATE/DELETE）是账单唯一数据源，指标只管运维**——两类数据的不同命运在设计期就要分轨。

### 1.4 为什么灰度原子单位是租户（ADR-217）

SaaS 的体验一致性单元是"企业"不是"用户"：同一公司两个员工看到的 Agent 一个聪明一个笨，工单必然产生且无法解释。对比：To C 产品灰度按用户分桶完全正常。**灰度粒度=产品的信任一致性单元**，这是产品形态决定的，没有技术对错。

### 1.5 为什么 TTFT 进 SLI（ADR-220）

对话产品的"可用"包含"及时"。如果 SLI 只有成功率，8 秒首字延迟的系统也能 100% 达标——但客户会流失。SLI 的选择暴露的是产品理解：批处理产品用吞吐、交易产品用成功率与一致性、对话产品必须含延迟。**SLO 设计是产品知识，不是运维知识**。

### 1.6 为什么 DR 不跨境（ADR-230）

驻留承诺与容灾冗余的矛盾是真实的架构张力。答案不是"技术上做不到"，而是**风险排序**：违约的合同罚金+监管处罚+信任崩塌是确定性损失；区域级故障是概率事件且 RTO 内可部分恢复。所以法域内找备区，找不到就降级方案+书面披露——架构师的诚实就是把不可兼得的东西明码标价给业务方选。

### 1.7 为什么计费三副本对账（ADR-215）

单点计量必然有误差（断连、重试、并发窗口）。三副本（原始事件/配额流水/供应商账单）互相对账，把"账单对不对"从"我们系统说是多少"变成"三个独立来源一致"——对不上的**冻结不出账、人工裁定后留痕**。错账的信任代价远高于晚出账。

## 2. 最容易写错的六处

| # | 位置 | 错误 | 后果 | 正确 |
|---|------|------|------|------|
| 1 | RLS 绑定 | 连接级 `SET app.current_tenant` | 隔离形同虚设 + 反向串号 | 事务级 `set_config(..., true)`（v2 教训） |
| 2 | schema 绑定 | 只绑 `search_path` 忘了绑 `current_tenant` | schema 指向对但 RLS 策略无值 → 0 行（或漏绑 schema → 解析到 public） | 两个 `set_config` 一起绑，事务级 |
| 3 | 配额 | GET+判断+DECRBY 分离 | 并发超卖 | 单条 Lua 原子 |
| 4 | 越权响应 | 返回 403 | 暴露资源存在性 | 404 |
| 5 | 限流 | 只限 Token 总量 | 瞬时并发打穿共享服务 | 总量+并发双层 |
| 6 | DR 切换 | 自动切换优先 | 误切换脑裂（双主） | 人工决策+fencing 优先 |
