## 二、关键 ADR 详解

### ADR 03-00：双重身份架构

- **上下文**：网关既要向 Agent 暴露统一工具入口，又要连接真实工具（各类 MCP Server）。
- **备选**：①纯代理（透传 MCP，无自有语义）②双重身份（对内 Server/对外 Client）③只做 Server（工具全部内联）。
- **决策**：②——"不用 MCP 连不上任何工具"成为结构性事实（协议收口），同时网关可在中间层做准入/审计/授权。
- **取舍**：③最简单但工具无法服务化；①无法插入治理。②复杂度最高但治理能力完整。
- **可回滚**：双面各自独立，任一面可替换实现。

### ADR 03-01：传输协议选 Streamable HTTP

- **上下文**：自建 Server 的传输选型决定客户端接入方式；旧 HTTP+SSE 双端点已被 2025-03+ 规范废弃。
- **备选**：①HTTP+SSE（旧稿大量示例使用）②Streamable HTTP 单端点（POST+mixin 流式响应，现行标准）。
- **决策**：②——远程统一 Streamable HTTP；本地 stdio Server 保留（见 00 篇 §10 正文）。
- **取舍**：①是技术债且违背现行标准；②需下游 Server 支持（不支持的暂时经适配层桥接）。
- **可回滚**：连接配置按 Server 粒度切换，任一侧可单独回退。

### ADR 03-07：`@Tool` 暴露必须显式 `ToolCallbackProvider` Bean

- **上下文**：`@Tool` 注解方法需装配为 MCP 工具；Spring AI 2.0 的装配入口是 `ToolCallbackProvider` Bean。
- **备选**：①只写 `@Component + @Tool` 期待自动注册（**不生效**——附录 05-01 §3 审计教训）②手写 `ToolCallback` 逐个注册（繁琐且易漏）③`MethodToolCallbackProvider` 显式 Bean。
- **决策**：③——`McpServerConfig` 为每组工具显式声明 `MethodToolCallbackProvider.builder().toolObjects(...)` Bean。
- **取舍**：①工具静默缺失、难以定位；②与 SDK 强耦合；③是官方装配路径，启动时自动扫描暴露。
- **可回滚**：删除/新增 Bean 即可增减工具，不影响传输层。

### ADR 03-13：审查通过版描述下发（🔷 规划中）

- **上下文**：LLM 依据工具 description 决策调用；描述被恶意/无意篡改会直接操纵 Agent 行为。
- **备选**：①透传实时自述 ②冻结准入时描述。
- **决策**：②——准入时指纹冻结，Agent 看到的永远是审查版；描述漂移即告警（防 Tool Poisoning）。
- **取舍**：①总有最新信息但不可信；②牺牲实时性换安全。版本更新走重新准入。
- **可回滚**：指纹表可重建（重放准入记录）。
- **现状**：正文未落地——本条目与 03-12（准入签名）为规划中的安全增强，落地时先补准入流程再冻结描述指纹。

### ADR 03-18：联邦目录最终一致

- **上下文**：目录跨集群同步，强一致代价高。
- **备选**：①强一致（同步锁/共识）②最终一致（30s 增量）。
- **决策**：②——工具登记是低频操作，30s 不可见窗口可接受；冲突走消解规则（PUBLISHED 优先/高版本胜/指纹一致双活/否则人工）。
- **取舍**：①对低频写是过度设计。
- **可回滚**：同步可暂停（各集群自治运行）。

### ADR 03-19：联邦 token 最小授权

- **上下文**：跨集群转发需要凭证，但长期宽权限 token 一旦泄露危害大。
- **备选**：①集群间长期服务账号 ②短 TTL 最小授权委托。
- **决策**：②——30s TTL、单工具、单次调用、禁止再委托。
- **取舍**：①实现简单但违背最小权限；②多了签发开销但爆炸半径极小。
- **可回滚**：签发开关可关（退化为无跨区能力，不影响本地）。
