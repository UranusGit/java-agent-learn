# 11-流式净额结算——微额高频的分钟级轧差

> **定位**：微额高频（单笔 $0.001 级、每秒万笔）场景下，逐笔清结算在成本与时效上均不可行。本篇落地**分钟级轧差**：窗口内双边/多边净额合并、净额与逐笔和**数学一致**的硬校验、轧差窗口失败的重入与对账。读者画像：要回答"万笔每秒怎么结算"的读者。前置阅读：[04-支付轨道与幂等](04-支付轨道与幂等.md)、[07-开放与生态](07-开放与生态.md)。
>
> **铁律 0**：轧差引擎自研「概念代码」。

## 一、四问

| 问 | 答 |
|----|----|
| **新增了什么需求** | ① 轧差窗口：按分钟聚合，同主体对间相互抵销只结净额（A 应付 B ¥100、B 应付 A ¥80 → 一笔 ¥20）② 多边净额：生态多方环形债务压缩（图算法求最小转账集）③ 一致性硬校验：∑净额流 == ∑逐笔流（任一窗口可证）④ 窗口重入：轧差输出提交失败 → 幂等重入（窗口号+批次号幂等键）⑤ 明细留存：轧差不删逐笔账——净额是**结算形态**不是记账形态 |
| **影响了哪些模块** | `ledger-svc`（04）之上新增净额引擎（窗口聚合器+多边图压缩）；持牌机构接口改批量指令 |
| **架构如何演进** | 逐笔结算 → 净额结算（记账粒度不变、结算粒度聚合） |
| **上一版痛点** | 生态高频交易逐笔过持牌机构：手续费吃掉微额利润、T+1 到账跟不上体验（07 §六） |

**本迭代验收**：① 净额压缩比 ≥90%（万笔窗口 → ≤千笔净额指令）② 一致性校验：任意窗口 ∑净额 == ∑逐笔（含多边环）③ 窗口提交失败重入 0 重复 ④ 逐笔明细仍可追（结算凭证 → 窗口号 → 明细集哈希）。

## 二、轧差窗口流水线

```mermaid
flowchart LR
    EV["账本事件流(04)<br/>万笔/分钟"] --> W["窗口聚合器<br/>[t, t+1min)"]
    W --> B["双边抵销<br/>A↔B 只留净额"]
    B --> M["多边压缩<br/>环形债务→最小转账集"]
    M --> CK{"硬校验<br/>∑净额==∑逐笔?"}
    CK -->|"过"| OUT["净额指令批<br/>(窗口号+批次号)"]
    CK -->|"不过"| HALT["冻结窗口+告警<br/>(人工介入)"]
    OUT --> PS["持牌机构批量结算"]
    PS -->|"回执"| REC["窗口关闭<br/>凭证:净额+明细哈希"]
    style CK fill:#fff9c4
    style HALT fill:#ffcdd2
```

**为什么校验不过必须冻结而不是修补**：净额错 = 结算层与账本层分裂，任何"先结后调"都会让后续所有窗口失去可信基础——宁可延迟一分钟，不可带病结算。

### 二.1 本节测试与验证（窗口聚合 + 任一窗口一致性硬校验）

**前置条件**：窗口聚合器（[t, t+1min)）+ 一致性硬校验（∑净额 == ∑逐笔，任一窗口可证）实现。

**材料 A——环形债务**：A→B 100、B→C 70、C→A 50、A→C 30（9 笔）。

**材料 B——校验破坏**：人为篡改一个窗口的某笔净额。

**步骤与断言**：

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | 材料 A 窗口聚合+轧差 | 输出 2 笔净额；∀窗口 ∑净额 == ∑逐笔（含多边环） |
| 2 | 注入 1 万笔/窗口 | 净额指令压缩比 ≥90%（指令 ≤1000 笔） |
| 3 | 材料 B 破坏校验 | 校验不过 → 冻结该窗口 + 告警，不发出净额指令（不修补直发） |
| 4 | 窗口关闭凭证 | 凭证含净额 + 明细集哈希，可回溯明细 |

**失败排查**：①校验过→只对了笔数没对金额（∀窗口必对金额和）；②冻结点漏→净额指令在校验前已被直接发出。

## 三、多边净额（图压缩）

```mermaid

    before -. 压缩 .-> after
```

- 算法「概念」：每个主体净头寸 = ∑应收 − ∑应付；只对净头寸非零者生成指令（正头寸收款、负头寸付款）——转账笔数从 O(边数) 降到 O(非零主体数)。
- **参与方许可**：多边净额改变对手方风险结构（原来欠 C 的钱变成欠净额池）——参与协议必须明示，未签约方退化为双边轧差。

### 三.1 本节核对（多边图压缩机制）

- [ ] 能说出净头寸算法（∑应收 − ∑应付、只对净头寸非零者生成指令），并解释"笔数从 O(边数) 降到 O(非零主体数)"
- [ ] 理解参与方许可纪律：未签约方退化为双边轧差，多边净额不强制改变对手方风险结构

## 四、失败重入与对账

| 故障 | 策略 |
|------|------|
| 窗口聚合失败 | 窗口顺延 1 分钟（不丢事件，事件在账本） |
| 净额指令批提交失败 | 幂等键（窗口号+批次号）重发，机构侧去重 |
| 部分净额结算成功 | 按笔隔离：成功笔关闭、失败笔转下窗重结（不整批回滚） |
| 对账 | 每日：∑窗口净额流 == ∑逐笔事件流 == 机构对账单三方平 |

### 四.1 本节测试与验证（失败重入幂等 + 三方对账）

**前置条件**：净额指令批幂等键（窗口号+批次号）+ 部分按笔隔离 + 每日对账作业实现。

**步骤与断言**：

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | 净额指令批提交失败后重发 3 次 | 机构侧仅 1 批生效（窗口号+批次号幂等去重，0 重复） |
| 2 | 部分净额结算成功（部分笔失败） | 成功笔关闭、失败笔转下窗重结，不整批回滚 |
| 3 | 窗口聚合失败 | 窗口顺延 1 分钟，事件仍在账本不丢失 |
| 4 | 每日对账 | 账本逐笔 / 窗口净额 / 机构对账单 三方平 |

**失败排查**：①重复入账→幂等键未含批次号（同一窗口不同批次被当一批）；②转下窗丢账→失败笔未带原窗口上下文。
