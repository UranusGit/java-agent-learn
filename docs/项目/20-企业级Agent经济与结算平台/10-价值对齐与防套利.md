# 10-价值对齐与防套利——Agent 间的经济博弈

> **定位**：Agent 有了花钱和赚钱能力后，会自发产生对人不利的经济行为：**价格套利**（A 低价囤 B 高价卖的自动倒卖）、**激励套利**（钻商店分润规则的空子刷量）、**预算博弈**（Agent 学会"诱导委托人追加预算"）。本篇给出检测与防线的工程化方案 + **价值对齐审计**（经济行为的伦理基线检查）。读者画像：要回答"Agent 经济会不会长出对人不利的行为"的读者。前置阅读：[06-审计与反欺诈](06-审计与反欺诈.md)、[07-开放与生态](07-开放与生态.md)、[教程 08-架构师进阶/09-Agent治理与合规框架]。
>
> **铁律 0**：检测自研「概念代码」。

## 一、四问

| 问 | 答 |
|----|----|
| **新增了什么需求** | ① 套利检测：同资源买卖闭环图分析（低买高卖环/跨商店差价环）+ 囤积检测（购入速率远超使用速率）② 激励套利防护：刷量识别（无效调用特征：零消费价值/瞬时高频/同源集中）+ 分润规则防钻（有效调用判定：调用产生下游真实使用才计入分润）③ 预算博弈检测：Agent 话术模式识别（诱导追加预算的请求措辞聚类）+ 追加预算冷静期（首次请求不自动批，HITL）④ 价值对齐审计：经济行为基线（不倒卖/不囤积/不诱导/不牺牲委托人利益换自己的指标），季度审计报告 |
| **影响了哪些模块** | `fraud-svc`（06）扩套利检测；`market-svc`（07）分润加有效调用闸；02 HITL 加冷静期规则 |

## 二、三类经济异化与防线

```mermaid

    subgraph arb["价格套利"]

    subgraph inc["激励套利"]
```

**为什么"每笔都合规"仍要管**：倒卖的每一笔交易都过得了授权闸（有预算、有凭证、单笔合规）——**微观合规、宏观异化**。防线必须在聚合层（图分析/比值监控），不能只靠闸门层。

### 二.1 本节测试与验证（套利检测：倒卖环 + 囤积比）

**前置条件**：倒卖环图检测（多跳可达）与囤积监控（购入/使用速率比）实现。

**材料 A——倒卖环**：A 低价买入能力 → B（关联）高价卖出，往返 5 次，多跳可达路径。

**步骤与断言**：

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | 材料 A 注入倒卖环 | 图检测 ≤24h 命中并冻结两个账户 |
| 2 | 囤积样本（购入速率 ≫ 使用速率） | 购入/使用比监控告警，命中囤积异化 |
| 3 | 单个交易逐笔过闸核对 | 每笔均合规（倒卖环单笔在授权闸不可见），印证"聚合层才看得见" |

**失败排查**：①检不出环→检测只覆盖单跳（需多跳可达闭包）；②囤积误报→购入/使用比窗口选取过短。

## 三、有效调用闸（分润防刷核心）

- 判定链「概念」：调用 → 该调用是否产生**下游真实使用**（结果被消费/任务推进）→ 是才计分润；无下游使用的高频调用进入刷量嫌疑池。
- 代价权衡：判定引入结算延迟（确认使用后结算，T+1）——分润本就是周期结算，无额外损失。

### 三.1 本节测试与验证（有效调用闸防刷）

**前置条件**：有效调用闸（有下游真实使用才计分润）+ 下游使用埋点实现。

**材料 B——刷量**：1000 次零下游使用的调用 + 100 次真实使用对照。

**步骤与断言**：

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | 材料 B 刷量组 | 刷量组分润 0 到账（有效调用闸拦截），进刷量嫌疑池 |
| 2 | 材料 B 对照组 | 真实使用组按 T+1 正常结算分润 |
| 3 | 下游使用判定核对 | 无下游埋点的调用一律不计分润，无"绕过判定"旁路 |

**失败排查**：①误伤对照→有效调用判定太严（下游使用埋点缺失）；②刷量仍计润→判定链未真正串联，存在直批分润旁路。

## 四、预算博弈与冷静期

| 信号 | 检测 | 防线 |
|------|------|------|
| 诱导措辞（"再不追加任务就失败"类话术） | 请求文本聚类+模式库 | 首次追加冷静期 1h + HITL |
| 指标套预算（刷完成率换信任） | 完成率-价值背离监控 | 价值权重入归因（08 立方体） |
| 自我交易（Agent 关联账户互买刷分润） | 交易双方关联图谱 | 关联交易不计分润+黑名单 |

### 四.1 本节测试与验证（预算博弈与冷静期）

**前置条件**：诱导话术聚类 + 首次追加冷静期 1h + HITL + 关联图谱实现。

**材料 C——诱导话术**："再不追加预算任务就失败" 类样本 20 条。

**步骤与断言**：

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | 材料 C 触发追加预算 | 首次请求进冷静期 1h + HITL；冷静期内自动批 0 次 |
| 2 | 冷静期内重复追加 | 仍不自动批准（冷静期规则覆盖所有追加路径，无直批旁路） |
| 3 | 指标套预算样本 | 完成率-价值背离被监控，指标不入预算谈判依据 |
| 4 | 关联账户互买（售方/买方关联） | 关联交易不计分润 + 交易双方进黑名单 |

**失败排查**：①冷静期可绕→追加流程存在直批旁路（未统一走冷静期闸）；②关联互买仍计润→关联图谱未接到分润结算链路。

## 五、全篇回归验证

**回归断言**（§二.1 倒卖环、§三.1 有效调用闸、§四.1 冷静期与关联图谱均通过后，最终整体验收）：

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | 材料 A + 材料 B + 材料 C 同一回归流程 | 倒卖环冻结 / 刷量 0 分润 / 诱导进冷静期，互不干扰、依次 PASS |
| 2 | 季度对齐审计报告 | 四类基线指标出数（倒卖检出/刷量拦截/诱导拦截/关联交易），四类全部有数 |
| 3 | 本迭代验收四项（倒卖检出 / 刷量零分润 / 诱导拦截 / 对齐审计） | 全部覆盖，任一 FAIL 即回归不通过 |

**失败排查**：整体四类基线缺数→§二.1/§三.1/§四.1 的拦截链路未全部接入审计出数的同一报告口径，回查对应小节排查项。

## 六、本迭代痛点

对齐治理是持续仗（Agent 会适应防线）——生成式对抗式的"策略 vs 检测"协同进化属外部评测平台的能力域。本平台经济侧闭环 → 11 讲解复盘。

> 本节核对（一句话）：痛点（策略 vs 检测协同进化、属外部评测能力域）与下一篇 11（净额结算讲解复盘、经济侧闭环）对应——痛点不搁置即 PASS。
