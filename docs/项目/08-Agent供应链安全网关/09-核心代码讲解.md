## 1. 完整代码：`SecurityPipeline`（把 v1-v8 串联起来）

各迭代的检测组件都是独立类；真正让它们按顺序工作的是一个编排器。下面的 `SecurityPipeline` 是**热路径上的安全编排**——从收到 Agent 的工具调用到返回结果，每个安全能力在正确时点执行。所有组件来自前 8 篇，可照抄编译。

```java
package com.group.secgw.pipeline;

import com.group.secgw.admission.ToolRegistration.Rating;
import com.group.secgw.api.ToolCallContext;
import com.group.secgw.api.ToolResponse;
import com.group.secgw.audit.AuditEvent;
import com.group.secgw.audit.AuditSink;
import com.group.secgw.behavior.BehaviorAnomalyDetector;
import com.group.secgw.behavior.DataExfilDetector;
import com.group.secgw.behavior.ToolBehaviorBaseline;
import com.group.secgw.ha.DegradeAwarePipeline;
import com.group.secgw.inject.ContentSanitizer;
import com.group.secgw.inject.InjectionAwareGate;
import com.group.secgw.incident.IncidentResponseService;
import com.group.secgw.incident.SecurityIncident;
import com.group.secgw.policy.Decision;
import com.group.secgw.policy.ZeroTrustPdp;
import com.group.secgw.registry.EndpointRegistry;
import com.group.secgw.registry.ToolEndpoint;
import org.springframework.stereotype.Component;
import reactor.core.publisher.Mono;

import java.time.Instant;
import java.util.List;
import java.util.concurrent.ConcurrentHashMap;
import java.util.concurrent.ConcurrentMap;

/**
 * 安全编排器（收官篇）——热路径上的全链编排。
 * 顺序：准入在目录构建时已做（v2）→ 策略（v6）→ 行为（v4）→ 注入（v5）→ 执行 → 数据流（v4）→ 审计（v1）。
 * 每个检测点都先问 DegradePolicy（v8）当前防线什么状态。
 */
@Component
public class SecurityPipeline {

    private final ZeroTrustPdp pdp;
    private final BehaviorAnomalyDetector anomalyDetector;
    private final DataExfilDetector exfilDetector;
    private final DegradeAwarePipeline degradeAwarePipeline;
    private final InjectionAwareGate injectionGate;
    private final ContentSanitizer sanitizer;
    private final IncidentResponseService incidentService;
    private final AuditSink auditSink;
    private final EndpointRegistry endpointRegistry;

    // v5 会话级隔离状态：sessionId → 是否出现过隔离内容（不是 ThreadLocal）
    private final ConcurrentMap<String, Boolean> sessionQuarantine = new ConcurrentHashMap<>();

    public SecurityPipeline(ZeroTrustPdp pdp,
                            BehaviorAnomalyDetector anomalyDetector,
                            DataExfilDetector exfilDetector,
                            DegradeAwarePipeline degradeAwarePipeline,
                            InjectionAwareGate injectionGate,
                            ContentSanitizer sanitizer,
                            IncidentResponseService incidentService,
                            AuditSink auditSink,
                            EndpointRegistry endpointRegistry) {
        this.pdp = pdp;
        this.anomalyDetector = anomalyDetector;
        this.exfilDetector = exfilDetector;
        this.degradeAwarePipeline = degradeAwarePipeline;
        this.injectionGate = injectionGate;
        this.sanitizer = sanitizer;
        this.incidentService = incidentService;
        this.auditSink = auditSink;
        this.endpointRegistry = endpointRegistry;
    }

    /** 工具调用入口：策略 → 行为 → 注入 → 执行 → 数据流 → 审计。 */
    public Mono<ToolResponse> execute(ToolCallContext ctx, Rating rating, String toolInput) {
        // ① 零信任策略（v6）：deny-by-default
        Decision decision = pdp.evaluate(ctx);
        if (decision instanceof Decision.Deny d) {
            return deny(ctx, "policy:" + d.reason(), AuditEvent.Outcome.DENIED);
        }
        boolean needConfirm = decision instanceof Decision.Confirm;

        // ② 行为规则层（v4）：异常即 L2/L3 响应
        ToolBehaviorBaseline base = ToolBehaviorBaseline.empty(ctx.toolId(), ctx.agent().agentId());
        BehaviorAnomalyDetector.Anomaly anomaly = anomalyDetector.checkRules(ctx, base);
        if (anomaly.flagged()) {
            // report 的第 8 参是 List<String>，把违规明细映射为字符串列表
            incidentService.report("behavior", SecurityIncident.Severity.HIGH, 0.8,
                    ctx.toolId(), ctx.agent().agentId(), ctx.sessionId(), ctx.traceId(),
                    anomaly.violations().stream().map(v -> v.detail()).toList());
        }

        // ③ 注入检测（v5）：内容进上下文前过检（走 v8 降级感知管道）
        return degradeAwarePipeline.checkInjection(ctx, rating, toolInput)
                .flatMap(inj -> {
                    if (inj.blocked()) {
                        sessionQuarantine.put(ctx.sessionId(), true);
                        if (injectionGate.check(ctx, Boolean.TRUE.equals(
                                sessionQuarantine.get(ctx.sessionId())))
                                == InjectionAwareGate.ToolAuthorization.DENY) {
                            return deny(ctx, "injection + high-risk tool", AuditEvent.Outcome.DENIED);
                        }
                        return Mono.just(ToolResponse.ok(sanitizer.quarantine(toolInput), 0));
                    }
                    return executeAndAudit(ctx, rating, toolInput, needConfirm);
                });
    }

    /** 执行 + 数据流向检测 + 审计。 */
    private Mono<ToolResponse> executeAndAudit(ToolCallContext ctx, Rating rating,
                                               String toolInput, boolean needConfirm) {
        ToolEndpoint ep = endpointRegistry.lookup(ctx.toolId()).orElseThrow();
        // 工具执行面（v3 的 GatewayProxyTool 内部转发；此处示意为直接调用）
        long start = System.currentTimeMillis();
        ToolResponse resp = ToolResponse.ok("tool-result:" + ctx.toolId(), System.currentTimeMillis() - start);

        // ④ 数据流向组合判定（v4）：敏感结果 × 出网能力
        if (exfilDetector.suspicious(ctx, resp)) {
            incidentService.report("data-exfil", SecurityIncident.Severity.CRITICAL, 0.9,
                    ctx.toolId(), ctx.agent().agentId(), ctx.sessionId(), ctx.traceId(),
                    List.of("sensitive+egress"));
        }

        // ⑤ 审计（v1）：COMFIRM_REQUIRED 由 v6 决策驱动
        AuditEvent.Outcome outcome = needConfirm
                ? AuditEvent.Outcome.CONFIRM_REQUIRED
                : AuditEvent.Outcome.COMPLETED;
        // AuditEvents 是 v1 的静态工具类，静态方法调用（含全部 import）
        return auditSink.emit(com.group.secgw.audit.AuditEvents.completed(ctx, resp, resp.durationMs()))
                .thenReturn(resp);
    }

    private Mono<ToolResponse> deny(ToolCallContext ctx, String reason, AuditEvent.Outcome outcome) {
        return auditSink.emit(com.group.secgw.audit.AuditEvents.flagged(ctx, outcome,
                        "{\"reason\":\"" + reason + "\"}", null))
                .thenReturn(ToolResponse.fail(reason, 0));
    }
}
```

> ⚠ 说明：`com.group.secgw.audit.AuditEvents` 是 v1 的**静态工具类**（私有构造器），上面用全限定名静态调用。核心不变式：**编排顺序固定，每个组件职责单一，检测点先问降级状态**。

### 1.1 本节测试与验证（SecurityPipeline 全链编排）

**前置条件**：v1–v8 全部组件（PDP/行为/注入/降级/事件/审计/登记表）已按各篇抄写并编译通过。

**材料——编排链路单测（JUnit5 节选，各依赖用 Mockito stub）**：

```java
// AF1 策略拒绝短路
when(pdp.evaluate(any())).thenReturn(Decision.deny("no policy"));
StepVerifier.create(pipeline.execute(ctxOf("fs.read", Rating.A), Rating.A, "ok"))
    .assertNext(r -> { assertFalse(r.success()); assertTrue(r.error().contains("policy:")); })
    .verifyComplete();
// AF2 注入命中 → 隔离返回 + 会话打标
when(pdp.evaluate(any())).thenReturn(Decision.allow());
when(degradePipeline.checkInjection(any(), any(), any()))
    .thenReturn(Mono.just(InjectionResult.blocked(List.of("rule"))));
StepVerifier.create(pipeline.execute(ctxOf("weather.query", Rating.B), Rating.B, "恶意内容"))
    .assertNext(r -> assertEquals(ContentSanitizer.QUARANTINE_MARKER, r.body()))
    .verifyComplete();
// AF3 正常全链 → COMPLETED 审计
when(pdp.evaluate(any())).thenReturn(Decision.allow());
when(degradePipeline.checkInjection(any(), any(), any()))
    .thenReturn(Mono.just(InjectionResult.pass()));
StepVerifier.create(pipeline.execute(ctxOf("weather.query", Rating.B), Rating.B, "北京"))
    .assertNext(r -> assertTrue(r.success()))
    .verifyComplete();
// AF4 Confirm 决策 → CONFIRM_REQUIRED 审计（stub auditSink 捕获 outcome）
when(pdp.evaluate(any())).thenReturn(Decision.confirm("max-rows"));
```

**步骤与断言**：

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | 单测 AF1 | Deny 短路：不进入行为/注入/执行；审计落 DENIED（`flagged` 分支） |
| 2 | 单测 AF2 | 注入命中返回隔离占位符；`sessionQuarantine` 对该 sessionId 置 true |
| 3 | AF2 后同一 sessionId 调高危工具 | `InjectionAwareGate` 判 REQUIRE_CONFIRMATION/DENY（联动生效） |
| 4 | 单测 AF3 | 正常链 COMPLETED；`exfilDetector.suspicious` 为 false 时不产生事件 |
| 5 | 单测 AF4 | Confirm 决策时审计 outcome=CONFIRM_REQUIRED（needConfirm 传播正确） |
| 6 | AF1–AF4 全量检查 `sessionQuarantine` | 无 ThreadLocal、按 sessionId 隔离（v5 状态传播） |

**失败排查**：①AF1 不短路→Deny 判定放到了 flatMap 内部；②AF2 占位符错→`sanitizer.quarantine` 传的是 toolInput 而非工具返回体（按 §1 源码语义核对）；③CONFIRM_REQUIRED 丢失→`needConfirm` 未传入 `executeAndAudit`。

## 2. 五个关键设计复盘

### 2.1 为什么收口必须是物理的（ADR-301）

"要求所有流量走网关"是流程约束，网络层 egress 白名单是物理约束。区别在攻防含义：流程约束对善意违规有效（忘了改配置的团队），对恶意绕过无效（故意私接的攻击者——正是本项目的威胁模型）。**安全边界必须建立在攻击者无法绕过的层**：网络层 > 平台层 > 代码约定 > 文档约定。

### 2.2 为什么工具描述用"审查通过版"而非实时版（ADR-308）

MCP 工具的自描述是**动态数据**——先过审再投毒是时间线攻击。网关双面 MCP 的设计里，Agent 看到的目录永远来自登记库（审查版），真实工具的描述漂移被指纹机制冻结。**任何进入 LLM 上下文的文本都要问一句：它的信任链是什么？**——这是间接注入防御的总纲。

### 2.3 为什么检测要分层（ADR-311）

三层的本质是**频率×成本的匹配**：规则层（每秒千次、零成本）抓结构性异常；分类器（每秒千次、毫秒本地推理）抓语义特征；LLM 判定（每天几十次、一次调用成本）只复核可疑流量。若倒过来（每次调用全 LLM 检测），网关延迟与成本会逼业务绕过它——**安全机制自身的成本超阈值时，会被使用者合法地绕过**，这是安全架构的第一公理。

### 2.4 为什么隔离而非丢弃（ADR-315）

注入检测有误杀率。丢弃误杀的内容 → 业务静默失败（用户困惑、排查无门）；隔离+标注 → Agent 能告知用户"部分内容被安全策略隔离"，误杀可见可申诉。**安全机制的透明度决定它能在组织里活多久**——黑盒式拦截最终会被业务压力拆掉。

### 2.5 为什么分级 fail-open/close（ADR-304 落地）

"安全组件挂了业务全停"与"安全组件挂了形同虚设"是两个极端，答案按风险分维：

| 维度 | 策略 | 逻辑 |
|------|------|------|
| 检测层（概率性防御） | A/B 级 fail-open + C 级 fail-close | 检测降级的窗口风险 < 全停的确定损失（对受信工具） |
| 策略层（授权边界） | 一律 fail-close | 授权是边界不是概率 |
| 审计层（合规底线） | 一律 fail-close | 不可追溯 = 合规事故 |

**"安全"不是一个整体，按功能分维后每维有自己的可用性策略**——这是安全架构师与安全产品配置员的分水岭。

## 3. 最容易写错的五处

| # | 位置 | 错误 | 后果 | 正确 |

## 7. 总结

**第一轮（v1-v8）收官。** 检验标准：能独立复述 §2 五个决策，特别是 2.3（安全成本公理）与 2.5（安全分维的可用性策略）——它们是"安全架构师"区别于"安全配置员"的核心判断力。把 `SecurityPipeline`（§1）在本地跑通，再逐步关掉每个检测组件验证降级矩阵，即完成第一轮八个迭代的代码闭环。

但收官不是终点——三个月后，一场集团审计和一次证书过期事故把项目拉回演进轨道：网关自己的依赖树从未盘点、服务之间还在共用一年期的手工证书、模型/数据集/Prompt 模板这三类 AI 原料完全没有准入。**第二轮深化（v9-v11）由此启动。**
