# 02-迭代一：金标资产化——版本 / 防污染 / 域标签

> **定位**：把裸金标变成**资产**：版本化（演进留痕）、**污染防护**（金标不得进微调/优化集——防"背答案"假高分）、域标签（受影响域定位——联动知识血缘）、审批流（金标变更走评审）。呼应 AWS"金标是护城河"——护城河要有资产管理。读者画像：要长期经营评测的读者。前置阅读：[01-最小Demo](01-最小Demo.md)。
>
> **铁律 0**：资产层自研。

## 二、资产模型

```mermaid
flowchart TB
    subgraph gs["golden-store"]
        V["版本化<br/>(vN 快照/diff/回滚)"]
        P["污染防护<br/>(指纹注册:微调管道拒收)"]
        D["域标签<br/>(场景×知识域)"]
        A["审批流<br/>(业务+评测双签)"]
    end
    SUB["金标提交/变更"] --> A --> V
    V --> P
    V --> D
    FT["微调/优化数据集"] -.->|"指纹比对拒收"| P
    REG["变更回归"] -.->|"按域定位子集"| D
    style P fill:#ffcdd2
    style A fill:#fff9c4
```

```sql
CREATE TABLE golden_case (
    id          text NOT NULL,
    set_version int  NOT NULL,
    question    text NOT NULL,
    expected    jsonb NOT NULL,        -- 期望要点/参考答案
    domain_tags text[] NOT NULL,        -- 域标签（场景×知识域）
    fingerprint text NOT NULL,          -- 污染防护指纹（问题+要点 hash）
    status      text DEFAULT 'ACTIVE',
    approved_by text[],
    PRIMARY KEY (id, set_version)
);
```

**防污染机制**：微调/优化数据准备管道在入模前对每样本算指纹 → 与金标指纹库比对 → 命中即拒（金标泄露=评测虚高）。**测试集与优化集物理分离**是铁律。

## 三、验证包（手工测试与验证）
**前置条件**：金标库（版本化+双签审批+指纹）+管道侧拒收钩子实现。

**材料 A——变更单**：修改 g01 的 expected（小改），走审批。

**材料 B——污染注入**：把金标问题文本混入一份微调训练集提交。

**步骤与断言**：

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | 材料A 提交 | 双签流触发；发布后版本 vN+1，diff 可视（改动行高亮） |
| 2 | 材料B 过数据管道 | 指纹命中 → 拒收+事件告警（0 混入） |
| 3 | 修改"退款知识域"知识条目 | 定位到带 refund 标签的金标子集（域联动） |
| 4 | v3 有问题回滚 v2 | 回归流水线切换到 v2 版本集 |

**失败排查**：②未拒→指纹算法只哈希整段（改写后不命中），应加 n-gram/嵌入双重指纹；③定位不到→金标缺域标签字段；④回滚后仍用 v3→回归任务读的是引用非版本号快照。
