# 05-优化归因与定向修复

> **定位**：把"差例→修复项"从人工升级为**归因驱动的定向修复**。核心：**① 差例归因到层（知识缺/Prompt 弱/规则误/模型能力边界）② 分层修复动作（补知识/改 Prompt/调规则/换模型建议）③ 修复项生成（人审后注册）**。呼应 [教程 08-架构师进阶/07-数据飞轮与持续改进](../../教程/08-架构师进阶/07-数据飞轮与持续改进.md)、[30-归因](../../项目/30-企业级Agent可解释与透明平台/03-证据归因引擎.md)。前置阅读：[04-评估汇流与回归门禁](04-评估汇流与回归门禁.md)。
>
> **铁律 0**：归因/修复生成为 LLM 辅助 + 人审（实证 ChatClient）；规则类修复确定性。

## 二、归因分型与分层修复

```java
// 概念代码：差例归因 → 定向修复
public CauseType diagnose(DiffCase c) {
    if (evidenceMissing(c))  return CauseType.KB_GAP;      // 检索无相关证据 → 知识缺失
    if (evidenceOkButWrong(c)) return CauseType.PROMPT_FLAW; // 证据在但答错 → 提示缺陷
    if (ruleBlockedCorrectly(c)) return CauseType.RULE_HIT; // 规则误伤
    return CauseType.MODEL_LIMIT;                          // 其余 → 模型能力边界
}

public FixSuggestion fix(CauseType t, DiffCase c) {
    return switch (t) {
        case KB_GAP      -> FixSuggestion.of("补充知识", kbDraftFor(c));    // 文档草稿
        case PROMPT_FLAW -> FixSuggestion.of("Prompt补丁", promptPatchFor(c));
        case RULE_HIT    -> FixSuggestion.of("规则调整", ruleAmendFor(c));  // 确定性
        case MODEL_LIMIT -> FixSuggestion.of("模型升级评估", escalate(c));  // 走教程44决策
    };  // 全部人审后注册为 ImprovementItem(带血缘+目标差例集)
}
```

**纪律**：**归因对了修复才有效**——知识缺失改 Prompt 是白费；模型边界硬补规则会误伤。归因→分层→定向是优化环的效率根源。

### 二.1 本节测试与验证（归因分型与分层修复）

**前置条件**：`Diagnoser`（证据检查）+ `FixSuggester`（分类型建议）+ 人审注册逻辑可编译运行；用例可与真实 ChatClient 联测（RULE_HIT 为确定性规则）。

**步骤与断言**：

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | 提交"检索无相关证据"的差例 | `diagnose` 返回 `KB_GAP`，`fix` 出"补充知识"的文档草稿 |
| 2 | 提交"证据在但答错"的差例 | `PROMPT_FLAW` → 出 Prompt 补丁 |
| 3 | 提交"规则误伤"的差例 | `RULE_HIT` → 确定性规则调整（ruleAmendFor） |
| 4 | 抽样核对归因准确率 | 归因到层与人工判定一致率 ≥80%（本迭代验收①） |
| 5 | 修复项经人审 | 注册为 ImprovementItem，带目标差例集进入 04 门禁 |

**失败排查**：①检索有证据仍判 KB_GAP→`evidenceMissing` 证据判定阈值/来源有误；②RULE_HIT 落到非确定性→`ruleAmendFor` 未走确定性规则；③修复项不进门禁→注册后未带目标差例集或未接 04 gate。
