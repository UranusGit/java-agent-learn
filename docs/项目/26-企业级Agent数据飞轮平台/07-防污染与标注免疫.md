## 二、三层免疫

```java
// 概念代码：免疫管线
public IngestResult immune(RawItem raw) {
    // ①来源分级: 权重与配额(匿名低权重+限额,外部最低)
    double w = trustWeight(raw.source());
    if (quotaExceeded(raw.source())) return IngestResult.rateLimited();

    // ②交叉验证: LLM判 vs 人审抽样 不一致率监控
    if (annotator.disagreementRate(raw.source()) > DISAGREE_MAX)
        alert(AnnotationSuspicious.of(raw.source()));

    // ③异常冻结: 该来源差评率 z-score 突变 → 冻结待查
    if (stats.zscoreOfNegative(raw.source()) > FREEZE_Z) {
        sources.freeze(raw.source());                     // 冻结期内不进优化环
        return IngestResult.frozenPendingReview();
    }
    return IngestResult.accepted(w);                      // 带权重入湖
}
```

### 二.1 本节测试与验证（三层免疫）

**前置条件**：免疫管线（来源权重/交叉验证/异常冻结）+ 统计检测 + 配额校验可编译运行。

**步骤与断言**：

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | 匿名来源差评洪水 | `trustWeight` 权重低且 `quotaExceeded` 触发 → 被 `rateLimited`/低权重吸收，同量恶意差评影响 ≤ 高信源 1/10 |
| 2 | 构造标注不一致率超过 DISAGREE_MAX | 触发 `alert(AnnotationSuspicious)` |
| 3 | 构造某来源差评率 z-score 超过 FREEZE_Z | `sources.freeze` 生效 → `frozenPendingReview`，冻结期不进优化环 |
| 4 | 恶意差评攻击整批 | 优化方向不被带偏（污染检出率 ≥95%） |

**失败排查**：①恶意差评仍带偏→权重未在产品进优化环的判分上生效；②不冻结→`stats.zscoreOfNegative` 窗口/阈值或 `FREEZE_Z` 判断有误；③冻结数据仍进优化→优化环未拦截 frozen 状态。

## 三、为什么免疫在采集而不在评估

污染数据一旦入湖进评估，**事后清洗成本远高于入口拦截**——免疫必须在摄入管线最前端（纵深防御的入口层，呼应 [08-供应链准入](../../项目/08-Agent供应链安全网关/02-工具准入与签名校验.md) 的准入思想）。

### 三.1 本节核对（免疫前置采集）

| # | 核对项 | 判据 |
|---|--------|------|
| 1 | 前置理由 | 能说清"污染入湖后清洗成本高，免疫放采集入口而非评估"的成本论证 |
| 2 | 纵深防御引借 | 明确"免疫前置采集"借鉴 08 供应链准入的准入思想 |
