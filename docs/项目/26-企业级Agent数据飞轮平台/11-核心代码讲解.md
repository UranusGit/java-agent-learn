## 二、飞轮主循环（串联各迭代）

```java
// 概念代码：飞轮驱动器
@Component
public class FlywheelDriver {
    public Flux<ReleaseEvent> drive(String bizLine) {
        return collect.probeAndSnoop(bizLine)                   // 02+10 采集(含主动探针)
            .map(immune::screen)                                  // 07 免疫(带权重)
            .doOnNext(lake::saveWithLineage)                      // 03 血缘入湖
            .transform(diagnoser::prioritizeAndSuggest)           // 05 归因+优先级
            .concatMap(item -> gate.gate(item)                    // 04 双卡门禁
                .filter(GateVerdict::passed)
                .flatMap(v -> release.rollout(item)));            // 06 灰度阶梯
    }   // 09 健康度全程打点
}
```

### 二.1 本节核对（飞轮主循环代码）

| # | 核对项 | 判据 |
|---|--------|------|
| 1 | 管线串联 | `drive` 里 collect→immune→lake(血缘)→diagnoser→gate→rollout 六个环节与 02/07/03/05/04/06 各迭代代码一一对应 |
| 2 | 反应式链路 | 全流程 Flux/Mono 无 block，符合 WebFlux 铁律 |

## 四、最容易踩的三个坑

1. **无血缘的飞轮** → 差例无法归因到层，改进盲打。**解法**：血缘强制（03）。
2. **免疫缺位** → 恶意反馈带偏优化。**解法**：入口免疫（07）。
3. **无灰度守门的改进** → 上线=赌博。**解法**：门禁+阶梯强制（04/06）。

### 四.1 本节核对（三个坑）

| # | 核对项 | 判据 |
|---|--------|------|
| 1 | 坑→解法映射 | 无血缘→强制血缘(03)/免疫缺位→入口免疫(07)/无守门→门禁+阶梯(04/06)，三条都能对应到迭代 |
| 2 | 能预防 | 能说清每个坑"为何出现、归因到哪一层" |
