> **定位**：让**飞轮本身**被度量——转速/转化率/回归率/周期时长四指标 + 断点告警。呼应 [教程 53 §5](../../教程/96-企业级数据飞轮闭环.md)、[教程 31-全链路可观测性](../../教程/31-全链路可观测性.md)。前置阅读：[08-多业务联邦飞轮](08-多业务联邦飞轮.md)。
>

## 一、四问

| 问 | 答 |
|----|----|
| **新增了什么需求** | ①四健康指标（转速/转化率/回归率/周期时长）②按业务线/环节切片 ③断点告警（某环停转/周期恶化） |
| **影响了哪些模块** | 各环 → 打点；新增 FlywheelHealthJob |
| **架构如何演进** | 飞轮从"改进工具"演进为"被治理的对象" |
| **上一版痛点** | 飞轮悄悄停转（差例堆积无人修/评估排队）没人知道 |

**本迭代验收**：①四指标按线可视化 ②转化率/周期对照 00 验收①②（≥30% / P50≤7天）③断点（某环节滞留超阈）告警。

### 一.1 本节核对（四问与迭代验收）

| # | 核对项 | 判据 |
|---|--------|------|
| 1 | 四问口径齐全 | 新增需求/影响模块/架构演进/上一版痛点四行均有且自洽（改进工具→被治理的对象） |
| 2 | 三项验收可判定 | 四指标可视化/对照验收阈值/断点告警——均可观察 |

## 二、四健康指标

```java
// 概念代码：健康指标计算
public FlywheelHealth health(String bizLine) {
    return FlywheelHealth.of(
        throughput(bizLine),      // 转速: 周/月上线改进项数
        conversion(bizLine),      // 转化率: 差例→修复上线 比例
        regressionRate(bizLine),  // 回归率: 改进引入新问题比例(灰度拦下也算)
        cycleDays(bizLine));      // 周期: 差例发现→修复上线 P50 天数
}
// 断点检测: 各环滞留量(待标注/待评估/待修复/灰度中)超阈 → 告警"飞轮在X环节堵塞"
```

### 二.1 本节测试与验证（四健康指标）

**前置条件**：指标采集（实证 Observation/Micrometer 打点）+ `FlywheelHealthJob` + 断点规则可编译运行；各环节滞留数据可注入。

**步骤与断言**：

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | 选某业务线计算 health | 转速/转化率/回归率/周期四指标均返回可读数值 |
| 2 | 构造某一环滞留量超阈（如待修复堆积） | 断点检测告警"飞轮在优化环堵塞" |
| 3 | 对照 00 验收①② | 转化率对照 ≥30%、周期 P50 ≤7 天 口径一致可评估 |
| 4 | 回归率统计 | 改进引入新问题的比例计算含灰度拦截样本 |

**失败排查**：①指标恒空→`FlywheelHealthJob` 未按业务线切片或打点缺失；②断点不告警→滞留量统计口径/阈值未覆盖该环节；③转化率无法对阈值→指标与 00 验收定义不一致。

## 三、指标解读（比数字更重要的是解读）

| 症状 | 诊断 |
|------|------|
| 转速高+回归率高 | 改得快但糙——门禁太松 |
| 转速低+采集量大 | 优化环堵了（归因/修复产能不足） |
| 周期长在"待人审" | 人审瓶颈——扩审或降人审依赖 |
| 转化率趋零 | 飞轮实质停转——优先治理 |

### 三.1 本节核对（指标解读）

| # | 核对项 | 判据 |
|---|--------|------|
| 1 | 四症状→诊断对应 | 转速高+回归率高/转速低+采集量大/周期长待人审/转化率趋零四条映射，能不看表复述 |
| 2 | 指标非孤立 | 强调"比数字更重要的是解读"，能结合指标组合定位飞轮断点 |
