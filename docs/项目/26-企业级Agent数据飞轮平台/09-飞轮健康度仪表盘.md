> **定位**：让**飞轮本身**被度量——转速/转化率/回归率/周期时长四指标 + 断点告警。呼应 [教程 53 §5](../../教程/53-企业级数据飞轮闭环.md)、[22-可观测](../../教程/22-全链路可观测性.md)。前置阅读：[08-多业务联邦飞轮](08-多业务联邦飞轮.md)。

## 一、四问

| 问 | 答 |
|----|----|
| **新增了什么需求** | ①四健康指标（转速/转化率/回归率/周期时长）②按业务线/环节切片 ③断点告警（某环停转/周期恶化） |
| **影响了哪些模块** | 各环 → 打点；新增 FlywheelHealthJob |
| **架构如何演进** | 飞轮从"改进工具"演进为"被治理的对象" |
| **上一版痛点** | 飞轮悄悄停转（差例堆积无人修/评估排队）没人知道 |

**本迭代验收**：①四指标按线可视化 ②转化率/周期对照 00 验收①②（≥30% / P50≤7天）③断点（某环节滞留超阈）告警。

## 二、四健康指标

```java
// 概念代码：健康指标计算
public FlywheelHealth health(String bizLine) {
    return FlywheelHealth.of(
        throughput(bizLine),      // 转速: 周/月上线改进项数
        conversion(bizLine),      // 转化率: 差例→修复上线 比例
        regressionRate(bizLine),  // 回归率: 改进引入新问题比例(灰度拦下也算)
        cycleDays(bizLine));      // 周期: 差例发现→修复上线 P50 天数
}
// 断点检测: 各环滞留量(待标注/待评估/待修复/灰度中)超阈 → 告警"飞轮在X环节堵塞"
```

## 三、指标解读（比数字更重要的是解读）

| 症状 | 诊断 |
|------|------|
| 转速高+回归率高 | 改得快但糙——门禁太松 |
| 转速低+采集量大 | 优化环堵了（归因/修复产能不足） |
| 周期长在"待人审" | 人审瓶颈——扩审或降人审依赖 |
| 转化率趋零 | 飞轮实质停转——优先治理 |

| 测试 | 期望 |
