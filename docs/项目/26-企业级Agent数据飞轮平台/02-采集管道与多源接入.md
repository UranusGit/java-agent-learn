## 二、四源接入与清洗

```java
// 概念代码：多源采集管道
public Mono<String> ingest(FlywheelSource src, RawItem raw) {
    return Mono.fromCallable(() -> {
        var cleaned = cleaner.clean(raw);                    // 去噪/脱敏(呼应25合规)
        if (dedup.isDuplicate(cleaned)) return dupId(cleaned); // 语义去重(实证 embed 相似)
        var labeled = annotator.label(cleaned);              // LLM 初判+置信
        if (labeled.confidence() < HUMAN_REVIEW_MIN)
            reviewQueue.offer(labeled);                      // 低置信进人审
        return lake.save(labeled.withTrust(trustOf(src)));   // 来源分级: AUTH>ANON>EXTERNAL
    });
}
```

### 二.1 本节测试与验证（四源接入管道）

**前置条件**：ingest 管道（clean/去重/annotate/来源 trust）可编译运行；`EmbeddingModel`（实证）已接入做语义相似判定。

**步骤与断言**：

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | 分别提交 FEEDBACK/DIFF_AUTO/REDTEAM/SIM 四源各一条 | 四源统一入湖，`RawItem` 带 source 与 trust（AUTH>ANON>EXTERNAL 权重） |
| 2 | 提交一条与已有差例语义近似的原始项 | 被 `dedup.isDuplicate` 命中，返回已有 id（合并计数），不入新数 |
| 3 | 构造低置信标注（< HUMAN_REVIEW_MIN） | 进 `reviewQueue` 人审队列，不直接入湖 |
| 4 | 对比匿名 vs 认证来源 | `trustOf` 权重不同；`quotaExceeded` 对超限源 429/限流 |

**失败排查**：①去重不命中→`EmbeddingModel` 语义相似阈值过严/未接入嵌入；②低置信未进人审→`confidence` 与 `HUMAN_REVIEW_MIN` 比较方向错；③来源权重全同→`trustOf` 未按 source 分级。

## 三、差例自动检出（最重要的源）

手工反馈永远稀疏——**自动差例检出**是飞轮主油路：

| 检出信号 | 来源 |
|---------|------|
| 用户明确负反馈（踩/重问/弃用） | 前端埋点 |
| 拒答/循环/超时 | 运行时事件（Observation） |
| 复核驳回（HITL） | 复核工作台（30-10） |
| 在线哨兵低分 | 19-04 式哨兵 |

### 三.1 本节核对（差例自动检出）

| # | 核对项 | 判据 |
|---|--------|------|
| 1 | 四类检出信号 | 用户负反馈/拒答超时/复核驳回/哨兵低分共四源，每条都能指出数据来源落点 |
| 2 | 自动是主油路 | 能说清"自动检出 > 手工反馈"的原因（手工稀疏、自动是飞轮主油路） |
