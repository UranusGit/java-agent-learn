## 二、双卡回归 + 门禁

```java
// 概念代码：改进项评估门禁
public GateVerdict gate(ImprovementItem item) {
    // 卡1: 目标差例集(本改进要修复的) 修复率
    double fixRate = evalOffline(item.patch(), item.targetCases());
    // 卡2: 金标全集(不能引入回归) 通过率
    double goldenPass = evalOffline(item.patch(), golden.all(item.bizLine()));
    boolean pass = fixRate >= FIX_MIN && goldenPass >= baselineGolden - REGRESS_TOL;
    return pass ? GateVerdict.PASSED : GateVerdict.blocked(fixRate, goldenPass);
}
```

### 二.1 本节测试与验证（双卡门禁）

**前置条件**：EvalPipeline（离线新旧对比）+ GateKeeper 可编译运行；目标差例集与金标全集就绪。

**步骤与断言**：

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | 改进项：修复差例率达到 FIX_MIN 且金标通过率未低于 baselineGolden-REGRESS_TOL | `gate` 返回 `PASSED`，放行进下一环 |
| 2 | 构造金标回归（goldenPass < 基线-容差） | 返回 `BLOCKED`，携带 fixRate/goldenPass，不进灰度 |
| 3 | 跳过 gate 直接调用下游（灰度/发布） | 流程强制拦截——无门禁 PASSED 无法进灰度 |
| 4 | 在线哨兵采样低分样本 | 自动回流采集环成为新差例候选（带血缘进 03/05） |

**失败排查**：①金标回归仍 PASSED→`goldenPass` 与 `baselineGolden - REGRESS_TOL` 比较方向或容差设置错；②可跳过门禁→灰度入口未强依赖 GateVerdict；③哨兵不回流→回流通道未接采集环。
