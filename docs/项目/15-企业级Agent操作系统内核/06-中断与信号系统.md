| 信号 | 默认处置 | 可捕获 | 语义 |
|------|---------|--------|------|
| SIG_APPROVE | 唤醒 BLOCKED 进程 | - | 审批结果（approved/rejected）注入进程上下文 |

### 三.1 本节测试与验证（HITL 挂起闭环）

**前置条件**：高危工具判定→WOULD_BLOCK 挂起登记（快照已落 nextStep）→SIG_APPROVE 唤醒实现。

**材料 A——高危工具剧本**：进程调用 `refund_transfer` 高危工具触发审批挂起。

**步骤与断言**：

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | 材料A 触发审批 | 返回 WOULD_BLOCK 挂起；线程/配额零占用（并发池占用数不变） |
| 2 | 审批端 approve=true | SIG_APPROVE 唤醒 → 进程续跑（带审批结果重发 syscall） |
| 3 | 审批端 approve=false | 进程走拒绝分支（exit 正常带原因，非挂死） |

**失败排查**：①挂起仍占线程/配额→用阻塞实现挂起（应持久化挂起态并释放执行资源）；③驳回不结束→拒绝分支缺 exit 语义（SIG_APPROVE payload 未注入拒绝结果）。

## 四、CANCEL vs KILL

```java
package com.example.kernel.interrupt;

/** 信号处置——CANCEL 优雅、KILL 强制（都不撕毁已计费的模型调用）。 */
public class SignalHandler {

    public void deliver(long pid, Signal signal, String payload) {
        AgentProcess p = kernel.processTable().get(pid);
        switch (signal) {
            case SIG_CANCEL -> p.requestGracefulExit(2);   // 检查点+退出
            case SIG_KILL -> p.terminateNow();             // 状态终结（在途调用自然完成，结果丢弃）
            case SIG_APPROVE -> p.pending(new Signal(Signal.SIG_APPROVE, payload));
            default -> p.pending(signal);
        }
    }
    public enum Signal { SIG_APPROVE, SIG_CANCEL, SIG_YIELD, SIG_KILL, SIG_TIMER }
}
```

### 四.1 本节测试与验证（CANCEL/KILL 分级语义）

**前置条件**：`SignalHandler.deliver` 按 §四 实现分级处置（CANCEL→请求优雅退出；KILL→立即终结）。

**材料 B——取消剧本**：进程执行到第 N 步时投递 SIG_CANCEL；**材料 C——SIG_KILL 剧本**。

**步骤与断言**：

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | 材料B | 进程 exit(2) + 快照落盘；可从第 N 步恢复（SIG_CANCEL 优雅退出） |
| 2 | 材料C | 进程立即 EXITED；在途调用自然完成后 /proc 无僵尸（SIG_KILL 不撕已计费调用） |

**失败排查**：①KILL 后仍有僵尸→子任务句柄未回收（收尾钩子缺失）；②CANCEL 后不可恢复→CANCEL 没先落检查点快照（应 requestGracefulExit 先快照再退出）。
