## 二、完整旅程（Prompt v12 从变更单到回流）

```mermaid
sequenceDiagram
    participant DEV as 变更人
    participant CG as change-gate(07)
    participant TW as 孪生(03)

    participant CH as 混沌/容量(05/06)
    participant APR as 审批人
    participant PROD as 生产(10)
    DEV->>CG: 变更单 v12(声明:影响退款场景)
    CG->>SC: 定向切片:退款×高客单+相邻场景
    SC->>TW: 孪生回放(R7 回放集+替身)
    TW-->>CG: diff:85 SAME/12 BETTER/3 WORSE
    CG->>CH: 降级彩排(六类)+容量(5×)
    CH-->>CG: 彩排通过/拐点5×(配额)
    CG->>APR: 审批(报告内嵌)
    APR->>APR: 点开 1 例 WORSE→可接受(话术变化)
    APR-->>CG: 批准(灰度5%起步)
    CG-->>DEV: 放行
    PROD-->>CG: 48h 实测 vs 预测偏差 4%
    Note over CG,PROD: 失真绿牌:孪生可信 ✅
```

**一句话**：变更先声明影响面、孪生里定向验差例、彩排故障、压出拐点、报告内嵌审批、上线后偏差回流养孪生健康度——生产只见过验证过的变更。

## 三、关键设计复盘

| # | 设计 | 为什么 |
|---|------|--------|
| 1 | 变量唯一原则 | 孪生里只有被测 Agent 是真的，依赖全是替身（03） |
| 2 | 保语义脱敏+一致性映射 | 脱敏不变形，回放结论才可信（02） |
| 3 | 两档 LLM 替身 | 编排变更零成本、效果变更真模型（03） |
| 4 | 影响面声明+相邻扩展 | 变更事故头号来源是影响面漏报（04） |
| 5 | 降级断言而非"没崩" | 真实要求是行为正确不是进程活着（05） |
| 6 | 档 B 压测+配额数学 | 压测零 LLM 成本，配额不用压用算（06） |
| 7 | 豁免必须贵 | 双签+公示，闸门才是闸门（07） |
| 8 | 合成三类型+人审闸 | 新 Agent 冷启动不等真实攻击者当测试员（08） |
| 9 | 推演输出存活参数 | 极端仿真的交付物是参数建议不是事故报告（09） |
| 10 | 孪生健康度三指标 | 仿真结论的前提"孪生=生产"需要被看守（10） |
