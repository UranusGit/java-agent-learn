## 二、数据包六要素

```java
// 概念代码：披露数据包
public record DisclosurePack(
        DecisionRecord decision,            // ①决策: 时间/对象/结论/风险级
        List<Evidence> evidences,           // ②证据: 检索片段/工具输出(快照)
        List<ValidatedAttribution> attribs, // ③归因(已校验): 结论←证据
        List<ConfidenceView> confidences,   // ④置信(分来源+校准状态)
        ExplanationTimeline timeline,       // ⑤时间线(取证级)
        ApprovalTrail approvals,            // ⑥HITL审批/披露审批留痕
        String hashChainRoot) {}            // 防篡改锚
```

### 二.1 本节测试与验证（数据包六要素 + 防篡改）

**前置条件**：02-07 产物（时间线/证据集/已校验归因/置信/反事实）可用；hash 链实现已装配（承 [20-hash链审计](../../项目/20-企业级Agent经济与结算平台/06-审计与反欺诈.md)）；`ApprovalTrail` 已记录审批留痕。

**材料——代码内含的旋钮**：`DisclosurePack` record 六字段 `decision/evidences/attribs/confidences/timeline/approvals/hashChainRoot`；`hashChainRoot` 为防篡改锚。

**步骤与断言**：

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | 对一笔完成披露审批的执行调一键导出 | 返回完整数据包，六要素（决策/证据/归因/置信/时间线/审批留痕）全部非空、完整率 100% |
| 2 | 生成 hash 链 | `hashChainRoot` 非空且随各要素内容确定计算 |
| 3 | 篡改数据包任一记录（如改时间线/证据）后重算 | hash 校验失败（防篡改生效） |
| 4 | 数据包同时提供机器可读 JSON 与人可读摘要 | 双格式均可生成，内容一致 |

**失败排查**：①导出行缺失某要素→`DisclosurePack` 组装时该项来源为空（对应迭代产物未生成）；②篡改后 hash 仍通过→hash 链仅锚单一字段而非全要素，或篡改的是未入链元数据；③审批留痕缺失→`ApprovalTrail` 未在导出前写入审批记录。

## 三、导出审批（披露也是敏感操作）

```mermaid
flowchart LR
    A["监管/合规发起披露请求"] --> B["范围审批(法务/安全)"]
    B -->|"过"| C["生成数据包+hash链"]
    B -->|"拒"| D["拒绝留痕"]
    C --> E["交付(审计: 谁/何时/何范围)"]
```

**纪律**：披露**不是想导就导**——涉及用户证据的数据外发要走范围审批（呼应 [25-合规留存](../../教程/58-历史记录持久化与合规.md)、[27-审计回放](../../项目/23-企业级Agent意图路由网关/09-审计回放与合规.md)），且披露本身全程留痕。
