# 03-证据归因引擎

> **定位**：可解释平台的核心——**结论 ← 证据**的归因链。核心：**① 结论拆分（把回答拆成可归因的关键结论）② 归因抽取（每结论标注支撑证据 id：检索片段/工具输出/记忆/规则）③ 证据存储（上下文证据可引用、可回溯）**。呼应 [教程 56 §4](../../教程/56-Agent可解释与透明工程.md)。前置阅读：[02-解释时间线工程化](02-解释时间线工程化.md)。
>
> **铁律 0**：归因抽取用实证 `entity()` 结构化输出思想；归因模型/存储自研「概念代码」。

## 二、证据登记 + 归因抽取

```java
// 概念代码：证据登记（执行时）→ 归因抽取（生成时）
// 1) 任何进上下文的证据先登记拿 id
public String register(EvidenceType type, String content, Map<String,String> meta) {
    String id = "EV-" + seq.incrementAndGet();
    evidenceStore.put(id, new Evidence(id, type, content, meta));   // 检索片段/工具输出/记忆/规则
    return id;
}

// 2) 生成时结构化抽取结论与引用（实证 entity 思想）
record Conclusion(String text, List<String> evidenceIds, ConclusionKind kind) {}  // FACT/INFERENCE/RULE_HIT

List<Conclusion> extract = client.prompt()
    .system("把回答拆成关键结论，每条标注支撑证据id（只准引用给定的 EV-id 列表），无依据的标 kind=INFERENCE")
    .user(question + "\n证据列表:\n" + evidenceDigest)
    .call().entity(/* List<Conclusion> */);
```

### 二.1 本节测试与验证（证据登记 + 归因抽取）

**前置条件**：执行链能在证据进入上下文前触发 `register(...)`；`entity()` 结构化输出已接入（实证 `entity()` 思想），能返回 `List<Conclusion>`；`evidenceStore` 已装配。

**材料——代码内含的旋钮**：`register(EvidenceType, content, meta)` 返回 `EV-<seq>` id；`evidenceStore.put(id, new Evidence(...))`；`Conclusion` 三字段 `text/evidenceIds/kind`；抽取只准引用给定的 `EV-id` 列表、无依据标 `INFERENCE`。

**步骤与断言**：

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | 检索 3 个片段进上下文，各触发一次 `register` | 3 个 `EV-N` id 登记，`evidenceStore` 可查到 3 条 |
| 2 | 构造含事实+推测的回答并调抽取 | 返回 `List<Conclusion>`：事实型带 `EV-id` 引用、推测型 `kind=INFERENCE` |
| 3 | 校验引用合法性 | 抽取结果的 `evidenceIds` 全部落在给定的 `EV-id` 集合内（§三 纪律要求） |
| 4 | 按 runId 查归因 | 时间线 + 归因双视图都能呈现，结论 ↔ 证据 id ↔ 原始内容全链可溯 |

**失败排查**：①无 `EV-id`→执行链未在证据入上下文前调 `register`，钩子漏挂；②结论没拆分（返回整段）→`entity()` 目标类型或 System Prompt 未按"拆关键结论、标引用、无据标 INFERENCE"约束；③引用了证据列表外的 id→抽取阶段未校验引用集合（需在提示中强约束 + 抽取后核验）。

## 三、结论分型（诚实解释的关键）

| kind | 含义 | 解释表达 |
|------|------|---------|
| FACT | 直接有证据 | "依据文档 EV-3：…" |
| RULE_HIT | 规则命中 | "命中规则#7" |
| INFERENCE | 推测（无直接证据） | "**推测**：无直接依据，基于…推断" |

**纪律**：让模型**显式区分"有据"与"推测"**——比全部伪装成有据诚实得多（INFERENCE 不是错误，是诚实标注，联动 05 置信度）。

### 三.1 本节核对（结论分型——诚实解释的关键）

- [ ] 三种 kind（FACT 有据 / RULE_HIT 规则命中 / INFERENCE 推测无据）的含义与解释表达能对照表格复述
- [ ] 纪律一句能说清"INFERENCE 不是错误，是诚实标注"——即让模型显式区分有据与推测，避免全部伪装有据
