## 二、业界对照（校准）

| 方案 | 层次 | 与本方向 |
|------|------|---------|
| **SHAP/LIME** | 特征归因（模型层） | 适合传统 ML 特征归因；LLM 场景特征=Token 不实用，本平台走系统层证据链 |
| **Chain-of-Thought 透明** | 推理过程 | 启发 01 时间线；但 CoT 自述≠证据，本平台要求可校验归因 |
| **EU AI Act 解释义务** | 合规 | 本平台披露数据包（08）的直接对应 |
| **模型卡片/数据卡片** | 文档级 | 与本平台互补（静态文档 vs 动态决策解释），见 [13-附录](../../附录/13-AI治理与合规/01-模型卡片与数据卡片.md) |

**定位判断**：LLM Agent 的可解释**主战场在系统层**（证据链/轨迹/置信）——模型层 XAI（注意力/归因）短期难以工程化落地，本平台选型正确。

### 二.1 本节核对（业界对照）

- [ ] 四种方案（SHAP/LIME、CoT 透明、EU AI Act 义务、模型卡片）与本平台方向的对照结论能复述，尤其能说清"SHAP/LIME 在 LLM 场景不实用"的原因
- [ ] 定位判断（系统层为主战场、模型层短期难落地）与本项目 ADR-01（系统层 XAI）口径一致，选型自洽

## 三、演进方向（按价值排序）

1. **归因自动化加强**：结论拆分与引用抽取的准确率提升（few-shot 校准样本积累，09 飞轮反哺 03）。
2. **跨 Agent 协作解释**：委托链上的解释贯通——A 委托 B（项目27），最终结论的归因要能跨中继追溯到 B 的证据（联邦归因，呼应 [27-联邦](../../项目/27-企业级Agent协作平台/09-跨组织协作与联邦.md)）。
3. **解释与仿真联动**：批量反事实扫描用 [21-仿真平台](../../项目/21-企业级Agent仿真与数字孪生平台/04-场景引擎与参数扫描.md) 承接（离线全量 vs 在线按需）。
4. **用户侧解释 UX 深化**：解释视图产品化（折叠/追问/证据原文下钻），联动 [14-附录交互设计](../../附录/14-Agent交互设计/00-Agent用户体验设计.md)。
5. **模型层 XAI 跟踪**：LLM 内部可解释（电路/特征可视化）研究进展——短期观望、长期若工程化则接入 01 时间线补充维度。

### 三.1 本节核对（演进方向按价值排序）

- [ ] 五个演进方向（归因自动化/跨 Agent 协作解释/与仿真联动/用户侧 UX/模型层跟踪）各自有明确的承接迭代或平台锚点，非空泛口号
- [ ] 排序（按价值）有可辩护理由——各方向的落地成本与价值权衡能一言说明

## 四、工程纪律复盘

- **不要**把 Trace 直接当解释（投影+分层是必须的）。
- **不要**信任未校验的归因（伪解释零容忍，高风险拒发布）。
- **不要**给未校准的置信（实际结果回验是底线）。
- **务必**快照固化（历史解释还原决策时点）。
- **务必**让置信触发行为（复核/拦截路由，不是展示数字）。

### 四.1 本节核对（工程纪律复盘）

- [ ] 三条"不要"（把 Trace 当解释 / 信任未校验归因 / 未校准置信）与三条"务必"（快照固化 / 置信触发行为）均能落到对应迭代篇（02 / 04 / 05 / 06 / 10），并能复述教训
- [ ] 复盘要点与本项目 ADR 取舍口径一致，无"正文未讲、复盘凭空出现"项
