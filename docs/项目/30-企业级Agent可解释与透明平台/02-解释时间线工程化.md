# 02-解释时间线工程化

> **定位**：把 01 的最小投影工程化：**① 时间线分层视图（概要/标准/取证三级）② 长执行折叠（几十步折叠成阶段）③ 多受众渲染（用户/排障/监管不同详略）**。前置阅读：[01-最小Demo](01-最小Demo.md)、[14-附录交互设计/01-中间过程可见性](../../附录/14-Agent交互设计/01-中间过程可见性设计.md)。
>
> **铁律 0**：投影/折叠自研「概念代码」；基座 Trace 实证。

---

## 一、四问

| 问 | 答 |
|----|----|
| **新增了什么需求** | ①三级视图（概要 5 步内/标准/取证全量含原始引用）②长执行阶段折叠（同类型步归并）③受众路由（用户看概要、排障看标准、监管看取证） |
| **影响了哪些模块** | Explainer → 视图分层 + 折叠器 |
| **架构如何演进** | 从"单时间线"演进为"分层多受众解释" |
| **上一版痛点** | 长任务几十步平铺没人看；给用户的解释和给监管的一样细（隐私/噪音） |

**本迭代验收**：①概要 ≤5 步讲清主流程 ②同类型步折叠（3 次重试显示为 1 步带标记）③三种受众各得其所。

## 二、三级视图与折叠

```java
// 概念代码：分层视图 + 折叠
public ExplanationTimeline render(String runId, Audience aud) {
    var full = timeline(runId);                                   // 全量(01)
    var folded = foldRepeats(full);                               // 折叠: 重试/同类工具连调 → 1步×N
    return switch (aud) {
        case USER      -> summarize(folded, 5);                   // 概要: 主流程≤5步
        case OPERATOR  -> folded;                                  // 标准: 全步骤+摘要
        case REGULATOR -> full.withRawRefs();                      // 取证: 全量+原始Span引用
    };
}
```

## 三、受众差异是设计核心

| 受众 | 详略 | 内容取舍 |
|------|------|---------|
| 用户 | 概要 | 讲"为你做了什么"，隐藏内部工具名/参数 |
| 排障 | 标准 | 全步骤 + 输入输出摘要 + 耗时 |
| 监管 | 取证 | 全量 + 原始证据引用（可对账）+ 签名 |

**隐私纪律**：用户视图不暴露内部工具细节（攻击面）；监管视图可含敏感证据但导出走 08 的披露审批（呼应 [25-合规](../../教程/25-历史记录持久化与合规.md)）。

## 四、验收

| 测试 | 期望 |
|------|------|
| 30 步长执行 | 概要 ≤5 步 |
| 3 次重试 | 折叠 1 步×3 |
| 用户视图 | 无内部工具参数 |
| 监管视图 | 全量+原始引用 |
