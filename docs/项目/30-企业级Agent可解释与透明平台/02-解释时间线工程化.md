## 二、三级视图与折叠

```java
// 概念代码：分层视图 + 折叠
public ExplanationTimeline render(String runId, Audience aud) {
    var full = timeline(runId);                                   // 全量(01)
    var folded = foldRepeats(full);                               // 折叠: 重试/同类工具连调 → 1步×N
    return switch (aud) {
        case USER      -> summarize(folded, 5);                   // 概要: 主流程≤5步
        case OPERATOR  -> folded;                                  // 标准: 全步骤+摘要
        case REGULATOR -> full.withRawRefs();                      // 取证: 全量+原始Span引用
    };
}
```

### 二.1 本节测试与验证（三级视图与折叠）

**前置条件**：§01 的 `timeline(runId)` 可用；`foldRepeats`/`summarize`/`withRawRefs` 已按本迭代实现；有一笔长执行（≥30 步）记录作输入。

**材料——代码内含的旋钮**：`foldRepeats(full)` 折叠同类型重复（重试/同类工具连调 → 1 步 ×N）；`summarize(folded, 5)` 概要步数上限 5；`switch (aud)` 按受众路由；`withRawRefs()` 取证级携带原始 Span 引用。

**步骤与断言**：

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | 用 30 步长执行调 `render(runId, USER)` | 概要 ≤5 步讲清主流程 |
| 2 | 用含 3 次重试的执行调 `foldRepeats(full)` | 折叠为 1 步 ×3 且步上有重试标记 |
| 3 | 调 `render(runId, OPERATOR)` | 返回全步骤 + 输入输出摘要 + 耗时（标准级） |
| 4 | 调 `render(runId, REGULATOR)` | 返回全量 + 原始 Span 引用（取证级） |
| 5 | 用户级输出扫描 | 无内部工具名/参数泄露（对照 §四 第 3 行隐私纪律） |
| 6 | 同类型连续工具调用 | 归并为 1 步 ×N，不逐条平铺 |

**失败排查**：①概要超 5 步→`summarize` 上限未生效或折叠未先执行（应 `folded → summarize` 有序）；②重试未折叠→`foldRepeats` 的"同类型"判定条件过严；③取证级找不到原始引用→`withRawRefs` 未带上 Span 引用元数据；④用户视图泄漏工具参数→受众路由未过滤，`USER` 分支走了全量。

## 三、受众差异是设计核心

| 受众 | 详略 | 内容取舍 |
|------|------|---------|
| 用户 | 概要 | 讲"为你做了什么"，隐藏内部工具名/参数 |
| 排障 | 标准 | 全步骤 + 输入输出摘要 + 耗时 |
| 监管 | 取证 | 全量 + 原始证据引用（可对账）+ 签名 |

**隐私纪律**：用户视图不暴露内部工具细节（攻击面）；监管视图可含敏感证据但导出走 08 的披露审批（呼应 [25-合规](../../教程/58-历史记录持久化与合规.md)）。

### 三.1 本节核对（受众差异是设计核心）

- [ ] 三种受众（用户/排障/监管）的详略与内容取舍能对照正文表格复述，且能指出各自的"该看什么、该藏什么"
- [ ] 隐私纪律一句能说清两件事：用户视图不暴露内部工具细节（攻击面）；监管视图含敏感证据却需走 08 披露审批
