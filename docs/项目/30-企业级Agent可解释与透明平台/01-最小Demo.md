## 二、最小投影

```java
// 概念代码：Trace → 解释时间线
@Component
public class Explainer {
    private final TraceReader traceReader;      // 读 Observation Span 流(实证基座)

    public ExplanationTimeline timeline(String runId) {
        return traceReader.events(runId).stream()
            .map(e -> switch (e) {
                case Retrieval r -> Step.evidence("检索: " + r.query(),
                        "命中 " + r.docs().size() + " 篇文档（" + topTitles(r.docs()) + "）");
                case ToolCall t  -> Step.action("调用工具 " + t.tool(),
                        digest(t.input()) + " → " + digest(t.output()));
                case LlmCall s   -> Step.model("模型推理", s.summary());
                default          -> Step.other(e.name());
            })
            .collect(ExplanationTimeline::of);
    }
}
```

### 二.1 本节测试与验证（最小投影：Trace → 解释时间线）

**前置条件**：`traceStore` 已具备一次带检索+工具调用的执行记录（Observation 实证基座）；`traceReader.events(runId)` 能按 runId 读回事件流。

**材料——代码内含的旋钮**：事件三类 `Retrieval`/`ToolCall`/`LlmCall`；每类映射 `Step.evidence/action/model`；`digest()` 对输入输出做摘要（非全文）；`topTitles()` 取命中文档标题。

**核对命令**（解释时间线接口自查）：

```bash
curl -s http://localhost:8081/explain/run-20260830-001/timeline    # 一次执行的解释时间线
# 预期输出（节选）：
#   {"runId":"run-20260830-001","steps":[
#     {"kind":"evidence","title":"检索: 退货政策","digest":"命中 3 篇文档"},
#     {"kind":"action","title":"调用工具 queryOrder","digest":"in/out 摘要"},
#     {"kind":"model","title":"模型推理","digest":"summary"}],"generateMs":1800}
```

**步骤与断言**：

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | 用一次「检索 + 2 工具 + 3 模型」的执行调用 `timeline(runId)` | 时间线 6 步全展示（1 检索 + 2 工具 + 3 模型） |
| 2 | 检查检索步 | 显示查询词 + 命中文档标题（`topTitles` 非空） |
| 3 | 检查工具步 | 输入/输出为 `digest` 摘要（长度可控，非全文） |
| 4 | 检查模型步 | 展示 `summary` 而非原始输出 |
| 5 | 时序核查 | 步骤顺序与真实执行时间一致（Retrieval 在 LLM 前 / ToolCall 按调用序） |
| 6 | 生成延迟 | 整条时间线生成 ≤3s（对照 §四 第 4 行） |

**失败排查**：①事件读空→`runId` 不对或 traceStore 未落该次执行；②步骤分类错→`switch` 分支与真实事件类型不匹配（确认 Observation 类型判定的 `Retrieval/ToolCall/LlmCall` 三态齐全）；③摘要仍含全文→`digest` 未生效或有事件类型落入 `default` 兜底；④延迟超标→时间线渲染在事件循环上阻塞或每步仍在调远程，需本地聚合。

## 三、为什么"投影"而不是"直接给 Trace"

Trace 面向机器（Span/属性/ID），解释面向**人**（做了什么/依据什么/结果怎样）——投影层做三件事：**分类**（证据/动作/推理）、**摘要**（输入输出 digest 而非全文）、**顺序叙事**（按时间讲清楚）。直接甩 Trace 给监管/用户等于没解释。

### 三.1 本节核对（为什么"投影"而不是"直接给 Trace"）

- [ ] 能说清投影层做的三件事（分类 / 摘要 / 顺序叙事）分别解决"人看不懂 Trace"的哪个痛点
- [ ] 「直接甩 Trace 给监管/用户 = 没解释」一句能举例说明（如一堆 Span id 与原始 key-value 对用户无意义）
