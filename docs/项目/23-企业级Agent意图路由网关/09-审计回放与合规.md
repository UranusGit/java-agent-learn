# 09-审计回放与合规

> **定位**：让每一次路由决策**可追溯、可回放、可审计**——尤其高风险请求要形成证据链，应对监管与内部追责。核心：**① 路由全链路审计日志**（输入含脱敏 → 意图 → 置信度 → 目标 → 产出 → HITL 审批结果）② **决策回放**（从日志还原一次完整路由 + 执行）③ 合规策略（高风险长期留存、敏感数据脱敏、越权告警）。呼应 [58-历史记录持久化与合规](../../教程/58-历史记录持久化与合规.md)、[32-工具执行可观测与审计](../../教程/32-工具执行可观测与审计.md)。前置阅读：[08-多级路由缓存](08-多级路由缓存.md)。
>
> **铁律 0**：审计日志落库/事件流自研；数据脱敏用已实证工具。

## 一、四问

| 问 | 答 |
|----|----|
| **新增了什么需求** | ①路由全链路审计日志（append-only、含 hash 链防篡改）②决策回放服务 ③合规策略（高风险留存 7 年、PII 脱敏、越权告警） |
| **影响了哪些模块** | RouteDispatcher → 全链路埋点；新增 审计日志存储 + 回放服务 + 合规策略 |
| **架构如何演进** | 从"只记单条路由"演进为"完整审计证据链 + 回放 + 合规留存" |
| **上一版痛点** | 只有日志，无回放；高风险误放行了无法追溯；无合规留存策略 |

**本迭代验收**：①任意请求可回放"输入→意图→置信度→目标→HITL→产出" ②审计日志 append-only + 防篡改 ③高风险日志留存 ≥ 7 年，PII 字段强制脱敏。

| # | 核对项 | 判据 |
|---|--------|------|
| 1 | 四问口径齐全 | 新增需求（append-only+hash 链/回放服务/合规策略）/影响模块（RouteDispatcher 埋点+审计存储+回放+合规）/架构演进/上一版痛点四行均有 |

## 二、路由全链路审计日志

```java
// 概念代码：append-only 审计事件（hash 链防篡改）
public record RouteAuditEvent(
        long seq,              // 单调递增，参与 hash 链
        String prevHash,       // 前一条 hash（防篡改）
        String requestId, String tenantId,
        String inputHash,      // 输入脱敏：只存 hash + 低频可逆脱敏
        RouteKey intent, double confidence,
        String selectedRoute, String outcome,
        String hitlDecision,   // HITL 审批：/ 批准 / 驳回
        long ts) {
    public String computeHash() { /* SHA-256(seq+prevHash+... ) */ }
}
```

**三条合规纪律**：
1. **高风险请求全文留存**：只对 approval/data 高危操作存"可回放明文"，其余存 hash（平衡隐私与审计）。
2. **PII 脱敏**：身份证/手机号/地址在入库前脱敏（呼应 [06-数据脱敏](../../项目/06-金融风控Agent系统/06-数据脱敏与合规.md)）。
3. **留存策略**：按风险分级设定留存时长与归档（呼应 [25](../../教程/58-历史记录持久化与合规.md)、[86-Agent治理与合规框架](../../教程/86-Agent治理与合规框架.md)）。

### 二.1 本节测试与验证（审计日志 + hash 链防篡改）

**前置条件**：`RouteAuditEvent` 记录已定义；`computeHash()`（SHA-256(seq+prevHash+...)）已实现；审计写入为 append-only。

**材料——事件记录核对**：

```text
seq / prevHash / requestId / tenantId / inputHash / intent / confidence / selectedRoute / outcome / hitlDecision / ts
```

**步骤与断言**：

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | 一次路由落一条审计事件 | 记录包含上表全字段，append-only（不覆盖） |
| 2 | 篡改中间任一条的 hash 字段 | 其后相邻事件的 `prevHash` 校验失败（防篡改生效） |
| 3 | 高风险 APPROVAL 请求 | 落**全量明文**（可回放明细）而非仅 hash；PII 字段入库前已脱敏 |

**失败排查**：①hash 链不断→`computeHash` 未把 prevHash 纳入或校验未实现；②高风险无明文→"只存 hash"分支误用于高风险；③PII 泄露→脱敏在入库前未执行（呼应数据脱敏）。

## 三、决策回放

```mermaid
sequenceDiagram
    participant OP as 审计员
    participant RP as 回放服务
    participant ST as 审计存储
    OP->>RP: 查 requestId
    RP->>ST: 读该 turn 全部 RouteAuditEvent
    ST-->>RP: 时间线事件流
    RP->>OP: 还原：输入→意图(置信度)→目标→HITL→产出
```

**回放价值**：误放行追责时，能还原"当时为什么路由到那"（置信度多少、是否过了 HITL、审批人是谁）——是内部追责与监管披露（呼应 [19-跨组织互认与监管披露](../../项目/19-企业级Agent信任与评测平台/10-跨组织信任互认与监管披露.md)）的基础。

### 三.1 本节核对（决策回放）

- [ ] "审计员查 requestId → 回放服务读全部 RouteAuditEvent → 还原'输入→意图(置信度)→目标→HITL→产出'"流程能复述，与正文验收①可回放完整链一致
- [ ] 回放能回答"当时为什么路由到那、置信度多少、是否过 HITL、审批人是谁"——这是追责披露的基础，与 09 合规定位一致

## 四、全篇回归验证

| 测试 | 期望 |
|------|------|
| 单请求回放 | 还原完整路由决策链 |
| hash 链 | 篡改任一条 → 后续 hash 校验失败 |
| PII 脱敏 | 敏感字段入库前已脱敏 |
| 留存 | 高风险日志长期留存，低风险可归档 |

**回归断言**：

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | 抽一条高风险请求 | 可回放"输入→意图→置信度→目标→HITL→产出"完整链（对应上表首行，验收①） |
| 2 | 篡改某条 hash 后校验 | 后续 hash 链校验失败（对应上表次行，验收②防篡改） |
| 3 | 检查高风险日志留存 / PII 字段 | 高风险留存 ≥7 年、敏感字段入库前已脱敏（对应上表后两行，验收③） |

**回归失败排查**：①回放断链→审计埋点缺某环节（如 HITL 结果未记 `hitlDecision`）；②篡改检测不到→`computeHash` 未含 prevHash；③脱敏失效→入库前脱敏未作用于高风险明文之外的 PII。
