## ADR-01：意图识别三层漏斗

**决策**：规则路由 → 语义路由 → LLM 分类，逐级兜底，确定性先行、LLM 收尾。

**背景**：意图识别可枚举、可语义、可 LLM 开放判断，三种方案性能/成本/泛化差异大。

**备选**：
- A. 纯规则：最快免费，但不认语义、覆盖不全。
- B. 纯 LLM 分类：最灵活，但每次路由烧 Token + 延迟 200ms+。
- C. 三层漏斗（采纳）：规则省心 → 语义主力（快不烧 Token）→ LLM 兜底模糊地带。

**取舍**：成本/延迟/可解释三重平衡。本平台一贯方法论"确定性先行、LLM 收尾"。

### ADR-01 本节核对
- [ ] 三层漏斗（规则→语义→LLM）的"确定性先行、LLM 收尾"与 [01/02] 落地一致；备选 A/B/C 三方案取舍理由能复述
- [ ] 该决策与 00 §三 迭代路线、03 控/数分离不冲突

## ADR-02：语义路由自研（EmbeddingModel + 余弦）

**决策**：基于 `EmbeddingModel#embed()`（javap 实证）自研语义路由，**不引入第三方 Router SDK**。

**背景**：Spring AI 2.0.0 全仓实证**无 Router API**，语义路由需自建。

**备选**：
- A. 无官方 API → 无法直接用。
- B. 自研（采纳）：示例句向量预计算缓存 + 余弦相似度，可解释、可观测、可调阈值。

**取舍**：无官方轮子只能是自研；实证约束了选择，也避免了"凭记忆用不存在的 Router"的理念错误（铁律 0）。

### ADR-02 本节核对
- [ ] "Spring AI 2.0.0 无 Router API → 自研 EmbeddingModel+余弦"这一铁律 0 结论可复述，且全篇未引入虚假 Router SDK
- [ ] 自研引擎所有编码均为「概念代码」，模型调用 `EmbeddingModel#embed()` 以已实证签名书写

## ADR-03：路由目标 = 可执行链，非裸 ChatClient

**决策**：`RouteTarget` 封装 ChatClient + preGuard + requiresHitl + risk，不是裸模型。

**背景**：只路由到模型，模型层没有业务语义（工具集/记忆/审批）导致直接裸调度不可用。

**备选**：A. 裸 ChatClient；B. 可执行链封装（采纳）。

**取舍**：路由不该只选模型，该选"带完整业务上下文的一条链"——这是与 [32-模型路由](../../教程/32-模型路由与降级.md) 的分界点。

### ADR-03 本节核对
- [ ] RouteTarget 封装（ChatClient+preGuard+requiresHitl+risk）与 [03] 落地一致，"选链非选模型"与 [32 模型路由] 分界说得清
- [ ] 裸 ChatClient 备选（A）被否定的理由（缺业务语义）能复述

## ADR-04：阈值按意图独立、风险分档

**决策**：每意图独立阈值，高风险意图（审批/支付）高阈值宁可不接，低风险多兜住。

**背景**：误分代价跨意图差一个数量级，全局一个阈值无法兼顾。

**取舍**：安全 >> 可用性（高风险）；可用性 > 极低误分（低风险）。呼应多租户分级治理。

### ADR-04 本节核对
- [ ] "按意图独立阈值、风险分档"与 [05] 落地一致（APPROVAL 0.85 / RAG 0.6）
- [ ] "误分代价跨意图差一个数量级"的取舍理由能复述，且与 [05 §二] 口径一致

## ADR-05：HITL 落工具执行边界（非路由 Advisor）

**决策**：高风险操作强制 HITL 闸门放在**工具执行边界**（ToolCallingManager 装饰器/ToolCallback 包装层），不放在路由的 Advisor。

**背景**：若 HITL 只是路由层 Advisor，执行链内部仍可绕过；安全闸门必须设在"能否真正操作"的边界。

**取舍**：即使路由误分（把高危请求当低风险），HITL 闸门仍能在工具执行前拦截——安全不从路由审计侧绕开。

### ADR-05 本节核对
- [ ] "HITL 落工具执行边界（ToolCallingManager 装饰器/ToolCallback 包装层），非路由 Advisor"与 [07] 落地一致
- [ ] "若只在路由 Advisor，执行链内仍能绕过"的根因能复述，与资料库 HITL 落点结论一致

## ADR-06：路由配置数据化 + 灰度秒级回滚

**决策**：阈值/示例句/意图配置抽离存储，变更走灰度 + 秒级回滚，不靠改代码发版。

**背景**：改路由参数高频（响应话术漂移），发版太重、回滚太慢。

**取舍**：运维便利 + 安全上线（呼应教程 29 灰度）。风险是配置漂移 → 用版本化 + 审计兜底。

### ADR-06 本节核对
- [ ] "配置数据化 + 灰度秒级回滚，不靠改代码发版"与 [06] 落地一致（热更新、10% 灰度、秒级回滚）
- [ ] "配置回滚（秒级）vs 代码回滚（重发）"差异与 [06 §三.1] 口径一致；版本化+审计兜底防配置漂移能复述

## ADR-07：缓存分两级 + 低置信不缓存

**决策**：会话级 + 全局语义级两级缓存；低置信/高风险请求不缓存。

**背景**：路由延迟优化（呼应教程 38）；但缓存的错误复用代价高。

**取舍**：性能 vs 正确性。缓存的 key 含租户（多租户矩阵），配置变更 → 全失效。

### ADR-07 本节核对
- [ ] "会话级+语义级两级缓存、低置信不缓存"与 [08] 落地一致
- [ ] "key 含租户、配置变更全失效、错一次一直错的代价"三条权衡能复述，与 [08 §二/§三] 一致

## ADR-08：策略中心统一下发（XDS 式）

**决策**：路由策略收入策略中心，审批-灰度-审计一体化管线，运行态按版本拉取。

**背景**：配置分散导致治理空白；多路由网关需集中管理（呼应项目 16 xDS 思想）。

**取舍**：管控分离深化（控制面管策略、数据面管执行）；复杂度用版本协商 + 会话一致性化解。

### ADR-08 本节核对
- [ ] "策略中心统一下发（XDS 式）、审批-灰度-审计管线"与 [10] 落地一致
- [ ] "管控分离深化 + 版本协商/会话一致性化解复杂度"的取舍能复述，与 [10 §二/§四]、[20] 控制面语义一致

## 决策代价回顾

- ADR-02 自研 = 不依赖外部 Router 库，但示例句维护成本要长期承担（靠 13 前沿的示例句飞轮缓解）。
- ADR-05 HITL 在工具边界 = 更安全，但需要每个高危工具接入闸门，接入成本较高（后续可做闸门自动注入）。
- ADR-08 策略中心 = 治理更强，但引入策略拉取/版本协商基础设施复杂度。
