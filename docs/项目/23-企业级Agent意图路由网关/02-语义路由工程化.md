## 二、示例句管理 + 向量缓存

```java
// 概念代码：语义路由工程化
@Component
public class SemanticRouter {
    private final EmbeddingModel embeddingModel;

    // 意图 → 示例句（每意图 10~20 条，覆盖变体/口语/同义）
    // 启动预计算：每个示例句 embed 一次，线上只对用户输入 embed 一次
    // 【05 迭代前】全平台用同一全局阈值(按意图独立阈值是 05 迭代引入 RouteConfig 后才有的能力)
    private static final double GLOBAL_THRESHOLD = 0.6;
    private final Map<RouteKey, List<String>> intentExamples = Map.of(
        RouteKey.ORDER_SERVICE, List.of("查订单物流", "退换货", "包裹到哪了"),
        RouteKey.KNOWLEDGE_RAG, List.of("搜索公司年报", "找制度文档"),
        RouteKey.APPROVAL_FLOW, List.of("审批报销", "流程卡住了")
    );
    private final Map<RouteKey, List<float[]>> exampleVecCache = new ConcurrentHashMap<>();

    @PostConstruct
    void preCompute() {
        for (var e : intentExamples.entrySet()) {
            List<float[]> vecs = embeddingModel.embed(e.getValue());  // embed(List<String>) 实证
            exampleVecCache.put(e.getKey(), vecs);
        }
    }

    RouteKey route(String input) {
        float[] v = embeddingModel.embed(input);
        RouteKey best = UNKNOWN; double bestScore = -1;
        for (var e : exampleVecCache.entrySet()) {
            double score = e.getValue().stream()
                    .mapToDouble(ex -> cosine(v, ex)).max().orElse(0);
            if (score > bestScore) { bestScore = score; best = e.getKey(); }
        }
        // 全局阈值兜底(按意图独立阈值 → 05 迭代落地)
        return bestScore >= GLOBAL_THRESHOLD ? best : UNKNOWN;
    }
}
```

### 二.1 本节测试与验证（示例句缓存 + 余弦路由）

**前置条件**：`SemanticRouter` 可编译；EmbeddingModel 已装配；示例句 `intentExamples` 已定义（ORDER_SERVICE/KNOWLEDGE_RAG/APPROVAL_FLOW 三意图为例）。

**材料——提问组**：

```text
"我的包裹为什么还没到"   # ORDER_SERVICE（无"订单/物流"关键词，考语义）
"今年集团营收增长多少"   # 示例集会命中（需有 DATA 意图句，缺则看兜底）
"随便聊聊"               # 低于 0.6 → UNKNOWN
```

**步骤与断言**：

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | 应用启动 | `@PostConstruct preCompute()` 对每示例句各 embed 一次，线上不重复 |
| 2 | 提问"我的包裹为什么还没到" | 语义命中 ORDER_SERVICE（无关键词仍靠语义） |
| 3 | 提问"随便聊聊" | 余弦最高分 <0.6 → UNKNOWN（全局阈值兜底） |
| 4 | 冷启动预计算 | 日志可见预计算完成的向量条数 == 示例句总数 |

**失败排查**：①全部兜底→`embed(List<String>)` 预计算没跑或返回空；②"我的包裹"没命中 ORDER_SERVICE→示例句集未含该意图变体，补句；③阈值无效→`GLOBAL_THRESHOLD` 读取分支未走到（检查 `return` 顺序）。

## 三、三方案选型矩阵（写进架构决策）

| 维度 | 规则路由 | 语义路由 | LLM 分类 |
|------|---------|---------|---------|
| 延迟 | ~0ms | ~30ms | ~200ms+（多一轮推理） |
| Token 成本 | 0 | ~1 次 embedding | 每次推理 |
| 语义泛化 | ❌ 只认字面 | ✅ 认意思 | ✅ 最灵活 |
| 可解释性 | 最强（规则可读） | 中（看相似度） | 弱（黑盒） |
| 新意图适配 | 加规则快 | 补示例句快 | 改分类词表 |
| 适用 | 高频确定性词 | 类别有限有示例 | 开放意图 |

**结论**：三层漏斗（规则 → 语义 → LLM）是标准解，**确定性先行、LLM 收尾**——这套取舍会记入 12-ADR。
