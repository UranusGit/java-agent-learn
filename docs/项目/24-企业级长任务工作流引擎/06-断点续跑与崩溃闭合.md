## 二、并发 Checkpoint 状态

```java
// 概念代码：每步原子状态（并发安全）
record StepRecord(String stepId, StepState state,
                  String opKey,            // 03 幂等键：崩溃判定依据
                  Map<String,Object> result) {}

// Checkpoint 保存：整张 stepState 表 + 每步原子 upsert
public void checkpoint(String runId, Map<String, StepRecord> steps) {
    for (var s : steps.values()) {
        stepStore.upsert(runId, s);   // 每步独立原子写，不做整表事务(可并发)
    }
}
```

### 二.1 本节测试与验证（并发 Checkpoint 每步原子）

**前置条件**：`StepRecord`/`stepStore.upsert(runId, s)` 按上文实现；stepStore 为支持每步独立原子写的 Redis/DB 存储（含 `opKey` 供崩溃判定）。

**材料——多步并发写与崩溃注入**：同时 `checkpoint` 多步；在写第 2 步后、第 3 步前模拟崩溃（进程终止），验证部分写落库。

#   崩溃后 load 可见 1-2 步落库、第 3 步无

**步骤与断言**：

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | 对 3 个步骤并行调用 `checkpoint` | 每步独立 `upsert` 均原子成功，无整表事务回滚污染 |
| 2 | 写第 2 步后、第 3 步前崩溃 | `load` 可见 1-2 步已落库、第 3 步无（`completedStep` 之前步骤在） |
| 3 | 并发同写一步 | 仅一次生效（原子 upsert/乐观锁），无覆盖丢状态 |
| 4 | 读回 `StepRecord` | `opKey`/`state`/`result` 字段完整，可供 §三 孤儿判定使用 |

**失败排查**：①整表事务回滚吞掉已完成步→写了 `@Transactional` 整表而非每步 upsert；②同一步被覆盖→`upsert` 无 CAS/乐观锁（两 Writer 同写一步）；③读回缺 `opKey`→`StepRecord` 未在落库时携带 03 幂等键。

## 三、并发恢复：孤儿步骤判定表

崩溃时可能有多个步骤停在 RUNNING。恢复协调器对每个孤儿步骤走**确定性判定**（用 03 幂等账本 + 该步是否外部副作用）：

| 账本状态 | 步骤性质 | 处理 |
|---------|---------|------|
| 已登记开始 + 已记结果 | 任意 | **重放结果**（副作用已发生一次） |
| 已登记开始 + 未记结果 | 有外部副作用(扣款/写库) | **人工/HITL 裁决**（不确定是否已触发） |
| 已登记开始 + 未记结果 | 无副作用(纯计算/读) | **安全重跑** |
| 未登记 | 任意 | **安全重跑**（副作用未发生） |

```java
// 概念代码：恢复协调器
public Mono<Void> recover(String runId) {
    return loadCheckpoint(runId)                     // 读取持久化步骤
        .flatMapMany(orphans -> Flux.fromIterable(orphans))
        .concatMap(orphan -> resolveOrphan(orphan))  // 按上表：重放/重跑/转HITL
        .then(continueFromLastDone(runId));          // 从未完成续跑
}
```

**核心纪律**：**宁可让"不确定是否触发副作用"的步骤转人工裁决，也不无脑重跑**——这是与"最大轮次""幂等"一起，构成可靠性的三重保险。

### 三.1 本节测试与验证（并发恢复孤儿闭合）

**前置条件**：`RecoveryCoordinator.recover(runId)` 按上文代码实现并调用 03 幂等账本（`markStarted`/`markDone`）做孤儿判定；能构造 `resolveOrphan` 三条路径的重放/安全重跑/转 HITL。

**材料——孤儿步骤四象限集**：覆盖判定表四行（已登记+已记结果/已登记+未记结果有副作用/已登记+未记结果无副作用/未登记）。

```bash
mvn test -Dtest=RecoveryCoordinatorTest        # 按 §三 手写判定表四行/续跑一致性用例后执行
# 预期输出（节选）：
#   Tests run: 5, Failures: 0, Errors: 0, Skipped: 0
#   四象限各走重放/HITL/安全重跑分支，续跑结果与未崩溃一致
#   BUILD SUCCESS
```


**步骤与断言**：

| # | 操作 | 预期（PASS 判据） |
|---|------|------------------|
| 1 | 孤儿"已登记开始+已记结果" | 决定性**重放结果**，副作用不重触发 |
| 2 | 孤儿"已登记开始+未记结果"且属有外部副作用（扣款/写库） | 转 **HITL 人工裁决**，绝不由机器重跑 |
| 3 | 孤儿"已登记开始+未记结果"且纯计算/读步骤 | 安全重跑（无副作用风险） |
| 4 | 孤儿"完全未登记" | 安全重跑（副作用未发生） |
| 5 | 恢复完成后 `continueFromLastDone` | 从最后已完成步骤续跑，最终结果与未崩溃一致 |

**失败排查**：①"不确定副作用"却重跑→`resolveOrphan` 对有外部副作用的孤儿走了安全重跑分支（判据漏查副作用性质）；②重放丢结果→`markDone` 未序列化结果；③恢复后结果不一致→`continueFromLastDone` 起点定位错误（`completedStep` 之后继续）。
