## 二、业界对照（校准）

| 方案 | 性质 | 与本方向 |
|------|------|---------|
| **Temporal** | 分布式工作流引擎（领域成熟） | 需引入依赖后 javap 实证；多副本/强一致时强 |
| **Spring 生态** | 无官方长任务工作流 API | 自研是主流做法 |
| **自研引擎（本文）** | Checkpoint+幂等+预算+DAG | 轻量、可控、可观测、贴合业务 |

**选型判断**：
- **何时自研（本文）**：企业内部、数量可控、需与 Spring Reactor 深度集成、成本敏感。
- **何时 Temporal**：跨团队海量长任务、需完整调度/重放 UI、已有 K8s+Temporal 运维；此时把 [08 SPI](../../docs/hitl) 的适配层换掉即可。

### 二.1 本节核对（业界对照校准）

| # | 核对项 | 判据 |
|---|--------|------|
| 1 | 对照表三行口径 | Temporal（业界成熟，需实证）/Spring 生态（无官方 API）/自研（本文）三行的性质与本项目立场一致 |
| 2 | 选型判断可落地 | "何时自研/何时 Temporal"给出可判定条件（团队规模/是否已有 K8s+Temporal/Ractor 集成深度），且与 ADR-01 预留的 SPI 迁移路径自洽 |

## 三、演进方向（按价值排序）

1. **引擎重放审计双通道**：把 Checkpoint + 幂等账本 + 轨迹事件沉淀为**可回放、可审计**的完整证据链（呼应 [01-会话引擎 JSONL 恢复](../../项目/22-企业级Agent会话引擎/00-需求分析与架构设计.md)、[23 审计回放](../../项目/23-企业级Agent意图路由网关/09-审计回放与合规.md)）。
2. **Temporal 适配层**：当 [09 多机] 演进到需要强一致/完整调度 UI 时，做 SPI 适配 Temporal（ADR-01 预留的迁移路径）。
3. **超长任务 + Agent 编排融合**：把 DAG 长任务与 [79-Agent工作流编排](../../教程/79-Agent工作流编排.md) 打通——Agent 自主生成的 plan 转成可持久化的 DAG（长任务化的 Agent）。
4. **预算成本智能预测**：用历史用量预测长任务预算（呼应 [20-预算预测与成本治理](../../项目/20-企业级Agent经济与结算平台/08-预算预测与成本治理.md)），实现"预估超预算提前降级"而非事后掐断。
5. **Saga 式补偿**：对多步骤跨系统长任务，借鉴 Saga 的补偿语义，失败时执行逆操作（比"全部人工裁决"自动化程度更高，呼应 [30-容错](../../教程/63-容错与弹性设计.md)）。

### 三.1 本节核对（演进方向按价值排序）

| # | 核对项 | 判据 |
|---|--------|------|
| 1 | 五条方向各自来源自洽 | 每条（重放审计/SPI 适配 Temporal/与 36 编排融合/预算预测/Saga 补偿）都能指向上游某能力或某迭代，非凭空新增 |
| 2 | 与决策关系一致 | 方向 2 与 ADR-01 迁移路径、方向 4 与 10/20 成本预测对接一致，演进不推翻已采纳决策 |

## 四、工程纪律复盘

- **不要**把副作用裸执行（不登记就执行 = 崩溃重复副作用）。
- **不要**只设最大轮次（挡不住"烧钱没进展"）。
- **不要**恢复时无脑重跑孤儿步骤（不确定副作用先转人）。
- **务必**每步持久化 + 元原子 upsert（多 Worker 才安全）。
- **务必**把预算做成可视化 + HITL 可裁决，而非只硬掐断。

### 四.1 本节核对（工程纪律复盘）

| # | 核对项 | 判据 |
|---|--------|------|
| 1 | 五"不要/务必"可溯源 | 每条纪律（副作用不裸执行/不只设轮次/恢复不无脑重跑/每步原子/预算可裁决）都能回溯到 ADR-02/03/06/05/10 对应决策 |
| 2 | 正反面口径 | "务必"与"不要"成对照（如"务必逐条 upsert"对"不要无脑重跑"），无只讲一面 |
