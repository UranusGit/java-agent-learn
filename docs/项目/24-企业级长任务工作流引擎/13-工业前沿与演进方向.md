# 13-工业前沿与演进方向

> **定位**：收官篇。把项目 24（长任务工作流引擎）放到业界长任务工程的长河中校准（Temporal / 自研 / Spring 方案），给出**可落地的演进方向**。读者画像：要判断"长任务该自研还是用 Temporal、下一步往哪走"的架构师。前置阅读：本项目全部正向迭代。

---

## 一、平台成熟度回看

| 能力 | 迭代 | 成熟度 |
|------|------|--------|
| 断点续跑 / 崩溃闭合 | 01/06 | ✅ 生产可用 |
| 幂等（副作用一次） | 03 | ✅ 生产可用 |
| 三层预算 + 死循环 | 04 | ✅ 生产可用 |
| DAG 编排 + 多 Worker | 05 | ✅ 生产可用 |
| 可视 + 取消 + 成本台 | 07/10 | ✅ 生产可用 |
| 独立引擎 SPI | 08 | ✅ 库级可用 |
| 多机分布式 | 09 | 🟡 半生产（需 K8s+Redis 配套） |

**收敛判断**：核心（幂等/预算/恢复/编排）已达**可直接投产**；多机分布式（09）与 Temporal 迁移是下一步决策点。

## 二、业界对照（校准）

| 方案 | 性质 | 与本方向 |
|------|------|---------|
| **Temporal** | 分布式工作流引擎（领域成熟） | 需引入依赖后 javap 实证；多副本/强一致时强 |
| **Spring 生态** | 无官方长任务工作流 API | 自研是主流做法 |
| **自研引擎（本文）** | Checkpoint+幂等+预算+DAG | 轻量、可控、可观测、贴合业务 |

**选型判断**：
- **何时自研（本文）**：企业内部、数量可控、需与 Spring Reactor 深度集成、成本敏感。
- **何时 Temporal**：跨团队海量长任务、需完整调度/重放 UI、已有 K8s+Temporal 运维；此时把 [08 SPI](../../docs/hitl) 的适配层换掉即可。

## 三、演进方向（按价值排序）

1. **引擎重放审计双通道**：把 Checkpoint + 幂等账本 + 轨迹事件沉淀为**可回放、可审计**的完整证据链（呼应 [01-会话引擎 JSONL 恢复](../../项目/22-企业级Agent会话引擎/00-需求分析与架构设计.md)、[23 审计回放](../../项目/23-企业级Agent意图路由网关/09-审计回放与合规.md)）。
2. **Temporal 适配层**：当 [09 多机] 演进到需要强一致/完整调度 UI 时，做 SPI 适配 Temporal（ADR-01 预留的迁移路径）。
3. **超长任务 + Agent 编排融合**：把 DAG 长任务与 [36-Agent工作流编排](../../教程/36-Agent工作流编排.md) 打通——Agent 自主生成的 plan 转成可持久化的 DAG（长任务化的 Agent）。
4. **预算成本智能预测**：用历史用量预测长任务预算（呼应 [20-预算预测与成本治理](../../项目/20-企业级Agent经济与结算平台/08-预算预测与成本治理.md)），实现"预估超预算提前降级"而非事后掐断。
5. **Saga 式补偿**：对多步骤跨系统长任务，借鉴 Saga 的补偿语义，失败时执行逆操作（比"全部人工裁决"自动化程度更高，呼应 [30-容错](../../教程/30-容错与弹性设计.md)）。

## 四、工程纪律复盘

- **不要**把副作用裸执行（不登记就执行 = 崩溃重复副作用）。
- **不要**只设最大轮次（挡不住"烧钱没进展"）。
- **不要**恢复时无脑重跑孤儿步骤（不确定副作用先转人）。
- **务必**每步持久化 + 元原子 upsert（多 Worker 才安全）。
- **务必**把预算做成可视化 + HITL 可裁决，而非只硬掐断。
