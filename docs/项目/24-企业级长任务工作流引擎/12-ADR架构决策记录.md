## ADR-01：自研引擎，不引入 Temporal

**决策**：基于教程 05-Observation可观测/07-指标治理：Token计量、SLO与基数熔断 `CheckpointStore` 范式自研工作流引擎，Temporal 仅作业界对照。

**背景**：需要企业级长任务可靠性，但本机无 Temporal SDK（未实证）、引入体积/运维重。

**备选**：A. 用 Temporal（成熟但需引入依赖实证+运维）；B. 自研（采纳，轻量可控可观测）。

**取舍**：轻量自研满足"幂等+预算+恢复+多 Worker"核心；Temporal 待规模验证后在 13-前沿讨论迁移。

### ADR-01 本节核对

- [ ] 能复述决策（自研、不引 Temporal）与两条理由（本机未实证、体积/运维重）；备选 A/B 取舍清晰
- [ ] ADR-01 与 13-前沿"何时 Temporal、SPI 适配层"承接，非孤立决策

## ADR-02：副作用三段式幂等

**决策**：副作用"登记→执行→记结果"三段 + 全局唯一 opKey（SETNX）防并发重放。

**背景**：长任务重试必然发生，副作用重复触发（扣款/发消息/写库）是事故（呼应 20-支付幂等）。

**取舍**：登记先于执行是底线；失败也登记（不误判成功），崩溃孤儿按账本判定。

### ADR-02 本节核对

- [ ] 能复述三段式（登记→执行→记结果）+ 全局唯一 opKey(SETNX) 防并发
- [ ] 决策与 03 文件 §二 代码（markStarted/markDone/markFailed）口径一致，无重复 API 虚构

## ADR-03：三层预算 + 死循环指纹

**决策**：轮次/Token/时长三闸 + "循环不进展"指纹检测（不只最大轮次）。

**背景**：最大轮次能防"无限"，挡不住"烧钱但没进展"（ReAct 反复同一工具）。

**取舍**：指纹滑动窗口判进展，正常换参数不算死循环，原地打转才掐断。

### ADR-03 本节核对

- [ ] 能复述"三闸（轮次/Token/时长）+ 指纹判循环不进展"区别于"只设最大轮次"
- [ ] 与 04 文件 §二/§三 代码（canContinue/isDeadLoop）口径一致

## ADR-04：单写者 Actor 核

**决策**：每任务一个 Actor（有界命令 + 串行处理），暂停/恢复/取消状态机（02）。

**背景**：多命令（暂停/新步骤/取消）并发会打架，状态不可控。

**取舍**：单写者保证状态一致；取消用"安全收尾"而非硬杀（保护副作用一致性）。

### ADR-04 本节核对

- [ ] 能复述"每任务一个 Actor 有界命令+串行"及取消走安全收尾不硬杀
- [ ] 与 02 状态机、07 取消纪律口径一致，非本节省造

## ADR-05：DAG 就绪层调度

**决策**：按"当前足依赖已满足的就绪步骤"一层层并行（非整图一锅端）。

**背景**：整图并发会击穿资源 / 破坏依赖约束；串行又慢。

**取舍**：就绪列表 + 限并发 flatMap，既有并行度又守拓扑序。

### ADR-05 本节核对

- [ ] 能复述"按就绪层一层层并行"（非整图并发）区别于串行与整图一锅端
- [ ] 与 05 文件 §二（拓扑就绪 + 限并发 flatMap）口径一致

## ADR-06：Checkpoint 每步原子 + 孤儿判定

**决策**：每步独立原子 upsert（非整表事务）+ 孤儿步骤按幂等账本确定性判定（重放/重跑/人工）。

**背景**：并发崩溃时，哪些重放/重跑/要人必须可判定。

**取舍**：宁可让"不确定副作用"的孤儿转 HITL，不无脑重跑——可靠性三重保险之一。

### ADR-06 本节核对

- [ ] 能复述"每步原子 upsert（非整表事务）+ 孤儿按账本确定性判定（重放/重跑/人工）"
- [ ] 与 06 文件 §三 判定表四象限口径一致，能指出"不确定副作用转 HITL 不无脑重跑"是最高纪律

## ADR-07：引擎 SPI 可插拔

**决策**：CheckpointStore/StepQueue/BudgetLedger 定义 SPI，业务只声明 StepSpec。

**背景**：引擎需被多业务复用、且存储/调度需随环境换。

**取舍**：抽象解耦但引入 SPI 复杂度；用内存实现做单测补偿。

### ADR-07 本节核对

- [ ] 能复述三 SPI（CheckpointStore/StepQueue/BudgetLedger）可插拔 + 业务只声明 StepSpec
- [ ] 与 08 文件 §二 SPI 接口、§二 测试验证（换存储只改配置/内存实现冒烟）口径一致

## ADR-08：分布式协调用 Redis

**决策**：抢任务（RPOPLPUSH+锁）、Checkpoint 原子、预算计数（INCRBY）统一走 Redis。

**背景**：多机续跑需跨实例一致的队列/状态/预算（呼应 09）。

**取舍**：Redis 简单够用；真强一致场景再评估（13-前沿提）。

### ADR-08 本节核对

- [ ] 能复述"统一走 Redis：抢任务 RPOPLPUSH+锁 / Checkpoint 原子 / 预算 INCRBY"
- [ ] 与 09 文件 §二 分布式协调、§二 测试验证（并发同一步单执行/预算多副本准确）口径一致

## 决策代价回顾

- ADR-01 自研 = 需长期维护引擎内核（靠 13-前沿评估是否迁移 Temporal 兜底）。
- ADR-02 幂等账本 = 引入账本存储与序列化（换取副作用安全）。
- ADR-05 就绪层调度 = 每轮轮询有轻微调度开销（换取依赖正确性）。

### 决策代价回顾 本节核对

> 本节核对（一句话）：三条代价（自研需维护内核/转账本引入存储/就绪层有轮询开销）均落在具体 ADR（01/02/05）上且给出"换取"的正收益，无凭空列代价；与前文备选取舍收敛一致即 PASS。
