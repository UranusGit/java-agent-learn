## 1. 五个关键设计复盘

### 1.1 为什么闸门在 ToolCallingManager 而不是 Advisor（本项目最重要的一课）

ChatClient 的 Advisor 环绕**整个调用边界**；工具执行循环发生在 ChatModel 内部的 ToolCallingManager。要拦截"LLM 已决定调用 `submit_final_decision`、但尚未执行"，唯一稳定的位置就是装饰 ToolCallingManager。这个教训的普适版：**拦截点必须选在被拦截行为的真实发生层**，而不是离业务最近的层。同样的道理：工具审计也在 TCM/ToolCallback 层做才不漏（AOP 拦 @Tool 拦不到框架的反射调用，[教程 01-WebFlux与响应式编程/07-WebFlux测试与性能调优 §Observation 扩展点]）。

真实签名（spring-ai-model-2.0.0 反编译核对）：

```java
// 真实接口：org.springframework.ai.model.tool.ToolCallingManager
// （框架自带接口，仅作签名参考——装饰器必须实现这两个抽象方法，不要照抄进项目）
public interface ToolCallingManager {

    List<ToolDefinition> resolveToolDefinitions(ToolCallingChatOptions chatOptions);

    ToolExecutionResult executeToolCalls(Prompt prompt, ChatResponse chatResponse);
}
```

```java
package com.bank.risk.tool;

import com.bank.risk.domain.ApprovalStatus;
import com.bank.risk.service.ApprovalService;
import com.fasterxml.jackson.databind.ObjectMapper;
import org.springframework.ai.chat.messages.AssistantMessage;
import org.springframework.ai.chat.messages.AssistantMessage.ToolCall;
import org.springframework.ai.chat.messages.Message;
import org.springframework.ai.chat.messages.ToolResponseMessage;
import org.springframework.ai.chat.messages.ToolResponseMessage.ToolResponse;
import org.springframework.ai.chat.model.ChatResponse;
import org.springframework.ai.chat.model.Generation;
import org.springframework.ai.chat.prompt.Prompt;
import org.springframework.ai.model.tool.ToolExecutionResult;
import org.springframework.ai.model.tool.ToolCallingManager;

import java.util.ArrayList;
import java.util.List;
import java.util.Set;

/** 关键代码：executeToolCalls 真实签名——从 ChatResponse 取工具调用，命中危险工具按审批状态分流。 */
public class HumanApprovalToolManager implements ToolCallingManager {

    private static final Set<String> DANGEROUS_TOOLS = Set.of("submit_final_decision");

    private final ToolCallingManager delegate;
    private final ApprovalService approvalService;
    private final ObjectMapper objectMapper;

    public HumanApprovalToolManager(ToolCallingManager delegate,
                                    ApprovalService approvalService,
                                    ObjectMapper objectMapper) {
        this.delegate = delegate;
        this.approvalService = approvalService;
        this.objectMapper = objectMapper;
    }

    @Override
    public java.util.List<org.springframework.ai.tool.definition.ToolDefinition> resolveToolDefinitions(
            org.springframework.ai.model.tool.ToolCallingChatOptions chatOptions) {
        return delegate.resolveToolDefinitions(chatOptions);
    }

    @Override
    public ToolExecutionResult executeToolCalls(Prompt prompt, ChatResponse chatResponse) {
        AssistantMessage assistantMessage = chatResponse.getResults().stream()
                .filter(g -> !g.getOutput().getToolCalls().isEmpty())
                .map(Generation::getOutput)
                .findFirst()
                .orElseThrow(() -> new IllegalStateException("模型没有请求任何工具调用"));

        for (ToolCall call : assistantMessage.getToolCalls()) {
            if (!DANGEROUS_TOOLS.contains(call.name())) {
                continue;
            }
            String applicationId = extractApplicationId(call.arguments());
            ApprovalStatus status = approvalService.statusFor(applicationId);
            switch (status) {
                case APPROVED -> { /* 放行，由 delegate 执行 */ }
                case REJECTED -> {
                    // 拒绝后通道封死：返回"人工否决"工具结果，Agent 不得重试提交（ADR-109）
                    return rejectedResult(prompt, assistantMessage, call,
                            "人工否决：终审提交被审批员拒绝，禁止再次提交");
                }
                case PENDING, EXPIRED -> throw new ApprovalPendingException(
                        approvalService.currentApprovalId(applicationId));
                case NONE -> throw new ApprovalPendingException(
                        approvalService.suspend(applicationId, prompt.getInstructions(), call));
            }
        }
        return delegate.executeToolCalls(prompt, chatResponse);
    }

    private String extractApplicationId(String argumentsJson) {
        try {
            return objectMapper.readTree(argumentsJson).path("applicationId").asText();
        } catch (Exception e) {
            throw new IllegalArgumentException("无法解析终审工具参数: " + argumentsJson, e);
        }
    }

    /** 构造"人工否决"的工具执行结果，回填给模型继续生成（拒绝语义的完整落点）。 */
    private ToolExecutionResult rejectedResult(Prompt prompt, AssistantMessage assistantMessage,
                                               ToolCall call, String message) {
        String json = "{\"status\":\"REJECTED_BY_HUMAN\",\"message\":\"" + message + "\"}";
        ToolResponse response = new ToolResponse(call.id(), call.name(), json);
        ToolResponseMessage responseMessage = ToolResponseMessage.builder()
                .responses(List.of(response))
                .build();
        List<Message> history = new ArrayList<>(prompt.getInstructions());
        history.add(assistantMessage);
        history.add(responseMessage);
        return ToolExecutionResult.builder()
                .conversationHistory(history)
                .returnDirect(false)
                .build();
    }
}
```

### 1.2 挂起用受控异常而不是"等待"

`throw new ApprovalPendingException(approvalId)` 的备选方案是让线程等待审批（轮询/长阻塞）。放弃理由：审批可能 24 小时后来，任何"在原请求里等"的方案都会把连接、内存、线程全拖垮。**挂起 = 持久化状态 + 终止当前流 + 用事件驱动恢复**——这是长任务通用形态（[教程 05-Observation可观测/02-组件交互：Registry、Handler、Convention、Filter协作 §Checkpoint 模式]）。

```java
package com.bank.risk.tool;

/** 受控异常：终止当前生成流，携带 approvalId 供调用方跳转到审批工作台。 */
public class ApprovalPendingException extends RuntimeException {

    private final String approvalId;

    public ApprovalPendingException(String approvalId) {
        super("终审提交已挂起等待人工审批: " + approvalId);
        this.approvalId = approvalId;
    }

    public String getApprovalId() {
        return approvalId;
    }
}
```

调用方用 `onErrorResume` 转为审批挂起响应（不是让请求卡住等）：

```java
// 片段（完整 Controller 见 03-迭代二 §4.15）：挂起不是等待，而是转为审批响应
.onErrorResume(ApprovalPendingException.class, e ->
        Mono.just(Map.of("status", "PENDING_APPROVAL", "approvalId", e.getApprovalId())))
```

### 1.3 为什么比对是字段级而不是文本级

```java
package com.bank.risk.domain;

import java.util.ArrayList;
import java.util.List;
import java.util.Set;
import java.util.stream.Collectors;

/** 字段级结构化比对——完整可手写。 */
public final class CrossValidator {

    public CrossValidationResult compare(PreTrialOpinion a, PreTrialOpinion b) {
        List<CrossValidationResult.FieldDiff> diffs = new ArrayList<>();
        if (a.riskLevel() != b.riskLevel()) {
            diffs.add(new CrossValidationResult.FieldDiff("riskLevel",
                    a.riskLevel().name(), b.riskLevel().name(),
                    CrossValidationResult.DiffSeverity.CRITICAL));
        }
        if (Math.abs(a.confidence() - b.confidence()) > 0.3) {
            diffs.add(new CrossValidationResult.FieldDiff("confidence",
                    String.valueOf(a.confidence()), String.valueOf(b.confidence()),
                    CrossValidationResult.DiffSeverity.MAJOR));
        }
        diffs.addAll(compareRiskFactorDimensions(a.riskFactors(), b.riskFactors()));

        boolean consistent = diffs.stream()
                .noneMatch(d -> d.severity() == CrossValidationResult.DiffSeverity.CRITICAL);
        return new CrossValidationResult(consistent, diffs,
                consistent ? CrossValidationResult.CrossVerdict.ADOPT
                           : CrossValidationResult.CrossVerdict.HUMAN_REVIEW);
    }

    private List<CrossValidationResult.FieldDiff> compareRiskFactorDimensions(
            List<PreTrialOpinion.RiskFactor> a, List<PreTrialOpinion.RiskFactor> b) {
        Set<String> aHigh = a.stream()
                .filter(f -> "high".equals(f.severity()))
                .map(PreTrialOpinion.RiskFactor::dimension)
                .collect(Collectors.toSet());
        Set<String> bHigh = b.stream()
                .filter(f -> "high".equals(f.severity()))
                .map(PreTrialOpinion.RiskFactor::dimension)
                .collect(Collectors.toSet());
        List<CrossValidationResult.FieldDiff> diffs = new ArrayList<>();
        for (String dim : aHigh) {
            if (!bHigh.contains(dim)) {
                diffs.add(new CrossValidationResult.FieldDiff("riskFactor." + dim,
                        "high", "未提及", CrossValidationResult.DiffSeverity.CRITICAL));
            }
        }
        return diffs;
    }
}
```

三个理由：可判定（HIGH≠MEDIUM 是布尔事实）、可审计（分歧清单直接进工作台）、可回溯（字段对应决策依据）。文本相似度三者全无。**凡是结论要进监管流程的比对，必须是结构化比对**。

### 1.4 双通道脱敏的必然性

Prompt 通道要"分析能力"（假名保留指代关系），审计通道要"回放保真"（加密原文）。单通道必然牺牲其一：全脱敏则回放失真，全原文则出域违规。**当同一数据有两个消费方且要求相反时，按消费方分通道是唯一解**——这和事件溯源里"写模型与读模型分离"（CQRS）是同构问题。

### 1.5 预算联动：排队而非降质（两类场景的对比）

| | 业务连续性优先型（营销/客服类场景） | 错误代价不对称型（本项目风控） |
|---|---|---|
| 超预算动作 | 降级到廉价模型 | 收敛触发面 + 排队 |
| 原因 | 业务连续性优先，降质可接受 | 错误代价不对称，降质不可接受 |

两类场景会得出相反的答案——**预算策略没有标准答案，只有与业务风险 profile 匹配的答案**。架构师的价值在于识别"这个业务里，质量与连续性哪个更不可牺牲"。

## 2. 最容易写错的五处

| # | 位置 | 错误写法 | 后果 | 正确 |
|---|------|---------|------|------|
| 1 | 阻塞桥接 | `chatClient.call()` 直接在 Netty 线程跑 | EventLoop 阻塞全线卡死 | `Mono.fromCallable(...).subscribeOn(boundedElastic)` |
| 2 | 双模型并行 | `CompletableFuture` + 固定线程池 | 与 WebFlux 栈背离，线程饥饿 | `Mono.zip + boundedElastic` |
| 3 | 哈希链序列化 | 直接 `toJson(event)` | 序列化不稳定随机断链 | canonical JSON（键排序） |
| 4 | 审批拒绝后 | 允许 Agent 换个措辞重新提交 | 绕过面："提交到碰巧被批" | 拒绝后工具通道对该申请封死 |
| 5 | 假名还原 | 还原接口不鉴权不留痕 | 脱敏形同虚设 | 授权角色 + 每次还原入审计链 |

## 3. 自检清单（照此核对你的手写代码）

- [ ] `ToolCallingManager` 装饰器实现的是 `executeToolCalls(Prompt, ChatResponse)`——不是 `(Prompt, ToolCallingChatOptions, List<ToolDefinition>)`
- [ ] `ToolCall` 从 `Generation.getOutput().getToolCalls()` 取，是 `AssistantMessage.ToolCall` 嵌套 record
- [ ] 结构化输出只用 `entity(Class)` / `entity(ParameterizedTypeReference)`，无 spec-lambda
- [ ] `@Tool` + `@ToolParam`，无 `@ToolMethod`；工具经 `MethodToolCallbackProvider` Bean 显式暴露
- [ ] Advisor 用 `CallAdvisor.adviseCall(ChatClientRequest, CallAdvisorChain)` 或继承 `BaseAdvisor` 实现双参 `before(ChatClientRequest, AdvisorChain)/after(ChatClientResponse, AdvisorChain)`（javap 实证真实存在，2026-08-16）
- [ ] 阻塞调用全部 `subscribeOn(boundedElastic)`，EventLoop 上无 block/Thread.sleep
- [ ] 哈希链用 canonical JSON（`ORDER_MAP_ENTRIES_BY_KEYS`）后哈希
- [ ] 审批拒绝后工具通道封死（REJECTED 状态），Agent 不得重试
- [ ] 假名还原每次入审计链，且审计不记录明文
- [ ] 密钥/Token 全部 `${ENV_VAR}` 或 KMS 引用，无硬编码
