## 为什么需要这个

| 模式 | 体验 |
|------|------|
| 非流式 | 用户提问 → 等 20 秒（白屏）→ 一次性出现全部回复 ❌ |
| 流式 | 用户提问 → 0.5 秒后开始逐字显示 → 像打字机一样 ✅ |

**流式输出是 AI 应用的基本体验要求**。没有流式的 AI 应用，用户会觉得"卡死了"。

## 知识讲解

### 1. SSE（Server-Sent Events）

SSE 是 HTTP 的一种用法：服务器可以持续推送数据给浏览器，而不是等完整响应再返回。

```
普通 HTTP：
  客户端 → 请求 → 服务器
  客户端 ← 完整响应 ← 服务器（等很久）

SSE：
  客户端 → 请求 → 服务器
  客户端 ← data: 第一个 token
  客户端 ← data: 第二个 token
  客户端 ← data: 第三个 token
  ...
  客户端 ← data: [DONE]
```

### 2. Spring AI 的流式 API

```java
// 非流式：等完整回复
String reply = chatClient.prompt().user(q).call().content();

// 流式：逐 token 返回
Flux<String> stream = chatClient.prompt().user(q).stream().content();
```

`.call()` vs `.stream()` 是唯一的区别——返回类型从 `String` 变成 `Flux<String>`。

### 3. Reactor Flux 基础

`Flux<T>` 是 Reactor 的"异步数据流"（0 到 N 个元素的序列）。你可以把它类比为 Java Stream 的异步版本：

```java
Flux<String> tokens = chatClient.prompt().user("你好").stream().content();

tokens
    .doOnNext(token -> System.out.print(token))   // 每来一个 token 打印
    .doOnComplete(() -> System.out.println("\n完成"))  // 全部完成
    .blockLast();  // 阻塞等待结束
```

## 动手实践

### Step 1：流式聊天接口

```java
package demo.demo02.controller;

import org.springframework.ai.chat.client.ChatClient;
import org.springframework.http.MediaType;
import org.springframework.web.bind.annotation.*;
import reactor.core.publisher.Flux;

@RestController
@RequestMapping("/api")
public class StreamChatController {

    private final ChatClient chatClient;

    public StreamChatController(ChatClient chatClient) {
        this.chatClient = chatClient;
    }

    // SSE 流式输出：GET /api/stream?q=你好
    // produces = text/event-stream 告诉浏览器这是 SSE
    @GetMapping(value = "/stream", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
    public Flux<String> stream(@RequestParam String q) {
        return chatClient.prompt()
                .user(q)
                .stream()
                .content();   // 返回 Flux<String>，每个元素是一个 token
    }
}
```

### Step 2：用 curl 测试

```bash
curl -N "http://localhost:8080/api/stream?q=用三句话解释什么是AI"

# 你会看到逐 token 返回（而不是等很久一次性返回）：
# data:AI
# data:是
# data:一
# data:种
# data:能
# ...
```

> `-N` 参数禁用 curl 缓冲，让你看到实时流。

### Step 3：带记忆的流式

```java
@GetMapping(value = "/stream", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
public Flux<String> stream(
        @RequestParam String q,
        @RequestParam(defaultValue = "default") String sessionId) {

    return chatClient.prompt()
            .user(q)
            .advisors(spec -> spec.param(ChatMemory.CONVERSATION_ID, sessionId))
            .stream()
            .content();
}
```

### Step 4：前端 HTML 消费 SSE

```html
<!DOCTYPE html>
<html>
<head>
    <meta charset="UTF-8">
    <title>AI 流式对话</title>
    <style>
        body { font-family: sans-serif; max-width: 800px; margin: 50px auto; }
        #chat { border: 1px solid #ddd; padding: 20px; min-height: 300px; border-radius: 8px; }
        #reply { white-space: pre-wrap; line-height: 1.8; }
        .input-area { margin-top: 15px; display: flex; gap: 10px; }
        input { flex: 1; padding: 10px; font-size: 16px; border-radius: 4px; border: 1px solid #ccc; }
        button { padding: 10px 20px; font-size: 16px; cursor: pointer; }
    </style>
</head>
<body>
    <div id="chat">
        <div id="reply"></div>
    </div>
    <div class="input-area">
        <input id="input" placeholder="输入问题..." onkeypress="if(event.key==='Enter')send()">
        <button onclick="send()">发送</button>
    </div>

    <script>
        async function send() {
            const input = document.getElementById('input');
            const reply = document.getElementById('reply');
            const q = input.value.trim();
            if (!q) return;

            reply.textContent = '';  // 清空上次回复
            input.value = '';

            // EventSource 是浏览器内置的 SSE 客户端
            const es = new EventSource(`/api/stream?q=${encodeURIComponent(q)}`);

            es.onmessage = function(event) {
                reply.textContent += event.data;  // 逐 token 追加
            };

            es.onerror = function() {
                es.close();
            };
        }
    </script>
</body>
</html>
```

把这个文件放到 `src/main/resources/static/chat.html`，然后访问 `http://localhost:8080/chat.html`。

### Step 5：处理流中的工具调用

流式 + 工具调用有个坑：工具调用发生在流中间。Spring AI 会在工具调用期间暂停流，执行工具，然后继续流：

```java
@GetMapping(value = "/stream", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
public Flux<String> streamWithTools(@RequestParam String q) {
    return chatClient.prompt()
            .user(q)
            .tools(timeTools)   // 流式也能调工具
            .stream()
            .content()
            .doOnNext(token -> {
                // 你可以在这里看到工具调用中间状态
                // log.debug("token: {}", token);
            });
}
```

> ⚠️ 如果 LLM 调用工具，`Flux` 会先返回工具调用的中间结果，再返回最终回复。前端需要处理这种情况。

---

## 常见坑

- ❌ **忘记 `produces = MediaType.TEXT_EVENT_STREAM_VALUE`** → 浏览器不当作 SSE 处理
- ❌ **Flux 没人订阅** → 流不会执行。Spring WebFlux 自动处理 HTTP 响应的订阅，但如果你手动操作 Flux 要注意
- ❌ **异常导致流中断** → 用 `onErrorResume` 兜底：
  ```java
  .onErrorResume(e -> Flux.just("\n[出错了：" + e.getMessage() + "]"))
  ```
- ❌ **SSE 不支持 POST** → EventSource 只支持 GET。需要 POST 流式时用 `fetch` + `ReadableStream`
