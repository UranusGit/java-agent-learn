## 知识讲解

### 1. 向量嵌入（Embedding）

把一段文字通过一个模型变成一个固定长度的数字数组：

```
"什么是 AI Agent" → [0.12, 0.85, 0.33, ..., -0.07]   （768 个数字）
"AI 智能体是什么" → [0.11, 0.82, 0.35, ..., -0.05]   （和上面很接近！）
"今天天气不错"     → [0.91, 0.22, 0.77, ..., 0.44]   （和前两个差很远）
```

**为什么相似**：语义相近的文本，向量也相近（在多维空间中距离小）。

### 2. 相似度计算：余弦相似度

两个向量之间的"相似度"用**余弦相似度**衡量——两个向量方向的夹角的余弦值：

```java
// 余弦相似度：-1（完全相反）到 1（完全相同）
static double cosineSimilarity(double[] a, double[] b) {
    double dot = 0, normA = 0, normB = 0;
    for (int i = 0; i < a.length; i++) {
        dot   += a[i] * b[i];
        normA += a[i] * a[i];
        normB += b[i] * b[i];
    }
    return dot / (Math.sqrt(normA) * Math.sqrt(normB));
}
```

### 3. 向量库 vs 传统数据库

| 维度 | 传统数据库（B+ 树） | 向量库 |
|------|-------------------|--------|
| 查询方式 | 精确匹配 `WHERE id = 1` | 相似度匹配 `ORDER BY similarity DESC` |
| 返回结果 | 精确的行 | "最相似"的 K 个（可能不是完全匹配） |
| 索引方式 | B+ 树（精确排序） | HNSW / IVF（近似最近邻） |
| 适用场景 | 结构化数据精确查询 | 语义搜索、推荐 |

> 💡 **类比**：传统数据库是"精确查找"，向量库是"模糊搜索"——它找的不是"完全一样的"，而是"意思最接近的"。

## 动手实践

### Step 1：手写简易向量检索（不依赖任何外部库）

```java
package demo.vector;

import java.util.*;

/**
 * 一个 50 行的简易向量检索器。
 * 不用向量库，不用嵌入模型——手动构造向量来理解原理。
 */
public class SimpleVectorSearch {

    // 一条向量记录
    record DocVector(String id, String text, double[] vector) {}

    // 文档库
    private final List<DocVector> docs = new ArrayList<>();

    // 添加文档
    public void add(String id, String text, double[] vector) {
        docs.add(new DocVector(id, text, vector));
    }

    // 检索最相似的 K 个文档
    public List<DocVector> search(double[] queryVector, int topK) {
        return docs.stream()
                .map(doc -> Map.entry(doc, cosineSimilarity(queryVector, doc.vector())))
                .sorted((a, b) -> Double.compare(b.getValue(), a.getValue()))  // 按相似度降序
                .limit(topK)
                .map(Map.Entry::getKey)
                .toList();
    }

    // 余弦相似度
    static double cosineSimilarity(double[] a, double[] b) {
        double dot = 0, normA = 0, normB = 0;
        for (int i = 0; i < a.length; i++) {
            dot   += a[i] * b[i];
            normA += a[i] * a[i];
            normB += b[i] * b[i];
        }
        return dot / (Math.sqrt(normA) * Math.sqrt(normB));
    }

    public static void main(String[] args) {
        var search = new SimpleVectorSearch();

        // 模拟嵌入向量（实际场景用 embedding 模型生成）
        // 维度 3 只是为了演示，实际是 768 或 1536 维
        search.add("d1", "什么是 AI Agent",           new double[]{0.1, 0.9, 0.2});
        search.add("d2", "AI 智能体原理",              new double[]{0.15, 0.85, 0.25});
        search.add("d3", "如何训练大语言模型",          new double[]{0.8, 0.2, 0.9});
        search.add("d4", "Spring Boot 开发指南",        new double[]{0.7, 0.1, 0.3});
        search.add("d5", "向量数据库选型",             new double[]{0.3, 0.5, 0.8});

        // 查询：和 "AI Agent 是什么" 最相似的文档
        double[] query = {0.12, 0.88, 0.22};  // "AI Agent 是什么" 的向量

        var results = search.search(query, 3);
        System.out.println("查询：AI Agent 是什么");
        for (var doc : results) {
            double score = cosineSimilarity(query, doc.vector());
            System.out.printf("  [%.3f] %s → %s%n", score, doc.id(), doc.text());
        }
    }
}
```

输出：
```
查询：AI Agent 是什么
  [0.999] d1 → 什么是 AI Agent
  [0.996] d2 → AI 智能体原理
  [0.789] d5 → 向量数据库选型
```

> 你可以看到："什么是 AI Agent" 和 "AI 智能体原理" 的相似度最高（0.999 和 0.996），而 "Spring Boot 开发指南" 的相似度很低。这就是语义检索的核心。

### Step 2：用真实的 Embedding 模型

上面的向量是手动构造的。现在用 Spring AI 调用真实的 Embedding 模型：

```java
// 先配置 embedding 模型（application.yml 不需要额外配置，
// spring-ai-starter-model-openai 自带 embedding 能力）

@RestController
@RequestMapping("/api")
public class EmbeddingController {

    private final EmbeddingModel embeddingModel;

    public EmbeddingController(EmbeddingModel embeddingModel) {
        this.embeddingModel = embeddingModel;
    }

    @GetMapping("/embed")
    public Map<String, Object> embed(@RequestParam String text) {
        // 把文本变成向量
        float[] vector = embeddingModel.embed(text);

        return Map.of(
            "text", text,
            "dimensions", vector.length,                    // 维度（如 768 或 1536）
            "first5", Arrays.copyOf(vector, 5),             // 前 5 个值
            "tokenCount", "N/A"                             // embedding 通常也有 token 计费
        );
    }

    @GetMapping("/similarity")
    public Map<String, Object> similarity(
            @RequestParam String text1,
            @RequestParam String text2) {

        float[] v1 = embeddingModel.embed(text1);
        float[] v2 = embeddingModel.embed(text2);

        double sim = cosineSimilarity(v1, v2);

        return Map.of(
            "text1", text1,
            "text2", text2,
            "similarity", Math.round(sim * 1000) / 1000.0,
            "interpretation", sim > 0.85 ? "高度相似" :
                               sim > 0.6  ? "有一定相关性" :
                                            "不太相关"
        );
    }

    private static double cosineSimilarity(float[] a, float[] b) {
        double dot = 0, normA = 0, normB = 0;
        for (int i = 0; i < a.length; i++) {
            dot   += a[i] * b[i];
            normA += a[i] * a[i];
            normB += b[i] * b[i];
        }
        return dot / (Math.sqrt(normA) * Math.sqrt(normB));
    }
}
```

```bash
curl "http://localhost:8080/api/similarity?text1=什么是AI&text2=人工智能是什么"
# {"similarity": 0.892, "interpretation": "高度相似"}

curl "http://localhost:8080/api/similarity?text1=什么是AI&text2=今天吃什么"
# {"similarity": 0.321, "interpretation": "不太相关"}
```

## 常见坑

- ❌ **向量维度不匹配** → 不同 embedding 模型维度不同（768/1024/1536），混用会报错
- ❌ **余弦相似度 vs 欧氏距离** → NLP 一般用余弦相似度（不受向量长度影响）
- ❌ **embedding 也要花钱** → 每次嵌入都按 token 计费，文档量大时注意成本
- ❌ **短文本 vs 长文本** → embedding 对长文本效果会下降。这就是为什么 RAG 要先分块
