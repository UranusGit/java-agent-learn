## 为什么需要这个

> **没有评估 = 玄学。** 改 prompt 不知道变好了还是变差了。换模型不知道效果如何。调参数没有依据。简历上也写不出量化指标。

这是区分"玩 Demo"和"做产品"的分水岭。从现在起，**你对 AI 应用的任何改动都要用评估集验证**。

## 知识讲解

### 1. 评估集（QA Set）

一组"问题 + 期望答案"的测试数据，用来量化你的 AI 应用质量：

```json
[
  {
    "id": "qa-001",
    "question": "公司的报销流程是什么？",
    "expectedAnswer": "填写报销单，附发票，经部门经理审批，财务审核后打款",
    "expectedSourceDoc": "报销制度.pdf",
    "category": "常见问题"
  },
  {
    "id": "qa-002",
    "question": "出差补贴标准是多少？",
    "expectedAnswer": "一线城市 200 元/天，其他城市 150 元/天",
    "expectedSourceDoc": "差旅制度.pdf",
    "category": "常见问题"
  },
  {
    "id": "qa-003",
    "question": "如何编写一个 Python 爬虫？",
    "expectedAnswer": null,
    "expectedSourceDoc": null,
    "category": "反例（文档中没有的信息）"
  }
]
```

**三条原则**：
1. **覆盖三类**：常见问题 / 边界问题 / 反例（文档中没答案的）
2. **最少 30 条**：太少没有统计意义
3. **每条有明确期望**：要么有 expected answer，要么明确标注"应该拒答"

### 2. 三大评估指标

#### 指标 1：Recall@K（检索质量）

**检索到的 Top-K 文档中，有没有正确文档？**

```
用户问题："公司的报销流程"
检索到的 Top-3：
  1. 差旅制度.pdf    ← 不是正确的
  2. 报销制度.pdf    ← ✅ 正确的！
  3. 休假制度.pdf    ← 不是

Recall@3 = 1（有正确文档，命中）
```

```java
// 计算 Recall@K
double recallAtK(List<String> retrievedDocIds, String expectedDocId, int k) {
    List<String> topK = retrievedDocIds.subList(0, Math.min(k, retrievedDocIds.size()));
    return topK.contains(expectedDocId) ? 1.0 : 0.0;
}

// 在整个测试集上取平均
double averageRecall = testSet.stream()
    .mapToLong(qa -> (long) recallAtK(ragService.search(qa.question, K), qa.expectedSourceDoc, K))
    .average().orElse(0);
```

#### 指标 2：Faithfulness（生成质量 / 忠实度）

**LLM 的回答是否忠于检索到的文档？有没有编造？**

用 LLM-as-Judge 来打分：让另一个 LLM 比较"检索到的文档"和"AI 的回答"，判断回答是否完全基于文档。

```java
// LLM-as-Judge：用 LLM 给 LLM 打分
String judgePrompt = """
    你是一个严格的评审。
    判断以下回答是否完全忠于提供的文档内容。
    如果回答中有文档未提及的信息，判定为不忠实。

    文档内容：
    %s

    AI 回答：
    %s

    请输出 JSON：
    {"faithful": true/false, "reason": "判断理由"}
    """.formatted(context, aiAnswer);

// 用一个强模型做评审
String judgment = judgeClient.prompt().user(judgePrompt).call().content();
// 解析 faithful 字段
```

#### 指标 3：人工评分（基准）

最可靠但也最慢的方法：你手动给每条回答打分（1-5 分）。

| 分数 | 标准 |
|------|------|
| 5 | 完美回答，准确无误 |
| 4 | 基本正确，有小瑕疵 |
| 3 | 部分正确，有遗漏 |
| 2 | 大部分错误 |
| 1 | 完全错误或编造 |

> 至少对 20 条做人工标注，作为基准。后续改 prompt/换模型时，对比这 20 条的分数变化。

### 3. A/B 对比方法论

**只改一个变量，跑全集，对比指标**：

| 实验 | 变量 | Recall@5 | Faithfulness | 人工分 |
|------|------|---------|-------------|-------|
| 基线 | chunkSize=500 | 0.82 | 0.75 | 3.8 |
| 实验1 | chunkSize=200 | 0.88 ↑ | 0.70 ↓ | 3.6 ↓ |
| 实验2 | chunkSize=1000 | 0.75 ↓ | 0.80 ↑ | 4.0 ↑ |
| 实验3 | topK=5→3 | 0.70 ↓ | 0.85 ↑ | 4.1 ↑ |

> 从表中可以看出：chunkSize 减小提高检索精确度但降低生成质量（上下文不全）。这就是评估的价值——**用数据说话，不靠感觉**。

## 动手实践

### Step 1：构建测试集

```java
package demo.demo02.eval;

import java.util.*;

public record TestSet(
    String id,
    String question,
    String expectedAnswer,      // null = 应该拒答
    String expectedSourceDoc,   // null = 反例
    String category             // 常见/边界/反例
) {
    // 构建测试集
    public static List<TestSet> buildDefault() {
        return List.of(
            // 常见问题（10 条）
            new TestSet("qa-001", "报销流程是什么？", "填写报销单附发票经审批后打款", "报销制度.pdf", "常见"),
            new TestSet("qa-002", "年假多少天？", "入职满一年5天，满三年10天", "休假制度.pdf", "常见"),
            // ... 补充到至少 10 条

            // 边界问题（10 条）
            new TestSet("qa-011", "试用期可以请病假吗？", "可以，按病假标准", "休假制度.pdf", "边界"),
            // ...

            // 反例（10 条）
            new TestSet("qa-021", "如何用 Python 写爬虫？", null, null, "反例"),
            new TestSet("qa-022", "公司股票代码是什么？", null, null, "反例")
            // ...
        );
    }
}
```

### Step 2：实现评估器

```java
package demo.demo02.eval;

import org.springframework.ai.chat.client.ChatClient;
import org.springframework.stereotype.Service;

import java.util.*;

@Service
public class RagEvaluator {

    private final ChatClient chatClient;
    private final RagService ragService;

    public RagEvaluator(ChatClient chatClient, RagService ragService) {
        this.chatClient = chatClient;
        this.ragService = ragService;
    }

    public EvalResult evaluate(List<TestSet> testSet) {
        int recallHits = 0;
        int faithfulHits = 0;
        int rejectionHits = 0;
        List<Map<String, Object>> details = new ArrayList<>();

        for (var qa : testSet) {
            // 1. 检索
            var docs = ragService.search(qa.question(), 5);
            var docIds = docs.stream().map(d -> d.getMetadata().get("file_name").toString()).toList();

            // 2. 检索质量
            boolean recallHit = qa.expectedSourceDoc() == null
                    || docIds.contains(qa.expectedSourceDoc());
            if (recallHit) recallHits++;

            // 3. 反例处理：应该拒答
            if (qa.expectedAnswer() == null) {
                // LLM 应该说"不知道"
                String reply = askRag(qa.question(), docs);
                boolean rejected = reply.contains("无法回答") || reply.contains("没有相关") || reply.contains("不知道");
                if (rejected) rejectionHits++;
                details.add(Map.of("id", qa.id(), "type", "反例", "rejected", rejected, "reply", reply));
                continue;
            }

            // 4. 生成质量
            String reply = askRag(qa.question(), docs);
            boolean faithful = checkFaithfulness(reply, docs);
            if (faithful) faithfulHits++;

            details.add(Map.of(
                "id", qa.id(),
                "recall", recallHit,
                "faithful", faithful,
                "reply", reply
            ));
        }

        return new EvalResult(
            (double) recallHits / testSet.size(),
            (double) faithfulHits / testSet.size(),
            (double) rejectionHits / testSet.stream().filter(t -> t.expectedAnswer() == null).count(),
            details
        );
    }

    private String askRag(String question, var docs) {
        String context = docs.stream()
                .map(d -> d.getText())
                .reduce("", (a, b) -> a + "\n---\n" + b);
        return chatClient.prompt()
                .system("基于文档回答。文档中没有的就说'根据已有文档无法回答'。\n\n文档：\n" + context)
                .user(question)
                .call().content();
    }

    private boolean checkFaithfulness(String reply, var docs) {
        String context = docs.stream().map(d -> d.getText()).reduce("", (a, b) -> a + "\n" + b);
        String prompt = """
            判断回答是否忠实于文档。文档未提及的信息视为编造。
            只输出 true 或 false。
            文档：%s
            回答：%s""".formatted(context, reply);
        String result = chatClient.prompt().user(prompt).call().content();
        return result != null && result.toLowerCase().contains("true");
    }

    public record EvalResult(
        double recallAt5,
        double faithfulness,
        double rejectionRate,
        List<Map<String, Object>> details
    ) {}
}
```

### Step 3：运行评估

```java
@RestController
@RequestMapping("/api/eval")
public class EvalController {

    private final RagEvaluator evaluator;

    public EvalController(RagEvaluator evaluator) {
        this.evaluator = evaluator;
    }

    @PostMapping("/run")
    public RagEvaluator.EvalResult run() {
        return evaluator.evaluate(TestSet.buildDefault());
    }
}
```

## 常见坑

- ❌ **测试集太小** → 少于 20 条时，一两条的变化就让指标波动 10%+。最少 30 条
- ❌ **只有常见问题** → 忘记反例测试。LLM 对文档中没有的问题可能编造答案
- ❌ **LLM-as-Judge 有位置偏置** → 把好答案放前面和放后面评分可能不同。用随机顺序跑多次取平均
- ❌ **改多个变量** → 一次只改一个。否则不知道是哪个改动导致的差异
- ❌ **评估集泄漏** → 评估集的问题和线上真实分布差异大，导致离线分数高但线上效果差。定期用线上数据更新评估集
- ❌ **LLM-as-Judge 不稳定** → 同一个输入评分两次结果不同。用 `temperature: 0` 并跑 3 次取多数

## 评估集构建清单

| 维度 | 要求 | 示例 |
|------|------|------|
| 常见问题（40%） | 高频、有明确答案 | "报销流程是什么" |
| 边界问题（30%） | 模糊、多义、需要推理 | "试用期可以请病假吗" |
| 反例（30%） | 文档中没有的 → 必须拒答 | "公司股票代码是什么" |
| 最少条数 | 30+ | 统计意义 |
| 标注字段 | question + expected + source + category | 见 TestSet record |
| 更新频率 | 每月从线上日志采样新问题 | 数据飞轮 |

> 评估集从哪来？三条路径：①人工编写 ②线上日志采样 ③LLM 自动生成（用 LLM 从文档反推问答对）。阶段 4 LLMOps 会深入讲第三条。
