## 为什么需要这个

阶段 1 你写了 3 个简单工具。但真实项目里你可能需要 20+ 个工具——查数据库、调外部 API、读写文件、发消息……如果不做体系设计，工具会变成一锅粥：

- 工具描述模糊 → LLM 选错工具
- 工具之间功能重叠 → LLM 困惑
- 工具出错抛异常 → Agent 直接崩溃
- 没有安全防护 → 被 prompt injection 利用执行危险操作

## 知识讲解

### 1. 工具设计三原则

**原则 1：单一职责**

```java
// ❌ 一个工具做太多事，LLM 不知道什么时候用
@Tool(description = "管理用户：增删改查")
public String manageUser(String action, String data) { ... }

// ✅ 每个工具做一件事
@Tool(description = "根据用户ID查询用户信息")
public String getUserById(Long userId) { ... }

@Tool(description = "创建新用户")
public String createUser(String name, String email) { ... }
```

**原则 2：描述清晰（给 LLM 看的说明书）**

```java
// ❌ 描述太模糊
@Tool(description = "搜索")
public String search(String q) { ... }

// ✅ 描述写清做什么、什么时候用、参数含义
@Tool(description = "在公司知识库中搜索相关文档。" +
     "当你需要查找公司制度、产品文档、技术文档时使用。" +
     "query 是搜索关键词，支持中文和英文。")
public String searchKnowledgeBase(String query) { ... }
```

**原则 3：安全第一**

```java
// ❌ 危险：用户可能通过 prompt injection 执行任意命令
@Tool(description = "执行 shell 命令")
public String execShell(String command) {
    return Runtime.getRuntime().exec(command);  // 极其危险！
}

// ✅ 安全：白名单 + 显式拒绝危险字符
@Tool(description = "执行安全的 shell 命令（仅限只读操作）")
public String execSafeShell(String command) {
    // 显式拒绝元字符（绝不用正则——用白名单更安全）
    if (containsDangerousChars(command)) {
        return "错误：命令包含不允许的字符";
    }
    // 设置超时
    // ... 安全执行
}
```

### 2. 工具错误处理：返回错误，不抛异常

> 这是 Agent 工程的核心原则之一：**失败要被 LLM 看到**。

```java
// ❌ 抛异常：Agent 直接崩溃，无法自我修复
@Tool(description = "查询天气")
public String getWeather(String city) {
    if (city.equals("火星")) {
        throw new IllegalArgumentException("不支持的城市");  // 崩溃！
    }
}

// ✅ 返回错误信息：LLM 看到错误后可以自我修正
@Tool(description = "查询天气")
public String getWeather(String city) {
    if (!SUPPORTED_CITIES.contains(city)) {
        return "错误：不支持城市'" + city + "'。支持的城市：" + SUPPORTED_CITIES;
        // LLM 看到后会说："抱歉，不支持查询火星天气，支持查询北京、上海..."
    }
    // 正常查询
}
```

> 💡 **原理**：LLM 会看到工具返回的文本。如果你返回的是错误信息，LLM 会"理解"这个错误并用自然语言向用户解释或重试。这比崩溃好一万倍。

## 动手实践

### Step 1：实现一个安全的工具基类

```java
package demo.demo02.tools;

import java.util.Set;

public abstract class SafeTool {

    // 危险字符白名单检查（Shell 命令专用）
    private static final Set<String> DANGEROUS_PATTERNS = Set.of(
        ";", "&&", "||", "$(", "`", ">", "<", "|", "rm ", "del ", "format "
    );

    protected String validateShellCommand(String command) {
        String lowerCmd = command.toLowerCase();
        for (String pattern : DANGEROUS_PATTERNS) {
            if (lowerCmd.contains(pattern)) {
                return "错误：命令包含不允许的操作符 '" + pattern + "'。仅支持只读命令。";
            }
        }
        return null;  // null = 验证通过
    }

    // 路径遍历防护
    protected String validatePath(String path) {
        if (path.contains("..") || path.startsWith("/etc") || path.startsWith("/root")) {
            return "错误：路径不在允许范围内。";
        }
        return null;
    }

    // 通用错误返回（不抛异常）
    protected String error(String message) {
        return "⚠️ " + message;
    }
}
```

### Step 2：实现一组生产级工具

```java
@Component
public class DatabaseTools extends SafeTool {

    private final JdbcTemplate jdbc;

    public DatabaseTools(JdbcTemplate jdbc) {
        this.jdbc = jdbc;
    }

    @Tool(description = "根据用户ID查询用户信息。userId 是用户ID（正整数）。返回姓名、邮箱、注册时间。")
    public String getUserById(Long userId) {
        if (userId == null || userId <= 0) {
            return error("用户ID必须是正整数");
        }
        try {
            var user = jdbc.queryForMap("SELECT name, email, created_at FROM users WHERE id = ?", userId);
            return "用户：" + user.get("name") + "，邮箱：" + user.get("email") + "，注册：" + user.get("created_at");
        } catch (EmptyResultDataAccessException e) {
            return error("用户ID " + userId + " 不存在");
        } catch (Exception e) {
            return error("查询失败：" + e.getMessage());
        }
    }

    @Tool(description = "根据关键词搜索用户。keyword 是姓名或邮箱的关键词。返回最多 10 条匹配结果。")
    public String searchUsers(String keyword) {
        if (keyword == null || keyword.trim().isEmpty()) {
            return error("搜索关键词不能为空");
        }
        try {
            var list = jdbc.queryForList(
                "SELECT id, name, email FROM users WHERE name LIKE ? OR email LIKE ? LIMIT 10",
                "%" + keyword + "%", "%" + keyword + "%");
            if (list.isEmpty()) return "没有找到匹配 '" + keyword + "' 的用户";
            return list.stream()
                .map(u -> u.get("id") + ": " + u.get("name") + " (" + u.get("email") + ")")
                .collect(Collectors.joining("\n"));
        } catch (Exception e) {
            return error("搜索失败：" + e.getMessage());
        }
    }
}
```

## 常见坑

- ❌ **工具参数太多** → LLM 容易传错参数。超过 4 个参数考虑拆分工具
- ❌ **返回大段 JSON** → 浪费 token。返回精简文本，让 LLM 组织自然语言
- ❌ **工具执行时间太长** → 超过 30 秒 LLM 会超时。长任务用异步 + 轮询
- ❌ **没有输入验证** → LLM 可能传入非法参数。每个参数都做校验

## 验收检查

- [ ] 能写出描述清晰的 @Tool 方法（LLM 能正确选用）
- [ ] 工具出错时返回错误信息而不是抛异常
- [ ] 有输入验证（空值检查、格式检查）
- [ ] 有安全防护（至少做了路径/命令检查）
- [ ] 能解释"为什么工具错误要返回给 LLM"
