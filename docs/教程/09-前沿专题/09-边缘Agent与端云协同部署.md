## 1. 为什么 Agent 要下边缘

云 Agent 的三个硬伤：**网络依赖**（断网即瘫痪）、**延迟**（往返 300ms+ 起步）、**数据出域**（隐私/合规敏感场景）。当场景是门店导购、工厂质检、现场巡检、车载助手——**边缘/端侧不是选项而是前提**。

## 2. 端云五形态

```mermaid
graph LR
    A["①全云"] --> B["②云主边辅<br/>(边缘预处理)"]
    B --> C["③边主云辅<br/>(云端兜底/训练)"]
    C --> D["④边缘自治<br/>(断网独立运行)"]
    D --> E["⑤端侧<br/>(手机/IoT本地)"]
```

| 形态 | 典型场景 | 选型依据 |
|------|---------|---------|
| 全云 | 网页问答/办公助手 | 无低延迟/隐私要求 |
| 云主边辅 | 门店导购（边缘缓存热数据） | 延迟敏感但可短暂降级 |
| 边主云辅 | 工厂质检（边缘推理+云端会诊） | 断网容忍+大模型偶发需要 |
| 边缘自治 | 产线控制/巡检 | 断网必须可用 |
| 端侧 | 隐私助手/车载 | 数据不出设备 |

**选型三问**：断网还能用吗（可用性）？延迟预算多少（体验）？数据能出域吗（合规）？——三问答案直接映射形态。

## 3. 边缘推理栈

| 组件 | 角色 | 要点 |
|------|------|------|
| **Ollama** | 单机轻量推理（边缘节点常用） | 模型管理简单；Spring AI 用 OpenAI 兼容端点接入（`base-url` 指向本地） |
| **vLLM** | 高吞吐服务（边缘机房/私有云） | 批处理+前缀缓存（附录16） |
| **量化** | 模型瘦身（Q4/Q8） | 边缘算力有限的前提；精度换密度 |

```yaml
# 概念配置：边缘节点接入本地 Ollama（OpenAI 兼容）
spring.ai.openai:
  base-url: http://localhost:11434    # 边缘节点本地推理
  api-key: ${ENV_LOCAL_KEY}
```

## 4. 断网自治与降级

边缘自治的核心是**分层降级**（呼应 [30-容错](../04-企业级架构主干/10-容错与弹性设计.md)）：

| 层 | 断网时 |
|----|--------|
| 意图路由 | 本地规则+语义路由照常（23 思想下沉） |
| 推理 | 本地小模型（能力降但可用） |
| 检索 | 本地缓存知识/最近同步的向量分片 |
| 上下文 | 本地窗口（[31-端侧装配](../../项目/31-企业级Agent上下文管理平台/10-端侧与边缘上下文.md)） |
| 云依赖能力 | 显式声明"需联网"并排队（恢复后补办） |

**纪律**：断网降级要**显式告知用户**（"当前离线模式，能力受限"），不是静默装正常。

## 5. 模型分发与灰度

边缘节点的模型更新=分布式变更风险：**分层分发**（云端 registry → 区域仓库 → 节点拉取）+ **灰度**（先 5% 节点验证再全量）+ **回滚**（保留上一版本地包，秒切回）。模型包大（GB 级），要**断点续传 + 带宽预算**（避免更新风暴打满门店专线）。

## 6. 端云分工（记忆/上下文/协作）

- **记忆**：高频个人/设备记忆本地（快+隐私），跨设备同步走云（[25-记忆](06-工业级记忆架构.md) 分层）。
- **上下文**：端侧轻量装配（确定性压缩），网络好时云端接管混合压缩（[31-端云](../../项目/31-企业级Agent上下文管理平台/10-端侧与边缘上下文.md)）。
- **协作**：端侧 Agent 可作为 A2A 节点（AgentCard 标注"边缘/低算力"约束，委托方据此调整，[27-协作](08-Agent间协作协议工程化.md)）。

## 7. 经济账

边缘自建的真实成本：**硬件摊销 + 运维（N 个节点的 N 倍故障面）+ 模型更新带宽**。决策公式：**云端 API 成本 vs 边缘 TCO**——高频低复杂度（质检唤醒词）边缘划算；低频高复杂度（深度分析）云 API 划算（呼应 [44-自建vs商用](../08-架构师进阶/10-多模型协作与供应策略.md)）。

## 8. 适用场景与不适用场景

### 适用场景 ✅
- 断网必须可用的现场（工厂/门店/车载/巡检）。
- 数据不能出域（隐私/合规）。
- 延迟预算 <300ms 的实时交互。

### 不适用场景 ❌
- 网络稳定且无隐私约束的场景（边缘是纯增成本）。
- 需要超大模型能力的任务（边缘算力装不下——应云边协作而非硬端侧）。
- 无运维能力的海量节点（故障面失控——先解决远程运维再谈边缘）。

边缘 Agent 部署 = **五形态选型（断网/延迟/合规三问）+ 推理栈（Ollama/vLLM/量化）+ 分层降级自治 + 模型分发灰度 + 端云分工（记忆/上下文）+ TCO 经济账**。核心纪律：断网降级显式告知；模型更新当变更管理（灰度+回滚）；能用云不硬边。落地完整平台 → [项目29-企业级边缘Agent部署平台](../../项目/29-企业级边缘Agent部署平台/00-需求分析与架构设计.md)。
