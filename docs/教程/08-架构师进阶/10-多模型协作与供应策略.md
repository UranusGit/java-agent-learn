# 10 多模型协作与供应策略
> **定位**：讲透生产级 Agent 的模型编排策略——不同任务用不同模型（推理用强模型、摘要用小模型、Embedding 用专用模型）、多供应商冗余（同一模型多供应商备份）、API Key 池管理（限流配额轮转）、自建 vs 商用决策框架、边缘部署与云模型混合编排。读完这篇，你的 Agent 不再被单一模型绑定，成本可控且高可用。
>
> **读者画像**：正在设计生产级 Agent 架构，需要优化模型选择、降低成本、提高可用性的架构师。

## 1. 为什么要做多模型编排

### 1.1 单一模型的局限性

生产环境中只依赖一个模型存在多个问题：

```mermaid
graph TB
    subgraph 单模型问题["单模型的问题"]
        P1["单点故障——模型 API 挂了全站挂"]
        P2["成本最优不了——所有任务用最贵模型"]
        P3["供应商锁定——迁移成本极高"]
        P4["速率限制——单个 API Key 配额有限"]
        P5["合规限制——数据驻留要求"]
        P6["能力瓶颈——一个模型不可能什么都擅长"]
    end

    style 单模型问题 fill:#ffcdd2
```

### 1.2 多模型编排的价值

| 策略 | 价值 |
|------|------|
| **任务路由** | 简单任务用小模型（便宜快），复杂任务用大模型（贵但好） |
| **供应商冗余** | 主供应商挂了，自动切换备选 |
| **API Key 池** | 多个 Key 轮转，突破单 Key 限流 |
| **混合部署** | 敏感数据用本地模型，非敏感用云模型 |
| **模型降级** | 高负载时自动降级到更小更快的模型 |

### 3.2 模型路由器

```java
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.stereotype.Service;
import java.util.*;

@Service
public class ModelRouter {

    private static final Logger log = LoggerFactory.getLogger(ModelRouter.class);

    private final Map<ModelTier, List<ModelEndpoint>> modelPool;
    private final LoadBalancer loadBalancer;
    private final ComplianceChecker complianceChecker;

    public ModelRouter(List<ModelEndpoint> endpoints,
                       LoadBalancer loadBalancer,
                       ComplianceChecker complianceChecker) {
        this.loadBalancer = loadBalancer;
        this.complianceChecker = complianceChecker;
        this.modelPool = groupByTier(endpoints);
    }

    /**
     * 根据任务类型选择模型
     */
    public Mono<ModelEndpoint> selectModel(TaskType taskType, String userId, String region) {
        ModelTier tier = taskType.tier();
        List<ModelEndpoint> candidates = modelPool.getOrDefault(tier, List.of());

        // 1. 合规过滤——排除不满足数据驻留要求的模型
        List<ModelEndpoint> compliant = candidates.stream()
            .filter(ep -> complianceChecker.isCompliant(ep, region))
            .toList();

        if (compliant.isEmpty()) {
            return Mono.error(new NoAvailableModelException(
                "没有满足合规要求的模型 for tier=" + tier + ", region=" + region));
        }

        // 2. 健康过滤——排除不可用的端点
        List<ModelEndpoint> healthy = compliant.stream()
            .filter(ModelEndpoint::healthy)   // record 布尔字段访问器是 healthy()，不是 isHealthy()
            .filter(ep -> ep.hasAvailableKey())
            .toList();

        if (healthy.isEmpty()) {
            // 尝试降级到更低的 tier
            return fallbackToLowerTier(tier, userId, region);
        }

        // 3. 负载均衡——从候选中选一个
        return Mono.just(loadBalancer.select(healthy));
    }

    private Map<ModelTier, List<ModelEndpoint>> groupByTier(List<ModelEndpoint> endpoints) {
        Map<ModelTier, List<ModelEndpoint>> pool = new EnumMap<>(ModelTier.class);
        for (ModelEndpoint ep : endpoints) {
            pool.computeIfAbsent(ep.tier(), k -> new ArrayList<>()).add(ep);
        }
        return pool;
    }

    private Mono<ModelEndpoint> fallbackToLowerTier(ModelTier tier,
                                                      String userId, String region) {
        ModelTier fallback = switch (tier) {
            case PREMIUM -> ModelTier.STANDARD;
            case STANDARD -> ModelTier.LIGHT;
            default -> null;
        };

        if (fallback == null) {
            return Mono.error(new NoAvailableModelException("所有模型均不可用"));
        }

        log.warn("Tier {} 无可用模型，降级到 {}", tier, fallback);
        return selectModel(forTier(fallback), userId, region);
    }

    /** 把降级目标 tier 映射回一个代表性任务类型，复用 selectModel 的完整过滤逻辑 */
    private TaskType forTier(ModelTier tier) {
        return switch (tier) {
            case PREMIUM -> TaskType.COMPLEX_REASONING;
            case STANDARD -> TaskType.TRANSLATION;
            case LIGHT -> TaskType.SUMMARIZATION;
            case EMBEDDING -> TaskType.EMBEDDING;
            case LOCAL -> TaskType.SENSITIVE_QUERY;
        };
    }
}

/** 合规过滤服务（示意）——按数据驻留要求判断端点是否可用 */
interface ComplianceChecker {
    boolean isCompliant(ModelEndpoint ep, String region);
}

/** 无可用模型（自定义业务异常） */
class NoAvailableModelException extends RuntimeException {
    public NoAvailableModelException(String message) { super(message); }
}
```

### 3.3 负载均衡策略

```java
import org.springframework.stereotype.Component;
import java.util.Comparator;
import java.util.List;
import java.util.concurrent.ThreadLocalRandom;

public interface LoadBalancer {
    ModelEndpoint select(List<ModelEndpoint> candidates);
}

/**
 * 加权随机——按权重分配流量
 */
@Component("weightedLoadBalancer")
public class WeightedLoadBalancer implements LoadBalancer {

    @Override
    public ModelEndpoint select(List<ModelEndpoint> candidates) {
        int totalWeight = candidates.stream()
            .mapToInt(ModelEndpoint::weight)
            .sum();

        int random = ThreadLocalRandom.current().nextInt(totalWeight);
        int cumulative = 0;

        for (ModelEndpoint ep : candidates) {
            cumulative += ep.weight();
            if (random < cumulative) return ep;
        }

        return candidates.get(candidates.size() - 1);
    }
}

/**
 * 最低延迟优先——选择响应最快的模型
 */
@Component("latencyLoadBalancer")
public class LatencyLoadBalancer implements LoadBalancer {

    @Override
    public ModelEndpoint select(List<ModelEndpoint> candidates) {
        return candidates.stream()
            .min(Comparator.comparingDouble(ModelEndpoint::getAvgLatencyMs))
            .orElse(candidates.get(0));
    }
}

/**
 * 最低成本优先——选择最便宜的模型
 */
@Component("costLoadBalancer")
public class CostLoadBalancer implements LoadBalancer {

    @Override
    public ModelEndpoint select(List<ModelEndpoint> candidates) {
        return candidates.stream()
            .min(Comparator.comparingDouble(ModelEndpoint::getCostPerToken))
            .orElse(candidates.get(0));
    }
}
```

### 4.2 自动故障切换

```java
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.stereotype.Service;
import org.springframework.web.reactive.function.client.WebClient;
import reactor.core.publisher.Mono;
import java.time.Duration;
import java.util.List;
import java.util.Map;

@Service
public class FailoverChatClient {

    private static final Logger log = LoggerFactory.getLogger(FailoverChatClient.class);

    private final ModelRouter modelRouter;

    public FailoverChatClient(ModelRouter modelRouter) {
        this.modelRouter = modelRouter;
    }

    /**
     * 调用 LLM——自动故障切换
     */
    public Mono<String> call(TaskType taskType, String prompt, String userId, String region) {
        return modelRouter.selectModel(taskType, userId, region)
            .flatMap(endpoint -> doCallWithFailover(endpoint, taskType, prompt, userId, region));
    }

    private Mono<String> doCallWithFailover(ModelEndpoint endpoint, TaskType taskType,
                                             String prompt, String userId, String region) {
        return doCall(endpoint, prompt)
            .timeout(Duration.ofSeconds(30))
            // 失败时记录并切换（ModelEndpoint 是不可变 record，不能直接改 healthy——
            // 生产环境把健康状态放到独立的 HealthRegistry，由心跳/错误计数驱动）
            .doOnError(error -> log.warn("端点 {} 调用失败：{}", endpoint.name(), error.getMessage()))
            // 故障切换——选择另一个端点重试
            .onErrorResume(error -> {
                log.info("故障切换：从 {} 切换到备选模型", endpoint.name());
                return modelRouter.selectModel(taskType, userId, region)
                    .filter(newEndpoint -> !newEndpoint.name().equals(endpoint.name()))
                    .flatMap(newEndpoint -> doCall(newEndpoint, prompt)
                        .doOnNext(result -> log.info(
                            "故障切换成功：{} → {}", endpoint.name(), newEndpoint.name()))
                    );
            });
    }

    private Mono<String> doCall(ModelEndpoint endpoint, String prompt) {
        // 从 Key 池获取一个可用的 Key
        ApiKey key = endpoint.acquireKey();

        return WebClient.create(endpoint.baseUrl())
            .post()
            .uri("/v1/chat/completions")
            .header("Authorization", "Bearer " + key.value())
            .bodyValue(Map.of(
                "model", endpoint.modelName(),
                "messages", List.of(Map.of("role", "user", "content", prompt))
            ))
            .retrieve()
            .bodyToMono(String.class)
            .doFinally(signal -> key.release());
    }
}
```

### 4.3 用 Spring AI 原生 API 构建模型端点

上面的 `ModelEndpoint` 记录是"路由元数据"；真正发起调用时，每个端点最终要对应一个 Spring AI 的 `ChatModel` / `ChatClient`。用真实 API（javap 实证）把模型端点变成可注入的 `ChatClient` Bean：

```java
import org.springframework.ai.chat.client.ChatClient;
import org.springframework.ai.deepseek.DeepSeekChatModel;
import org.springframework.ai.deepseek.DeepSeekChatOptions;
import org.springframework.ai.deepseek.api.DeepSeekApi;
import org.springframework.ai.openai.OpenAiChatModel;
import org.springframework.ai.openai.OpenAiChatOptions;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class ModelChatClientConfig {

    @Bean
    public ChatClient openAiGpt4oClient() {
        OpenAiChatModel model = OpenAiChatModel.builder()
            .options(OpenAiChatOptions.builder()
                .model("gpt-4o")                 // model(String) 来自继承的 ToolCallingChatOptions.Builder（javap 实证）
                .temperature(0.2)
                .build())
            .build();
        return ChatClient.create(model);         // 2.0 入口：ChatClient.create(ChatModel)
    }

    @Bean
    public ChatClient deepseekClient() {
        DeepSeekChatModel model = DeepSeekChatModel.builder()
            .options(DeepSeekChatOptions.builder()
                // 注意：DeepSeek 的 model() 收枚举 DeepSeekApi.ChatModel，不是 String（javap 实证）
                .model(DeepSeekApi.ChatModel.DEEPSEEK_CHAT)
                .build())
            .build();
        return ChatClient.create(model);
    }
}
```

- **DeepSeek 坐标**：官方 starter 是 `spring-ai-deepseek`（`org.springframework.ai.deepseek.DeepSeekChatModel` / `DeepSeekChatOptions`，javap 实证）；也可以用 `spring-ai-starter-model-openai` 配 `spring.ai.openai.base-url/api-key/model` 走 OpenAI 兼容通道。
- **熔断/降级**：重试与熔断建议用 Resilience4j——第三方库，真实坐标 `io.github.resilience4j:resilience4j-spring-boot3`（需在 pom.xml 添加依赖），用 `@CircuitBreaker` 包裹 ChatClient 调用，与上面的 `FailoverChatClient` 互补。
- **LiteLLM 等聚合网关**：把多供应商聚合成一个 OpenAI 兼容端点（[LiteLLM 官网](https://docs.litellm.ai/)），`ModelRouter` 只需维护一个 `baseUrl` 指向网关的端点，密钥与路由交给网关——适合团队不想自维护多供应商的场景。

### 5.1 为什么要 Key 池

### 5.2 Key 池实现

```java
import org.springframework.stereotype.Component;
import java.util.*;
import java.util.concurrent.*;
import java.util.concurrent.atomic.AtomicInteger;

@Component
public class ApiKeyPool {

    private final Map<String, List<ManagedKey>> pools = new ConcurrentHashMap<>();

    /**
     * 注册 Key 池
     */
    public void registerPool(String poolName, List<String> keys, int rateLimitPerMinute) {
        List<ManagedKey> managedKeys = keys.stream()
            .map(key -> new ManagedKey(key, rateLimitPerMinute))
            .toList();
        pools.put(poolName, new CopyOnWriteArrayList<>(managedKeys));
    }

    /**
     * 获取一个可用的 Key——选择使用量最低的
     */
    public Optional<ManagedKey> acquireKey(String poolName) {
        List<ManagedKey> keys = pools.get(poolName);
        if (keys == null || keys.isEmpty()) return Optional.empty();

        // 清理过期计数
        keys.forEach(ManagedKey::resetIfExpired);

        // 选择使用量最低且可用的 Key
        return keys.stream()
            .filter(ManagedKey::isAvailable)
            .min(Comparator.comparingInt(ManagedKey::getCurrentUsage))
            .map(key -> {
                key.incrementUsage();
                return key;
            });
    }

    /**
     * 标记 Key 被限流——暂时禁用
     */
    public void markRateLimited(String poolName, String keyValue, Duration cooldown) {
        pools.getOrDefault(poolName, List.of()).stream()
            .filter(k -> k.value.equals(keyValue))
            .findFirst()
            .ifPresent(key -> key.markRateLimited(cooldown));
    }

    /** 所有 Key 池名称——供监控扫描 */
    public Set<String> getPoolNames() {
        return pools.keySet();
    }

    /** 某个池的全部 Key——供监控统计可用/限流数量 */
    public List<ManagedKey> getKeys(String poolName) {
        return pools.getOrDefault(poolName, List.of());
    }

    public static class ManagedKey {
        private final String value;
        private final int rateLimitPerMinute;
        private final AtomicInteger currentUsage = new AtomicInteger(0);
        private volatile long windowStart = System.currentTimeMillis();
        private volatile long rateLimitedUntil = 0;

        public ManagedKey(String value, int rateLimitPerMinute) {
            this.value = value;
            this.rateLimitPerMinute = rateLimitPerMinute;
        }

        public boolean isAvailable() {
            if (System.currentTimeMillis() < rateLimitedUntil) return false;
            resetIfExpired();
            return currentUsage.get() < rateLimitPerMinute;
        }

        public void incrementUsage() {
            currentUsage.incrementAndGet();
        }

        public int getCurrentUsage() {
            return currentUsage.get();
        }

        public void resetIfExpired() {
            long now = System.currentTimeMillis();
            if (now - windowStart > 60_000) {  // 1 分钟窗口
                currentUsage.set(0);
                windowStart = now;
            }
        }

        public void markRateLimited(Duration cooldown) {
            rateLimitedUntil = System.currentTimeMillis() + cooldown.toMillis();
        }

        public String getValue() { return value; }

        /** 是否处于限流冷却期 */
        public boolean isRateLimited() {
            return System.currentTimeMillis() < rateLimitedUntil;
        }
    }
}
```

```java
import io.micrometer.core.instrument.MeterRegistry;
import io.micrometer.core.instrument.Tags;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.scheduling.annotation.Scheduled;
import org.springframework.stereotype.Component;
import java.util.List;

@Component
public class ApiKeyPoolMonitor {

    private static final Logger log = LoggerFactory.getLogger(ApiKeyPoolMonitor.class);

    private final ApiKeyPool keyPool;
    private final MeterRegistry meterRegistry;
    private final AlertService alertService;

    public ApiKeyPoolMonitor(ApiKeyPool keyPool, MeterRegistry meterRegistry,
                             AlertService alertService) {
        this.keyPool = keyPool;
        this.meterRegistry = meterRegistry;
        this.alertService = alertService;
    }

    @Scheduled(fixedRate = 30_000)
    public void reportKeyPoolStatus() {
        for (String poolName : keyPool.getPoolNames()) {
            List<ApiKeyPool.ManagedKey> keys = keyPool.getKeys(poolName);
            int available = (int) keys.stream()
                .filter(ApiKeyPool.ManagedKey::isAvailable).count();
            int rateLimited = (int) keys.stream()
                .filter(ApiKeyPool.ManagedKey::isRateLimited).count();

            meterRegistry.gauge("apikey.pool.available",
                Tags.of("pool", poolName), available);
            meterRegistry.gauge("apikey.pool.ratelimited",
                Tags.of("pool", poolName), rateLimited);

            if (available == 0) {
                log.error("Key 池 {} 所有 Key 都不可用！", poolName);
                alertService.sendAlert(AlertLevel.CRITICAL,
                    String.format("API Key 池 %s 耗尽", poolName));
            }
        }
    }
}
```

## 6. 模型准入与供应商尽调

前面几节假设模型已经在路由表里——但一个新模型（或新供应商）凭什么能进路由表？企业级多模型体系的入口如果没有门槛，路由表会被"谁新接谁"式地污染：一个未经验证的模型带着幻觉率超标、数据留存政策不明、SLA 赔付缺失进来，故障切换时它恰恰是首选备胎。**模型准入（Model Onboarding）是多模型体系的第一个治理闸门**，与模型卡片、AI 治理框架（[教程 08-架构师进阶/09-Agent治理与合规框架]）的关系是：治理定标准，准入是执行标准的流程。

### 6.1 准入流程：四阶段闸门

```mermaid
flowchart TD
    REQ["业务方/平台发起<br/>新模型接入申请"] --> G1{"闸门1：供应商尽调<br/>（文档审查）"}
    G1 -->|"数据留存/训练用途/<br/>法规管辖/SLA 赔付条款<br/>任一不过"| STOP1["拒绝或法务介入"]
    G1 -->|"通过"| G2{"闸门2：技术评估<br/>（评测集跑分）"}
    G2 -->|"金标准集上效果/延迟/<br/>成本三项达标"| G3{"闸门3：安全红队<br/>（对抗样本+护栏兼容）"}
    G3 -->|"通过"| G4["闸门4：灰度接入<br/>（影子流量→小流量→全量）"]
    G4 --> REG["登记进模型注册表<br/>（路由表唯一来源）"]
    STOP1 --> ARCH["归档尽调报告"]
```

四个闸门的要点：

1. **供应商尽调（闸门 1，文档审查）**：核心六问——训练数据是否用我的输入再训练？数据留存期与删除方式（呼应 [教程 04-企业级架构主干/05-历史记录持久化与合规] 的 GDPR 留存要求）？法规管辖地与数据出境？SLA 的可用性承诺与赔付条款？价格调整通知期？退出时的数据导出义务？这六问的答案决定该模型能承载哪些密级的数据
2. **技术评估（闸门 2）**：用**自家金标准评测集**跑分（不是排行榜——评测集资产治理见 [教程 08-架构师进阶/03-自我反思与Agent评估 §7]），三项达标线：效果不低于现役模型同任务水平、p95 延迟在任务预算内、单次成本在任务预算内
3. **安全红队（闸门 3）**：对抗样本（注入/越狱用例库，见 [附录 08-Agent安全深度/04-红队与对抗测试方法论]）上的表现 + 与现有护栏（输入输出审核）的兼容性——有的模型输出格式会绕过基于正则的输出护栏
4. **灰度接入（闸门 4）**：影子流量（只记录不返回）→ 5% 真实流量 → 全量，复用体系灰度发布设施（[教程 04-企业级架构主干/09-灰度发布与版本管理]），指标异常自动回切

四道闸门里，闸门 1 的六问是"问出答案"，答案落到合同上才算数——SLA 的测法怎么审、DPA 条款怎么卡、退出义务怎么写死，见 [附录 12-AI治理与合规/06-模型供应商合同与SLA审查]。

### 6.2 模型注册表：路由表的唯一合法来源

准入通过的模型进**模型注册表**（Model Registry）——一份随版本管理的登记，记录：模型标识与版本、供应商与合同要点、准许的数据密级、评测基线快照、路由权重、准入日期与复审周期。路由器（§3.2）只从注册表读候选，禁止任何硬编码模型名——这样"下架一个模型"是改注册表一处，而不是全代码库搜替换。注册表还要带**复审周期**（如每半年重跑闸门 2 的评测集）：模型供应商会静默更新端点，基线漂移要靠复审发现。

### 6.3 供应商退出预案

尽调时就要写下退出预案：数据导出格式与义务、切换到替代模型的评估成本、双供应商的冗余是否已覆盖（§4）。退出预案写不出来（如供应商不承诺数据导出）本身就是尽调不通过的信号——供应商锁定风险在准入时评估，比在生产事故时发现便宜一百倍。

## 7. 自建 vs 商用决策框架

### 7.1 决策矩阵

| 维度 | 商用 API（GPT-4o 等） | 自建部署（Llama3/Qwen） |
|------|---------------------|----------------------|
| **初始成本** | 极低（按量付费） | 高（GPU 服务器） |
| **边际成本** | 持续按 Token 付费 | 固定成本（电费+折旧） |
| **质量** | 最高（GPT-4o / Claude 3.5） | 中上（Llama3-70B / Qwen） |
| **延迟** | 300-2000ms（网络） | 50-500ms（本地） |
| **数据隐私** | 数据需发送到外部 | 数据完全自控 |
| **合规** | 需满足数据驻留 | 天然满足 |
| **可用性** | 依赖供应商 SLA | 自主控制 |
| **定制化** | 有限（微调受限） | 完全可控（任意微调） |
| **运维复杂度** | 极低 | 高（需要 MLOps 团队） |

### 7.3 成本估算

```java
import org.springframework.stereotype.Service;

@Service
public class CostEstimator {

    /**
     * 估算商用 API 月成本
     */
    public double estimateApiCost(int dailyCalls, int avgInputTokens,
                                   int avgOutputTokens, double pricePerMillionTokens) {
        int monthlyTokens = (avgInputTokens + avgOutputTokens) * dailyCalls * 30;
        return (monthlyTokens / 1_000_000.0) * pricePerMillionTokens;
    }

    /**
     * 估算自建部署月成本
     */
    public double estimateSelfHostedCost(int dailyCalls, String gpuType) {
        // GPU 服务器月租费
        double gpuMonthlyCost = switch (gpuType) {
            case "A100-80GB" -> 15_000;  // 约 15000 元/月
            case "A100-40GB" -> 8_000;
            case "A6000" -> 5_000;
            case "RTX-4090" -> 2_000;
            default -> 5_000;
        };

        // 运维成本（MLOps 工程师时间分摊）
        double opsCost = 10_000;

        return gpuMonthlyCost + opsCost;
    }

    /**
     * 盈亏平衡点——日调用量达到多少时自建更划算
     */
    public int breakEvenPoint(double pricePerMillionTokens,
                              int avgTokensPerCall, double monthlySelfHostedCost) {
        double dailyApiCost = avgTokensPerCall * pricePerMillionTokens / 1_000_000;
        return (int) (monthlySelfHostedCost / 30 / dailyApiCost);
    }
}
```

### 8.2 混合编排策略

```java
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.stereotype.Service;
import reactor.core.publisher.Mono;
import java.time.Duration;

@Service
public class HybridModelOrchestrator {

    private static final Logger log = LoggerFactory.getLogger(HybridModelOrchestrator.class);

    private final ModelGateway cloudGateway;   // 云模型网关（OpenAI/Azure/DeepSeek 等）
    private final ModelGateway localGateway;   // 本地模型网关（Ollama / vLLM）
    private final DataSanitizer dataSanitizer;

    public HybridModelOrchestrator(ModelGateway cloudGateway, ModelGateway localGateway,
                                   DataSanitizer dataSanitizer) {
        this.cloudGateway = cloudGateway;
        this.localGateway = localGateway;
        this.dataSanitizer = dataSanitizer;
    }

    /**
     * 敏感数据路由到本地模型，普通数据路由到云模型
     */
    public Mono<String> chat(ChatRequest request) {
        // 1. 检查输入是否包含敏感数据
        DataSanitizer.SanitizationResult sanitization =
            dataSanitizer.sanitize(request.message());

        if (sanitization.hasSensitiveData() && !sanitization.canSanitize()) {
            // 无法脱敏的敏感数据——必须用本地模型
            log.info("检测到不可脱敏的敏感数据，路由到本地模型");
            return callLocalModel(request.message());
        }

        // 2. 根据任务复杂度路由
        TaskType taskType = classifyTask(request.message());

        if (taskType == TaskType.COMPLEX_REASONING) {
            // 复杂推理——用云端的强模型
            return callCloudModel(request.message(), ModelTier.PREMIUM);
        } else if (taskType == TaskType.SIMPLE_QA) {
            // 简单问答——用本地模型（延迟低，免费）
            return callLocalModel(request.message());
        } else {
            // 标准任务——用云端标准模型
            return callCloudModel(request.message(), ModelTier.STANDARD);
        }
    }

    /**
     * 云模型降级到本地模型
     */
    private Mono<String> callCloudModel(String message, ModelTier tier) {
        return cloudGateway.call(message, tier)
            .timeout(Duration.ofSeconds(15))
            .onErrorResume(error -> {
                log.warn("云模型不可用，降级到本地模型：{}", error.getMessage());
                return callLocalModel(message);
            });
    }

    private Mono<String> callLocalModel(String message) {
        return localGateway.call(message)
            .onErrorResume(error -> Mono.just(
                "本地模型也不可用，请稍后重试"));
    }

    /** 任务复杂度分类（示意）——生产可按意图识别服务或规则引擎 */
    private TaskType classifyTask(String message) {
        return message.length() > 50 ? TaskType.COMPLEX_REASONING : TaskType.SIMPLE_QA;
    }
}

/** 模型网关抽象——云/本地各一个实现 */
interface ModelGateway {
    Mono<String> call(String message);
    Mono<String> call(String message, ModelTier tier);
}

/** 数据脱敏（示意）——真实实现见教程 05-Observation可观测/10-观测测试与跨服务传播：TestObservationRegistry与trace透传 §4.3 DataSanitizer */
class DataSanitizer {
    record SanitizationResult(boolean hasSensitiveData, boolean canSanitize) {}

    SanitizationResult sanitize(String input) {
        boolean sensitive = input.contains("身份证") || input.contains("手机号");
        // 示意：包含敏感词即认为"不可脱敏"（真实实现支持可脱敏的 PII 类型）
        return new SanitizationResult(sensitive, !sensitive);
    }
}

/** 聊天请求体 */
record ChatRequest(String message) {}
```

## 10. 适用场景与不适用场景

### 适用场景

- 生产级 Agent（需要高可用、低成本）
- 多业务场景 Agent（不同任务不同模型）
- 合规要求高的场景（数据驻留）
- 高流量场景（需要 API Key 池突破限流）
- 成本敏感的场景（简单任务用小模型省钱）

### 不适用场景

- 原型/Demo 阶段（直接用一个模型更简单）
- 调用量极低的场景（单模型就够了）
- 团队没有 MLOps 能力（混合部署运维复杂）
- 对延迟要求极端（多一层路由增加延迟）

## 11. 本章总结

| 概念 | 一句话 |
|------|--------|
| **任务路由** | 不同任务用不同模型——推理用强模型，摘要用小模型 |
| **模型分层** | PREMIUM / STANDARD / LIGHT / EMBEDDING / LOCAL 五层 |

| **负载均衡** | 加权随机 / 最低延迟 / 最低成本三种策略 |
| **自建 vs 商用** | 数据敏感度 + 调用量 + 延迟要求决定 |
| **模型准入** | 供应商尽调→技术评估→安全红队→灰度四闸门，注册表是路由表唯一来源 |
| **边缘部署** | Ollama（简单）/ vLLM（高性能）本地模型 |
| **混合编排** | 敏感数据走本地，普通数据走云端，自动降级 |
