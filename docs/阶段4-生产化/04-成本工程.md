## 四层成本优化

> 来源：[行业调研](../调研/00-Agent架构师行业调研-2026.md)——完整上下文工程可降本 10x

```
L1: Prompt Cache     → 缓存固定部分，第二次起省 90%  （最简单最有效）
L2: 语义缓存          → 语义相同的问题直接返回缓存结果
L3: 模型路由          → 简单问题走小模型，复杂问题走大模型
L4: 上下文裁剪        → 裁剪不必要的历史和工具定义
```

| 层级 | 实现难度 | 节省效果 | 优先级 |
|------|---------|---------|-------|
| L1 Prompt Cache | ⭐ | 50-90% | **先做这个** |
| L2 语义缓存 | ⭐⭐ | 20-40% | 第二 |
| L3 模型路由 | ⭐⭐ | 30-60% | 第三 |
| L4 上下文裁剪 | ⭐⭐⭐ | 10-30% | 第四 |

## 动手实践

### L1：Prompt Cache

```java
// 把 system prompt 标记为可缓存（DeepSeek/Anthropic 支持）
// 关键：保持 system prompt 不变，把动态部分放 user message

// ✅ 固定 system prompt（可缓存）
String FIXED_SYSTEM = "你是一个客服助手。公司编码规范：...（5000 字固定内容）";

// ❌ 不要在 system prompt 里拼接动态内容
String BAD_SYSTEM = "你是一个客服助手。当前用户：" + userName;  // 每次不同→缓存失效
```

### L2：语义缓存

```java
@Component
public class SemanticCache {

    // 用户问题 → embedding → 查缓存 → 命中则直接返回
    public Optional<String> get(String query) {
        float[] queryVec = embeddingModel.embed(query);

        // 在缓存中找相似度 > 0.95 的
        return cacheStore.values().stream()
            .filter(entry -> cosineSimilarity(queryVec, entry.vector()) > 0.95)
            .map(entry -> entry.reply())
            .findFirst();
    }

    public void put(String query, String reply) {
        float[] vec = embeddingModel.embed(query);
        cacheStore.put(query, new CacheEntry(vec, reply));
    }
}
```

### L3：模型路由

```java
@Component
public class ModelRouter {

    // 用小模型判断复杂度，路由到不同模型
    public String route(String query) {
        // 简单问题（天气/时间/翻译）→ 用便宜模型
        if (isSimple(query)) return chatClient_small.prompt().user(query).call().content();

        // 复杂问题（代码/推理/写作）→ 用强模型
        return chatClient_large.prompt().user(query).call().content();
    }
}
```

## L3 模型路由决策表

| 问题特征 | 路由到 | 理由 |
|---------|-------|------|
| 简单问答（天气/时间/翻译） | 小模型（如 deepseek-chat） | 成本低、速度快 |
| 代码生成/多步推理 | 强模型（如 deepseek-reasoner） | 质量优先 |
| 闲聊/打招呼 | 小模型 | 不需要推理能力 |
| RAG 问答 | 中等模型 | 需要理解文档但不需要强推理 |
| Agent 多步任务 | 强模型 | 需要规划和决策 |

### 路由策略实现（分类器 + 规则混合）

```java
@Component
public class ModelRouter {

    public enum Tier { CHEAP, STANDARD, PREMIUM }

    // 规则优先（速度快），规则不中再用 LLM 分类
    public Tier route(String query) {
        // 规则 1：超短输入 → CHEAP
        if (query.length() < 10) return Tier.CHEAP;

        // 规则 2：关键词匹配
        if (query.contains("翻译") || query.contains("总结")) return Tier.CHEAP;
        if (query.contains("代码") || query.contains("调试") || query.contains("架构")) return Tier.PREMIUM;

        // 规则 3：默认 STANDARD
        return Tier.STANDARD;
    }

    // 使用时按 Tier 选择不同 ChatClient
    public String ask(String query) {
        return switch (route(query)) {
            case CHEAP    -> cheapClient.prompt().user(query).call().content();
            case STANDARD -> standardClient.prompt().user(query).call().content();
            case PREMIUM  -> premiumClient.prompt().user(query).call().content();
        };
    }
}
```

> 路由策略不需要完美——80% 的准确率就能省 50%+ 成本。路由本身也有成本（如果用 LLM 分类），所以规则优先。

## 随堂练习：语义缓存加速器（60 分钟）

实现语义缓存：语义相同的问题直接返回缓存。

**需求**：
```
第1次 "什么是RAG"       → 调 LLM → 缓存结果
第2次 "RAG是什么"        → 命中缓存（省 100% token）
第3次 "怎么写Java爬虫"   → 不命中 → 调 LLM
```

**提示**：用 EmbeddingModel 把 query 转向量，在缓存中找相似度 > 0.92 的条目。加 `/api/cache/stats` 查看命中率。

**扩展**：加 TTL 过期；加缓存大小限制（LRU 淘汰）。
