# stateDiagram-v2（状态图）

画状态机、生命周期、状态流转。订单状态机、任务状态迁移等场景最常用。

## 基础模板

````markdown
```mermaid
stateDiagram-v2
    [*] --> 待支付
    待支付 --> 已支付 : 支付成功
    待支付 --> 已取消 : 超时未支付
    已支付 --> 已完成 : 确认收货
    已支付 --> 退款中 : 申请退款
    退款中 --> 已关闭 : 退款完成
    已完成 --> [*]
    已关闭 --> [*]
```
````

- **必须用 `stateDiagram-v2`**（v1 已废弃）。
- `[*]` 是开始 / 结束伪状态。开始写在第一个 `-->` 的左边，结束写在最后。
- 迁移标签用冒号：`状态1 --> 状态2 : 触发条件`。
- 状态名直接用中文即可，无需引号（含特殊字符时才加）。

## 复合状态（子状态机）

````markdown
```mermaid
stateDiagram-v2
    [*] --> 运行中
    state 运行中 {
        [*] --> 初始化
        初始化 --> 就绪
        就绪 --> 忙碌 : 收到任务
        忙碌 --> 就绪 : 任务完成
    }
    运行中 --> [*] : 停止
```
````

- 复合状态用 `state 名称 { ... }` 包裹，内部同样有自己的一对 `[*]`。

## 状态定义与标签

- 显式定义状态并加描述：`state "处理中 (耗时)" as processing`，之后用 `processing` 引用。
- 给状态加内部注释：
  ````markdown
  ```mermaid
  stateDiagram-v2
      state 待支付 {
          note right of 待支付
              等待用户完成支付
          end note
      }
      [*] --> 待支付
  ```
  ````

## 常见坑

| 坑 | 原因 | 修复 |
|---|---|---|
| 写成 `stateDiagram`（无 `-v2`） | v1 已废弃，行为不一致 | 统一写 `stateDiagram-v2` |
| 复合状态后面整图解析失败 | `state 名称 {` 与 `}` 未配对 | 写完检查大括号配对，内部缩进统一 |
| 状态名含空格报错 | 空格被当两个 token | `state "含空格的名称" as id`，之后用 `id` 引用 |
| 忘写结束 `[*]` | 状态机悬在半空，读者不知道终点 | 终态显式连 `[*]`（允许多个，但别漏） |
| 迁移条件丢失 | 裸箭头读者不知道为何迁移 | 触发条件写边上：`待支付 --> 已支付 : 支付成功` |
| 状态 + 分支判断混一张图 | 两种结构搅在一起难读 | 拆两张：状态图讲迁移，flowchart 讲某状态内的判断 |
