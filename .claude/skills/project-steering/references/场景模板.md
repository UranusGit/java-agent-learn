## 代码项目场景

### 1. Java 企业级（Spring Boot）

**匹配**：`pom.xml` / `build.gradle` + spring-boot 依赖

```markdown
# CLAUDE.md

## 项目
Java 17 + Spring Boot 3.x + MyBatis-Plus / JPA + MySQL 8。

## 命令
- 构建: `mvn clean install -DskipTests`
- 测试: `mvn test`
- 单测: `mvn test -Dtest=<类名>`
- 运行: `mvn spring-boot:run`（端口 8080）

## 架构
Controller → Service → Mapper/Repository 三层分离。
- Controller 只做参数校验和调用 Service
- Service 管事务，不直接操作 HttpRequest
- Mapper 只做数据访问，不含业务判断

## 硬性规则
IMPORTANT:
- ❌ 禁止 `@Autowired` 字段注入，使用构造器注入
- ❌ 禁止提交 .env / application-local.yml
- 修改后运行 `mvn compile` 确认编译
- 新建 API 必须创建 Service + DTO + Mapper
- 最小变更，不重构无关代码

## 禁止修改
- `src/main/resources/db/migration/` — Flyway 迁移
- `src/generated/` — 自动生成代码
- `pom.xml` 依赖版本 — 需评审
```

## 2. 全栈 TypeScript（Next.js / React）

**匹配**：`package.json` + next/react/nuxt

```markdown
# CLAUDE.md

## 命令
- `pnpm dev` — 开发服务器
- `pnpm build` — 生产构建
- `pnpm test` — 所有测试
- `pnpm test -- <file>` — 单文件测试
- `pnpm typecheck` — TypeScript 类型检查
- `pnpm lint` — ESLint

## 架构
Server Components → Server Actions → Prisma → PostgreSQL。
- Server Components 优先，需要交互时加 "use client"
- Prisma client 通过 `src/lib/db.ts` 获取
- API 返回 `{ data: T | null, error: string | null }`

## 硬性规则
IMPORTANT:
- ❌ 禁止在 client component 中直接调用 Prisma
- ❌ 禁止用 `any`，用 `unknown` + 类型守卫
- ❌ 禁止 `useEffect` 做数据获取
- 修改后运行 `pnpm typecheck && pnpm test`
- 表单验证用 Zod

## 禁止修改
- `prisma/migrations/` — 已执行迁移
- `src/generated/` — 生成代码
- `pnpm-lock.yaml` — 用 pnpm 管理
```

```markdown

## 命令

- Django: 每个 app 对应一个业务域。Model → Serializer → ViewSet
- FastAPI: 路由 → Service → Repository。Pydantic 做验证

- 所有公共函数必须有类型注解

## 禁止修改
- <migrations/ 目录>
- <settings 中的 SECRET_KEY>
```

## 4. Go 服务

**匹配**：`go.mod`

```markdown
# CLAUDE.md

## 命令
- 构建: `go build ./...`
- 测试: `go test ./...`
- 单测: `go test ./internal/<pkg>/ -run <TestName>`
- Vet: `go vet ./...`
- Lint: `golangci-lint run`
- 运行: `go run cmd/<service>/main.go`

## 约定
- cmd/（入口） internal/（私有） pkg/（可复用）
- 每个函数返回 error，不要 panic
- context.Context 作为第一个参数
- 接口定义在消费者侧

## 硬性规则
IMPORTANT:
- ❌ 禁止 panic（用 error 返回）
- ❌ 禁止忽略 error（不要 `_ = err`）
- 修改后运行 `go vet ./... && golangci-lint run`

## 禁止修改
- <*.pb.go 生成文件>
- go.sum（go mod tidy 管理）
```

## 5. Monorepo

**匹配**：workspace 配置 + packages/ 或 apps/

```markdown
# CLAUDE.md — Monorepo 根

## 目录
apps/      # 可部署应用
packages/  # 共享包（ui/ utils/ config/）

## 命令
- `pnpm dev` — 启动所有
- `pnpm dev --filter <app>` — 只启动指定应用
- `pnpm build` / `pnpm test` / `pnpm lint`

## Monorepo 规则
- `packages/` ❌ 不能 import `apps/`
- `apps/` 之间 ❌ 不能互相 import
- `apps/` ✅ 可以 import `packages/*`
- 新增共享代码前，评估是否真需要共享
```

## 6. 遗留代码维护

**匹配**：代码 > 5 年 / 测试覆盖率 < 30% / 有 > 1000 行文件

```markdown
# CLAUDE.md — 遗留代码维护

## ⚠️ 重要
本项目是 <年份> 项目，测试覆盖不完整。修改前必须理解上下文。

## 风险区域
| 模块 | 风险 | 注意事项 |
|------|------|---------|
| <auth> | 🔴 高 | 改动必须评审 |
| <payment> | 🔴 高 | 需 QA 回归 |
| <report> | 🟢 低 | 相对独立 |

## 修改流程
1. 理解：读目标类及所有调用者
2. 搜索：grep 找所有引用
3. 评估：输出影响分析
4. 测试先行：有测试就跑，没有先写
5. 小步改动：一次一个方法
6. 回归：运行全量测试

## 已知的坑
- <具体坑>：<原因 + 正确做法>

## 绝对不要
- ❌ 不要大规模重命名（破坏反射/XML 引用）
- ❌ 不要改方法签名
- ❌ 不要升级核心框架版本
```

## 非代码项目场景

### 11. 技术文档体系

**匹配**：docs/ 目录 + 多个 .md 文件，或有文档工具配置（GitBook/Docusaurus/MkDocs）

```markdown
# CLAUDE.md

## 项目
<项目名> 技术文档体系，共 <N> 篇文档，<M> 个章节。

## 写作规范
- 语言: 中文，技术术语保留英文原文（如 "context window"）
- 图表: 所有结构图用 Mermaid（❌ 不用 ASCII 字符画）
- 交叉引用: [篇名 §章节号]（如 [基础篇 §1.3]）
- 代码示例: 标注语言 + 确保可运行
- 每篇文档开头有 "> **定位**" 引用块说明与系列其他文档的关系

## 结构约定
- 章节编号连续（§1, §2, ...），跨文档不重复
- 目录(TOC) 与正文标题保持同步
- 文件命名: `<主题>-<类型>.md`（如 `CLAUDE-MD-规范指南.md`）

## 硬性规则
IMPORTANT:
- ❌ 禁止 ASCII 流程图——用 Mermaid
- ❌ 禁止无来源的断言——引用官方文档或标注"<推测>"
- 修改后检查所有交叉引用是否仍然有效
- 新增文档时更新目录索引
- Mermaid 图不超过 15 个节点（超了拆分）

## 禁止修改
- docs/archive/ — 归档的历史版本
- SUMMARY.md / _sidebar.md — 目录结构变更需确认
```

### 12. 调研/研究项目

**匹配**：目标是产出分析报告/对比文档/行业调研

```markdown
# CLAUDE.md

## 任务
调研 <主题>，产出 <形式>（报告/文档集/对比表）。

## 质量标准
- 每个核心观点至少引用 2 个独立来源
- 区分事实（有来源）和推断（标注"[推测]"）
- 量化数据必须注明时间和来源
- 来源标注格式: [来源名](URL) 或 [N] 对应参考文献
- 交叉验证: 关键数据用 ≥ 2 个来源对比

## 结构
- 从概览到深入（V1 概览 → V2 细节 → V3 实战）
- 每个部分有明确的"关键发现"摘要
- 末尾有"信息来源"和"更新日期"

## 硬性规则
IMPORTANT:
- ❌ 禁止无来源的数据/结论
- ❌ 禁止混合事实和观点（用"数据显示"vs"笔者认为"区分）
- ❌ 禁止引用过期数据（标注日期，> 2 年的数据标注"可能过时"）
- 链接到原始来源，不要链接到转载

## 禁止触碰
- references/ 已整理的参考文献列表
```

- 新术语首次出现时定义

## 禁止修改
- 已出版的章节（标注 ✅ Published）

### 14. 数据/系统迁移

**匹配**：数据库切换、框架升级、语言迁移

```markdown
# CLAUDE.md

## 迁移任务
<旧系统> → <新系统>，预计 <周期>。
⚠️ 高风险：涉及<生产数据/核心依赖>。

## 迁移原则
- 策略: 双写 + 影子验证
- 每一步必须有回滚条件和回滚命令
- 流量切换必须渐进（1% → 10% → 50% → 100%）
- 数据校验: 迁移后行数一致 + 抽样对比

## 硬性规则
IMPORTANT:
- ❌ 禁止无回滚方案的步骤
- ❌ 禁止一次性切换全量流量
- ❌ 禁止跳过数据校验步骤
- ✅ 每步完成后运行验证脚本
- ✅ 遇到不一致立即停止，不要"继续看看"

## 应急回滚
- 回滚命令: <rollback script/command>
- 回滚决策人: <who decides>
```

### 15. 基础设施 / DevOps

**匹配**：Terraform/K8s/Ansible/CI-CD 配置

```markdown
# CLAUDE.md

## 基础设施
IaC 工具: <Terraform/Pulumi/CloudFormation>
环境: dev / staging / prod

## 命令
- 计划: `terraform plan -var-file=<env>.tfvars`
- 应用: `terraform apply -var-file=<env>.tfvars`
- 验证: `terraform validate && tflint`
- 销毁: `terraform destroy`（⚠️ 仅 dev）

## 硬性规则
IMPORTANT:
- ❌ 禁止自动 apply 到 staging/prod（必须人工确认 plan）
- ❌ 禁止直接修改 prod 状态文件
- ✅ 每次变更先 plan，检查 diff
- ✅ 新增资源必须有 tags（env, owner, cost-center）
- ✅ 敏感变量用 .tfvars（gitignore）不用硬编码

## 环境隔离
- dev: 可自由修改
- staging: 需 PR Review
- prod: 需 PR Review + 审批 + 维护窗口

## 禁止修改
- terraform.tfstate — 状态文件
- prod.tfvars — 生产配置
```

## 安全条款（按行业）

### 金融（PCI-DSS）

```markdown
## 金融安全
- ❌ 禁止存储信用卡完整号码（只存后 4 位 + token）
- ❌ 禁止记录 CVV
- ✅ 通过 PCI-DSS 认证的支付网关处理
- ✅ 所有金融交易有审计日志
- ✅ 静态数据加密（TDE）+ 传输加密（TLS 1.3）
- ✅ 敏感字段 AES-256-GCM 加密
```

### 医疗（HIPAA）

```markdown
## HIPAA 合规
- ❌ 禁止非生产环境使用真实 PHI
- ❌ 禁止 PHI 写入日志/错误消息/APM
- ✅ PHI 字段应用层加密
- ✅ 所有 PHI 访问记录审计日志
- ✅ 用户登录需要 MFA
```

### 电商

```markdown
## 电商安全
- ❌ 禁止前端处理支付（只获取 payment intent）
- ✅ 订单金额服务端重新验证
- ✅ 支付回调验证签名
- ❌ 禁止跨用户查询数据（每查询带 user_id 过滤）
- ✅ 订单数据返回前验证归属权
```

## EARS 五模式速查

| 模式 | 语法模板 | 适用 |
|------|---------|------|
| 普遍型 | 系统应当 `<行为>` | 恒定全局约束 |
| 事件驱动 | 当 `<触发>` 时，系统应当 `<行为>` | 响应外部事件 |
| 状态驱动 | 在 `<状态>` 期间，系统应当 `<行为>` | 持续状态约束 |
| 非期望 | 如果 `<异常>`，则系统应当 `<响应>` | 错误处理 |
| 可选 | 当包含 `<特性>` 时，系统应当 `<行为>` | 功能开关 |

## 场景组合规则

| 组合 | 主场景骨架 | 追加段落 |
|------|-----------|---------|
| Java + 遗留 | Java 模板 | + 遗留模板的风险区域和修改流程 |
| Monorepo + 微服务 | Monorepo 根模板 | + 微服务模板的通信约定 |
| 重构 + 遗留 | 重构模板 | + 遗留模板的已知的坑 |
| SDK + Monorepo | Monorepo 根模板 | + SDK 模板的兼容性规则 |

组合时取主场景骨架，次场景差异段落追加。总行数 < 200。
