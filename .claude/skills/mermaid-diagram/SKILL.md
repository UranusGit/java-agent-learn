# Mermaid 图生成（Typora 兼容）

把"需要表达结构"的内容落地为格式正确、能直接渲染的 Mermaid 代码块。**先想清楚这段内容要不要图，再决定怎么画。** 决定要画时，一切语法选择以 Typora 能渲染为第一优先级。

## 第一原则：说明白，不是画出来

图的唯一价值是让读者**更快、更省力**地理解事务/流程；为画图而画图、为排版好看而画图，都是噪音。

决定要不要图之前，先过三道判断：

1. **内容有没有结构？** 分支 / 并发 / 分层 / 时序 / 状态迁移 / 实体之间的关系——没有这些结构，就是纯叙述，一句话说完，不需要图。
2. **一句话或一个表格能不能说清？** "A 调用 B"、两步串行这种一两个箭头的关系，用一句话；两列二维的对应关系，用表格。文字和表格都比图更省阅读成本，也更易维护。
3. **图画出来读者真的省力吗？** 还是只是为了文档"看起来专业"？判断标准：**图必须比被它替代的文字更快被理解，否则不要画。**

三道判断都通过，才动手画图。

## 图和正文的分工

- 正文负责讲**为什么**、怎么取舍、异常怎么处理、结论是什么。
- 图负责一次性展示**结构 / 顺序 / 依赖**这种文字说不利索的部分。
- 图是正文的支撑，不是正文的替代；也不要让正文逐节点复述图（图下面再按节点念一遍 = 双重叙述）。

## 图的质量（画了就要有信息量）

- **每个节点、每条边都要承载信息。** 不承载信息的节点 / 边删掉。
- **控制单图复杂度。** flowchart 超过约 12~15 个节点就拆：按主题拆成多张小图，或先画分层总览再展开细节。一张图只讲一个主题。
- **控制整篇数量。** 图是点缀不是洪水；图与图、图与文字之间不重复表达同一信息。
- **宁缺毋滥。** 拿不准这张图有没有价值时，跳过。烂图（看不懂、信息重复、纯装饰）不如没有。

> 这张表回答的是"要画时选哪种"，不是"遇到就画"。一两个箭头的关系用一句话，两列二维关系用表格——它们不在图的服务范围内。

## 画图时的三个铁律（决定画图之后）

1. **要用 Mermaid，不要用 ASCII 字符画。** 一旦决定画图，就输出 ```` ```mermaid ```` 代码块，绝不写 `+---+` 字符画或文本 `-->` 箭头；文档里已有字符画且内容确实需要图时，按 `references/文本流程图转换.md` 改写。这条管的是"画图的表达方式"，不改变"要不要画图"的判断。
2. **Typora 兼容优先。** 只写 Typora 内置 Mermaid 11.x 稳定支持的语法。避免 `-beta` 实验图（`radar-beta`、`treemap-beta`、`block-beta`）和 `flowchart-elk` / `graph-elk` 布局引擎。不确定某特性是否兼容时，查 `references/Typora兼容性.md`。
3. **语法必须完整可渲染。** 生成结果用户复制进 Typora 就能渲染出图，不能有解析错误。写完后必须过一遍「输出前自查清单」。

## 通用语法铁律（所有图都适用）

1. 代码块语言标识必须是 `mermaid`（Typora 靠这个渲染）：
   ```` ```mermaid ````
2. **标签含特殊字符就加双引号。** `( ) [ ] { } : # "` 等都会让解析器报错或显示错乱。规则：只要标签文本里有除中英文、数字、下划线、空格、连字符、点以外的字符，整个标签用 `"..."` 包裹：
   - `A["计算 (含公式)"]` —— 有括号，必须加引号
   - `A["状态: 完成"]` —— 有冒号，必须加引号
3. 中文文本可以直接写；但含特殊字符（尤其 `:` `(` `)`）时同样要加引号。**凡是拿不准的，一律加引号。**
4. **ID 用英文小写字母、数字、下划线**，不能含空格和标点（子图 ID 同规则）。ID 只做引用，显示文本放标签里：
   - `participant client as 客户端`
   - `client->>server: 请求`
5. 同一张图里 ID 全局唯一，不要复用。
6. 注释用 `%%` 开头：`%% 这是注释`。
7. 配置指令 `%%{init: {...}}%%` 放第一行，只写最小配置（如主题）。
8. **一个代码块只放一张图。** Typora 对多图 `&&` 分隔支持不稳定，不要用。
9. 生成完的 mermaid 紧跟在相应正文后，代码块内不要放别的语言。

## 中文节点（你文档的主要场景）

你的文档节点基本都是中文。中文在 Mermaid 里是**合法文本**，直接写即可，记住三条：

1. **纯中文直接写，不需要引号**：
   - `A[用户提交订单]`
   - `待支付 --> 已支付`
   - `client->>server: 发送消息`
2. **ID 保持英文**，中文放标签 / 显示名：`participant client as 客户端`。之后引用永远用 `client`，不是 `客户端`。
3. **中文里混入特殊字符（`:` `(` `)` `"` 等）时，整个标签加双引号**：
   - `A["状态: 完成"]`
   - `A["计算 (含公式)"]`
   - **拿不准就加引号**——加引号永远比不加安全。

**例外（标识符严格的图）**：`classDiagram` 的类名 / 成员名、`erDiagram` 的实体名 / 属性名建议用英文（解析器按标识符解析，中文易出问题）；中文语义放 `note` 注释或关系标签里，如 `Dog --|> Animal : 继承`。

## 生成流程

1. **先做"要不要图"判断**：按「第一原则」过三道判断。不需要图 → 用一句话或一个表格，直接结束，不进入后续步骤。
2. 从需求/文档上下文提炼要表达的结构：有哪些节点、实体、参与者，它们之间的关系是什么。
3. 按上面的表格选图类型。
4. 打开对应 reference 文件取模板：`references/<类型>.md`。
5. 套模板写 mermaid，套用「通用语法铁律」。
6. 若文档中已有文本流程图，且内容确实需要图，用 `references/文本流程图转换.md` 的规则转换。
7. 输出前过一遍自查清单。

## 输出前自查清单

- [ ] 是否真的需要这张图？一句话或一个表格能否替代它？（不能明确说出这张图给读者省了什么力，就删掉图）
- [ ] 每个节点、每条边都有信息量？有没有纯装饰的节点？
- [ ] 是否与正文重复表达同一信息？
- [ ] 代码块语言标识是 `mermaid`？
- [ ] 图类型关键字正确（`flowchart` / `sequenceDiagram` / `classDiagram` / `stateDiagram-v2` / `erDiagram` / `gantt` / `pie` / `mindmap` / `timeline` / `gitGraph` / `packet-beta` / `sankey-beta` / `xychart-beta` / `quadrantChart` / `kanban` / `architecture-beta` / `venn` / `ishikawa`）？
- [ ] 含特殊字符的标签都加了双引号？
- [ ] 中文节点含 `:` `(` `)` 等特殊字符时也加了引号？（拿不准的也加了？）
- [ ] 引号成对闭合；`{` `}` `(` `)` `[` `]` 成对？
- [ ] 每个 ID 只定义一次？
- [ ] 依赖缩进的图（mindmap / timeline / kanban / stateDiagram 复合态）缩进层级正确且一致？
- [ ] 每张图独立一个代码块，没有 `&&` 多图分隔？
- [ ] 没有 `-beta` 实验特性和 `flowchart-elk`？
